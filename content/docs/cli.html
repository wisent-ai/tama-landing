CLI

Tama Desktop bundles a sealed native Rust CLI at Tama.app/Contents/Resources/hooks-release/bin/tama. Its public usage starts with tama <command>. This index links every public top-level command and command leaf; hidden runner and bridge entrypoints are intentionally not part of the public surface.

Catalog and release inspection

  • tama help — print the sealed public command summary.
  • tama list [--json] — list the sealed hook catalog.
  • tama show <hook-id> [--json] — inspect one hook.
  • tama validate [--json] — validate catalog and source integrity.
  • tama install-plan [--json] — show enforcement targets without writing them.
  • tama mcp-config — print the MCP server fragment.
  • tama model-provider [show | set --origin URL --model MODEL | unset] [--json] — choose the model service Tama asks: Brama, or an OpenAI-compatible service whose key is read from standard input.
  • tama sessions [--json] [--home <path>] — inspect live session records.
  • tama assignment show --session SESSION_ID [--json] — read one session's newest operator instruction and fresh Oko task ledger, and record that both were read.
  • tama task scope show|set|clear --session <ID> [--repository <NAME>]… [--defect <ID>] [--task <ID>] [--json] — declare which defect or task a session serves and which repositories it touches; block-off-task-work checks every write against it.
  • tama justify <record|show|remove|list> [--file <path>] [--justification <text>] [--kind file|cua] [--quote <text>] [--expires-at <iso>] [--home <path>] [--json] — record, read or remove a justification the authorization gates require.
  • tama tests <approve|revoke|list|audit> [<path>…] [--remove] [--json] — the operator's approvals of test code, and the audit of every test nobody approved; block-unapproved-tests refuses test code anywhere else.
  • tama policy import|list|remove — validate and keep inactive policy bundles, list them, and remove one, without installing or enabling anything.
  • tama hooks declare|undeclare|release|warm|stage|seal|source-identity|install-release|integrity|digest — add, withdraw, build, warm, package, install and verify hook releases.
  • tama merges review --root <PATH> --since <YYYY-MM-DD> [--json] — the damage review of branch merges already on main.

Machine enforcement

  • tama enforcement status [--json] — read the durable machine selection.
  • tama enforcement only <hook-id>... — enforce only selected hooks machine-wide.
  • tama enforcement add|remove <hook-id>... — turn hooks on or off and keep the rest, from the selection as it is when the change is written.
  • tama enforcement preflight <hook-id> — ask one hook whether it can work here and read what it answered.
  • tama enforcement all — restore the all-hooks machine baseline.

Installation and repository operations

  • tama install — install user-global Git dispatchers.
  • tama uninstall [--unset-git-config] — remove the managed Git dispatchers and put back what they displaced.
  • tama onboarding [--reset] [--policy-bundle <dir>] [--replace] [--home <path>] — the first-use walkthrough, optionally adopting an inactive policy bundle on the way in.
  • tama find-violations — scan repositories without modifying them.
  • tama declare-root — declare a repository root whose files are fixed there by other tooling.
  • tama vocabulary-report --repo <path>… [--json] — every keyword list still in a repository, grouped by its words.
  • tama extract-patterns --file <rust-file> --const <NAME> --into <json> — move a guard's pattern table out of Rust into a JSON declaration.
  • tama clean — ask Brama for one patch per repository per round, apply it, and re-scan.
  • tama brama-check [--json] — which Brama address this machine resolves, and what the gateway answers.
  • tama justify <record|show|remove|list> — record, read and retire the justifications the write guards require.
  • tama request <operation> — answer one Tama Desktop request: JSON body on stdin, NDJSON events on stdout.
  • tama provider-config --provider <claude|codex> --dispatcher <command> [--json] — print the hook block an install writes into that provider's config.

Adaptive doctor

tama adaptive <command> is the public adaptive-layer command group. Its leaves are:

  • tama adaptive status — effective per-hook state and telemetry transport.
  • tama adaptive drift — live-versus-archive content hashes.
  • tama adaptive queue — queued repair requests.
  • tama adaptive repair <hook-id> [--patch-file <path>] — validate and stage a proposal.
  • tama adaptive apply <proposal-dir> — apply a validated proposal with owner consent.
  • tama adaptive install — install and verify the native runner shim.
  • tama adaptive uninstall — restore the newest runner backup.
  • tama adaptive claude-config — print Claude event routing.

Worktrees

tama worktrees <command> is the public worktree command group. A linked worktree is a second checkout of a repository you already have, and creating one is refused by the block-repository-copies hook; this group is how you inventory and remove the ones that already exist. Its leaves are:

  • tama worktrees list [--root <PATH>]... [--json] — every linked git worktree under the roots.
  • tama worktrees remove [--root <PATH>]... [--except <PATH>]... [--apply] [--force] [--json] — remove them; previews unless --apply.

--root is repeatable and required at least once on both leaves; there is deliberately no machine-wide default root. --except is repeatable, takes the path of one linked worktree to leave completely alone, and exists on remove only — list removes nothing, so it has no --except.

Copies

tama copies <command> is the public group for the other noun block-repository-copies refuses: a second full checkout with its own .git directory, which a clone of a local path or a recursive copy produces and which git never lists from the original. Its leaves are:

  • tama copies list [--root <PATH>]... [--json] — every second full checkout under the roots.
  • tama copies remove [--root <PATH>]... [--except <PATH>]... [--only <PATH>]... [--apply] [--force] [--json] — remove them; previews unless --apply.

A pass refuses any copy carrying uncommitted changes, commits absent from every remote, no origin to compare against, linked worktrees of its own, or no canonical checkout under the roots given. --except spares a copy and --only narrows the pass to named copies, accepting them as removable when they are the sole checkout here; the two are never combined.

Merges

tama merges review --root <PATH> --since <YYYY-MM-DD> [--json] reads every checkout under the root and lists each merge on main's first-parent line since the date whose subject is Merge <branch> into main and which nothing reverted. For each it reports the files it added or changed that are over 300 lines on main today and the paths it re-added after main had deleted them. It exits one when any merge left either, zero when every merge is clean, and two on a usage error. It changes nothing; whether the merged source compiles is the release build's answer. The branch merger that made these merges no longer exists.

Existing policy bundles

A supported self-contained policy bundle or sealed release contains shared-hooks/registry.json and regular, non-symlink files under shared-hooks/, claude-hooks/, codex-hooks/, repo-githooks/, adaptive/, external-hooks/, and bin/, plus supported root metadata such as release.json and external-sources.json. Other top-level paths are reported in ignoredPaths.

The complete registry and every registered source are validated before the editable store changes. A sealed release must also match its release.json tree identity. Results report imported, unchanged, removed, conflicting, and rejected counts. Repeating an identical source is unchanged; differing content conflicts unless explicit replacement is safe. Untracked and locally changed stored files remain conflicts even with --replace.

Every imported bundle is inactive: zero hooks are installed or enabled, and the command does not change the current release, ~/.shared-hooks, agent settings, or Git configuration. policy list returns canonical source paths, SHA-256 identities, timestamps, hook counts, file counts, and retained bundle paths without printing policy contents.

Exit and refusal contract

Successful commands exit 0. Usage errors exit 2. Operational failures and findings that fail the command's contract exit 1, except for explicitly documented disabled or empty outcomes. Each command page records its required inputs, effects, output, and exact relevant refusal text from the sealed dispatcher.
