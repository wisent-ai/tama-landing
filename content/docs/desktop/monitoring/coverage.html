Coverage screen

Which runtime carries which hook, and whether that runtime's own configuration really installs it. The screen answers "is Codex actually covered on this machine" without a terminal, and it separates the two halves of that question: the registry's declared mappings, and how many of them the provider's config on this machine installs. It is explicit that neither half is live execution evidence — each provider's own sentence, captured from the sealed release, is Registry-declared mappings; not live execution evidence.

The distinction is not academic. Until 2026-09-07 every install deleted Tama's entries from ~/.claude/settings.json and ~/.codex/hooks.json, so both providers ran no policy at all while this screen showed full declared coverage (hook-releases).

Where the data comes from

A plain GET of /v1/coverage on the loopback backend (cli), read on first visit and re-read only on demand — coverage is registry content, so polling it would imply it changes. Against the release sealed on 2026-09-07 (source revision 2b50253), the claude provider reports adapter ~/.claude/settings.json, 94 declared mappings, 94 of them installed, 56 hooks, 9 events; codex reports 111 declared, 111 installed, 57 hooks, 16 events. A failed read shows Coverage could not be read with the error sentence and Retry.

Header, facets, counters

Title Coverage; scope is the selected provider; freshness reads reading now, read <time>, or not read yet; the one action is Re-read coverage. The Provider facet lists Every provider (total mappings) and each provider with its mapping count — warning-toned when it maps nothing. Counters: Providers (declared in this release), Assignments (covered event pairs), Policies covered (distinct covered policies), Without coverage (providers without coverage; warns when nonzero), and Not installed (configs missing declared mappings; warns when nonzero).

States and table

No providers at all: No provider coverage — No providers are covered in this release. A provider with no mappings: No coverage for <provider>, with the registry's own note when it declares one, else This provider has no covered events., and a Show every provider action. Loading reads Reading provider coverage; a failed read shows Coverage could not be read with the error sentence and Retry. The table is POLICY, EVENT, TRIGGER, PROVIDER.

Inspector

Selecting a provider (or any of its rows) shows: badges for the coverage kind (declared), No mappings when uncovered, and Not installed when the config installs fewer mappings than the registry declares; fields Declared mappings, Policies, Events, Installed in its config, Adapter path (No adapter declared), and Live coverage required — yes / no / not declared, the release's own statement of whether it demands live coverage evidence for this provider. Installed in its config reads <n> of <m> installed for the two providers whose config Tama writes, counted by matching each declared mapping against the commands in that config, and no config Tama writes for OMP, Git, the editor adapters and kimi — where the question has no answer rather than the answer zero. The same numbers come from /v1/coverage as mappingCount and installedMappingCount, and tama validate turns a shortfall into one install drift line per missing mapping.
