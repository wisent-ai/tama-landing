Justifications screen

The Justifications screen reads recorded file/test reasons and provides CUA consent management. Both recording controls run tama-cli request, one process per operation, with the same validation as the CLI.

File and test justifications

The existing registry view reads requirements declared by requires_justification hooks. Search matches the target, justification and recorded user quote. Select a record to inspect its reason, target existence, word count and expiry. An unreadable registry is an error; missing evidence or expiry does not mean the service is down.

Record justification opens a sheet for the absolute target path, file/test kind and justification. Tests additionally require a verbatim user request contained in that justification. The backend validates and writes the entry; its refusal remains visible in the sheet. The target file's contents are not read by the registry view.

CUA consent

CUA consent opens a separate grant sheet even when the catalogue has no file justification requirements. The form takes the OMP session ID, installed application name, comma-separated actions and either an exact quote or text matching one original user message. The default matching mode retrieves the full message without retyping its whitespace.

Record consent sends those fields as the body of tama-cli request justifications/cua/record. Tama verifies the real message and installed application, then the sheet rereads the registry. A refusal appears under Refused using the product's exact message. A successful recording does not start the driver or claim that a GUI action ran.

Inspect and remove consent

Recorded grants shows the original user quotation, application, allowed actions, session, lifetime, bundle identifier and executable. Refresh reruns tama-cli request justifications/cua; a failed read is not represented as an empty success. CUA grants are not judged by file existence or a justification word count.

Remove opens a confirmation quoting the exact consent to retire. Confirming removes every grant with that exact quote through tama-cli request justifications/cua/remove and rereads persisted state. It does not change any hook source or runtime capability.

What the result proves

A record proves that Tama accepted and stored the quoted consent. The installed hook still checks the current session, app and action for every CUA operation. Driver availability and macOS permissions are separate requirements; an operation that cannot run remains failed even when the grant is recorded.

See tama justify for exact input rules, refusals and registry behavior, and tama request for the request contract.
