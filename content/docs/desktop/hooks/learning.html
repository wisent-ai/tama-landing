Learned screen

Tama shows one proposal per contested hook, drafted rule or unresolved operator correction with a named cause. The screen reads the sealed CLI's tama rules digest through tama request rules/digest; it does not install policy.

What a row shows

  • The contested hook, drafted rule or cause the proposal is about.
  • What was observed, how often, and the first and last observation.
  • For a lesson, expand Read sources to see every Oko session, the operator's words and the named cause. A linked defect groups its moments; otherwise identical causes group them.
  • The selectable command: tama adaptive repair <hook>, tama rules remove --id <rule>, or oko frustration show <moment-id>. The last command only inspects evidence; it neither fixes the cause nor enables a hook.

Dismiss until new evidence

The button runs tama request rules/dismiss with the proposal's id and the operator's approval for that one request. The proposal leaves the screen and comes back when more evidence arrives than it had. A refusal is shown as the command's own sentence.

When a source cannot be read

A failed Oko read appears as oko-frustration unreadable with the command's failure, and a failed adaptive read names that source. Other proposals remain visible; an empty list beside a failed source does not mean there were no corrections.

If the local dismissal record cannot be read or parsed, the whole digest request is refused. The screen shows the file error, not a successful empty list; it cannot decide which proposals are hidden from damaged state.

The screen is under Policy and needs policy control, like the build registry.
