Hardcodes

The Hardcodes screen in the Repair group shows what tama hardcodes reports: every tracked line of the repositories under one root that writes down a value nobody declared — a fleet host name or a vault item id read live from Stado, a number block-numeric-literals refuses, or a host with a port.

Using it

  1. Choose root… picks a repository, or the directory holding repositories.
  2. Name the commit that wrote each line asks for origins, as --origins does.
  3. Scan sends hardcodes/scan with {roots, origins} and shows the command's own document.

Each row names the repository, the file and line, the kind (host, vault-item, number or address), the value, and under origins the commit that wrote the line with its subject. A repository git could not read is shown above the table as Unreadable with git's answer. The header counts findings and repositories. The screen changes nothing: giving a value its source, or removing it, is a commit in that repository.

Refusals

A request without roots is refused with hardcodes/scan needs roots: at least one repository, or a directory holding repositories, to read; it does not guess which tree to read. A root that is neither a repository nor holds one is refused with root <path> is not a git repository and holds none directly under it; name a repository or the directory that holds repositories, and a host or vault vocabulary Stado cannot answer with cannot read what counts as a name: <error>. Any refusal is shown as Scan refused with the product's sentence and recorded under the failure point tama.hardcodes.scan.
