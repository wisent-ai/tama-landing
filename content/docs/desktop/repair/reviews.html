Reviews

The Reviews destination in the Repair group inspects retained commit reviews: what the model reviewer of review-commit read and answered before a commit was created. A push retains nothing to inspect; review-push reads the attestation each commit carries, shown under Install → Carried attestations. The screen has the same local control authorization boundary as the other Repair screens. It does not run a model, retry a commit or change credentials.

Read an exchange

  1. Choose Reviews, then Refresh. The initial screen says the records have not been read; loading and failure are distinct states.
  2. The table lists retained IDs and their recorded outcome, or Unreadable result. An empty inspected directory is different from a missing or unreadable directory, which is an error.
  3. Select a row. The detail pane re-reads that exact record and displays its ID, retained directory, outcome and full cause. Refresh clears the old selection; a failed request cannot leave a prior result presented as current.

Interpret the result

Passed means the reviewer passed that exchange, not that Git created the commit. Source finding names a grounded finding to repair. Review unavailable names the failed review operation or dependency; it does not ask you to amend source merely because a provider failed.

Unreadable records keep their exact filesystem or JSON cause. A missing result is not guessed to be a pass, an unfinished exchange or a legacy record. The directory identifies the retained envelope and answer for further inspection.

Shared command

The screen uses reviews/list and reviews/show, one tama request process per operation. These call the same reader as tama reviews list and show. Native request failures are shown and reported under tama.reviews.list or tama.reviews.show. The screen offers no publication or provider-repair mutation.

Stage session-owned changes

The Session-owned staging panel above the retained reviews accepts a session identity and repository checkout, optionally the files to stage, one per line, as tama stage --path takes them (left empty, every recorded edit is staged), and optionally the sessions that wrote those files together with it, one per line, as tama stage --with takes them (a reviewer that amended the author's hunk, a session whose formatter rewrote it). Inspect changes computes a candidate without publishing the index; Stage session changes publishes the recorded deltas atomically. Both show the changed paths, successful receipt calls and candidate tree, and the files left out with their causes; when nothing was staged the panel says so, and says that nothing remains only when nothing was left out either. A conflict, missing receipt, a named file the session never edited or failed Git operation displays its full cause and reports it under tama.stage.

Below the co-authors, an optional field takes the Oko task this session took over from a stopped session named among them, as tama stage --task takes it: that session's every edited path is then staged with this session's own, while Oko shows this session leading the task and the predecessor no longer runs; otherwise the panel shows the refusal naming the task's claimant, its claim history or the predecessor's running process.

Below the task, the toggle Read the index from HEAD first sends fromHead, as tama stage --from-head does: the staging index is read from HEAD before the session's changes are carried onto it, so an index read on an older HEAD takes back no later commit, and entries staged by other means are not kept.

The panel uses the typed stage native request and the same implementation as tama stage --session. It never invokes a shell staging command, compiler or installer. Working files remain untouched, unrelated staged entries remain in the index unless the index is read from HEAD first, and a candidate tree is not a qualification verdict.

Index repair

The Index repair panel below staging takes a repository checkout. Read index reads the checkout's index for entries whose object the store does not hold and for an index that holds no entry while HEAD tracks files; Repair index repairs them as tama index repair --apply does, writing the index only. The panel names the index file it read and, when GIT_INDEX_FILE chose that file, warns that it is not necessarily the checkout's own, so an index read through a variable left from another checkout is not taken for an emptied one. It uses the typed index/repair native request; a failure is shown and reported under tama.index.repair.

Harsh review rounds

The Harsh review rounds panel below staging takes a checkout path and Read rounds lists the rounds of harsh review recorded for the commit it is making: each round's reviewer (a session, the declared judge or the operator), the staged tree it covered and its findings, and each finding recorded as an Oko defect. review-commit lets that commit through only once a round by a reviewer other than its author, over the exact staged tree and message, found nothing. The panel uses the reviews/harsh native request, the same reader as tama reviews harsh show; an unreadable register is shown as the failure it is and reported under tama.reviews.harsh.

Admitted commit

The Admitted commit panel below the rounds takes a checkout path and a commit, and Read admission shows what review-commit kept when it admitted that commit: the agent session that made it (marked when the commit was started outside that session's process tree and carried its edits) or the operator, the tree and the commit it follows, when it was admitted, and the Harsh-Review-Rounds: line it was let through with. A commit the hook never admitted shows the refusal naming the commit, its tree and its parent. The panel uses the reviews/admitted native request, the same reader as tama reviews admitted; a failure is reported under tama.reviews.admitted.

Admission cutover

The Admission cutover panel below the admitted commit takes a checkout path, and Read cutover shows when review-commit admitted its first candidate there and the tip of every local branch then: every commit those tips hold was made before admissions, and every pushed commit after them carries its own admission, or review-push refuses it. A checkout where review-commit admitted nothing yet says that no cutover is kept and no pushed commit is judged by its admission. The panel uses the reviews/cutover native request, the same reader as tama reviews cutover; a failure is reported under tama.reviews.cutover.
