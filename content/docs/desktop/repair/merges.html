Merges

The Merges screen in the Repair group shows what tama merges review reports: every merge on main's first-parent line since a day, in every checkout under one root, whose subject is Merge <branch> into main and which nothing reverted, and what each one left on main today.

Using it

  1. Choose root… picks the directory holding the checkouts.
  2. Type the first day, YYYY-MM-DD, in the field above the table.
  3. Review sends merges/review with {root, since} and shows the command's own document.

Each row names the repository, the merge commit and branch, and a chip: clean in green; over the limit: … and carried back: … in red for files over 300 lines and paths the merge re-added after main had deleted them; and unreadable: … in amber for a checkout git could not read. The screen changes nothing: repairing a merge is a commit in that repository.

Refusals

A request without root or since is refused with merges/review needs root: the directory whose checkouts are read or merges/review needs since: the first day, YYYY-MM-DD, whose merges are read. Any refusal is shown as Review refused with the product's sentence and recorded under the failure point tama.merges.review.
