Errors that say which failure

block-generic-errors is a write gate that refuses source code whose error messages say a failure happened without saying which one. A message such as "the upload did not succeed" names no step, no cause, no state that was observed and no fix, so whoever meets it has to find all four again. The rule is that every error says what failed, why, the state that was observed (the path, the item, the values that do exist) and what fixes it.

Quickstart

Install Tama and choose the gate for this machine:

stado product install tama --surface cli
tama enforcement add block-generic-errors
tama show block-generic-errors

Then ask your agent to report a failed upload in a TypeScript service. Where it would write a message that only says the upload failed, the write is refused before it lands, naming the file, the line, the sentence and why a reader cannot act on it:

block-generic-errors: BLOCKED: the file this write leaves holds an error message that says a failure happened without saying which, whoever wrote it:
  web/upload.ts:14: "<sentence>" says the operation failed without the step, the cause or the fix: throw new Error("<the message>");
Say in each message what failed, why, the state that was observed (the path, the item, the values that do exist) and what fixes it; …

The agent writes the version that tells the next person what to do instead:

throw new Error(`uploading ${file} to ${bucket}: the store answered ${status} ${body}; check that ${bucket} exists and this key may write to it`);

Before you turn the gate on for a codebase, list what it already holds, per repository:

tama violations find --generic-errors --tree ~/code
tama violations find --generic-errors --repo ~/code/service --json

What is refused

A sentence of the catalogue generic_sentences that wisent-errors keeps, matched without regard to case inside a string literal of a source file. The catalogue says for each sentence why a reader cannot act on it, and the refusal quotes that reason. The sentences are not listed again here or in Tama's code: the catalogue is the one place they are written, and a sentence added there is refused everywhere.

FilesString literals read
.rs, .swift, .go"…" and `…`
.ts, .tsx, .js, .mjs, .cjs, .py"…", '…' and `…`

A line that starts as a comment (//, /*, *, #, --) is not read: a comment that explains why a sentence says nothing is not an error message. A file under a directory named tests, test, __tests__, Tests or fixtures, a file whose name marks it as a test (.test., .spec., _test., Tests.swift, Test.swift), and build output and installed dependencies (target, .build, dist, build, node_modules, vendor, .venv, Pods, DerivedData, .git) are not read either: a test asserts the very sentences a refusal must not say. A file its repository declares in .tama/violations-ignore (a path, or a folder written with a trailing / for everything below it), with the reason written beside it, is not read by the gate or by tama violations find --generic-errors: that is how a vendored bundle, unpacked as its publisher built it, stays out. tama errors check does not read the declarations: a directory given to it is judged whole. A declaration file that exists and cannot be read refuses the write, naming the file and the system's cause.

What is read

The whole file as the write leaves it: a hashline section or a string edit is replayed on the file, and a written file's content is read as written. A sentence the file already held is refused on its next edit until the edit rewrites it, whoever wrote it, and the refusal lists every one, not only the first. A write that names no file, and a file of a language that is not listed above, pass.

Refusals and what they mean

RefusalMeaning
the file this write leaves holds an error message that says a failure happened without saying which …One line per sentence: the file and line, the sentence, why a reader cannot act on it, and the line. Rewrite each message to say what failed, why, the state observed and the fix; where the product declares its failures (wisent_errors::Operation), raise a declared cause instead of a free sentence.
the file this write leaves cannot be rebuilt to judge it: …The edit could not be replayed on the file (the file is missing, or the edit does not apply); the cause follows.

Listing what a codebase already holds

tama violations find --generic-errors runs the same judgement over every file each repository owns (--repo, --tree, --owner, --me): the files Git tracks or would track, so build output a repository ignores is never counted. Each finding carries the sentence as its rule and line N: "<sentence>" <why>: <the line> as its message. Tama Desktop offers the same pass as Errors that name no failure on the Violations screen. tama errors check --source <dir> applies it to a source directory together with the check of the failure catalogues a product declares.
