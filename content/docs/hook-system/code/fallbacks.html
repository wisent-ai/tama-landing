No fallbacks

block-fallbacks is a write gate that refuses code which answers a missing or failed value with one nobody stated. A fallback hides the failure from whoever could fix it and turns into a decision nobody made; the rule is that a missing value is an error naming what is missing, where it was looked for and why it matters.

Quickstart

Install Tama and choose the gate for this machine:

stado product install tama --surface cli
tama enforcement add block-fallbacks
tama show block-fallbacks

Then ask your agent to read a port from the environment in a TypeScript service. Where it would write const port = env.PORT ?? "8080";, the write is refused before it lands:

block-fallbacks: BLOCKED: this write adds a fallback, which answers a missing or failed value with one nobody stated:
  web/server.ts: TypeScript ?? or || to a literal: const port = env.PORT ?? "8080";
Make the missing value an error that names what is missing, where it was looked for and why it matters …

The agent writes the version that tells the next person what to do instead:

const port = env.PORT;
if (!port) throw new Error("PORT is not set: the server listens on the port the deployment declares in PORT");

Other things people use it for: keeping a Rust service from turning a missing configuration field into unwrap_or_default(); keeping release scripts from shipping to ${TARGET:-production} when nobody set a target; keeping a Python job from silently reading settings.get("region", "eu").

What is refused

FilesConstruct
.rsunwrap_or, unwrap_or_default, unwrap_or_else
.js, .mjs, .ts, .tsx?? or || followed by a literal (string, number, array, object)
.swift?? followed by a literal; try?
.py.get(key, default); or followed by a literal
.sh${VAR:-default} and ${VAR-default}

The constructs are declared one file extension per entry in rust/crates/tama-hook-tools/src/ports/block_fallbacks/constructs.json; adding a language is one entry. The refusal lists every file, the construct and the added line, so each cause is shown, not just the first.

What is read

Only what the write adds: the + lines of each hashline section or patch, an edit's replacement text, a written file's content. Code a file already holds is not scanned, so a file is edited without first rewriting every fallback in it. A ?? or || that reads another variable passes, as does a file of a language with no declared construct, and a write that names no file.

Where it comes from

Source: rust/crates/tama-hook-tools/src/ports/block_fallbacks/mod.rs; binary: src/programs/block/limits/block_fallbacks.rs; the real-binary test that runs the built hook on harness payloads (a hashline edit, a string edit, a whole-file write, refusals and passes): tests/fallbacks/refusal.rs (cargo test -p tama-cli --test fallbacks_refusal); declaration: hook-declarations/code-discipline/block-fallbacks.json.
