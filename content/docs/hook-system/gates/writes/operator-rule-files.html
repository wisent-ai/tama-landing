The operator's rule files: block-operator-rule-files

A gate on the file tools (write, edit, multiedit, notebook), bash, eval and the REPL device (tama hook block-operator-rule-files) that refuses a call writing, editing, moving or deleting one of the operator's rule files. The rule files are his statement of how agents work, so an agent that rewrites them rewrites its own instructions; he edits them himself, in his own terminal, which runs no hook. The gate is declared and registered, not selected: the operator turns it on with tama enforcement add block-operator-rule-files.

Which files

The list is the operator's data, ruleFiles in the gate's declaration hook-declarations/autonomy-boundary/block-operator-rule-files.json, read when tama is built; no file name is spelled in the code. Each entry is a path under the home, and one * in a name stands for any run of characters inside that name:

"ruleFiles": ["AGENTS.md", "ARCHITECTURE.md", "NAMES.md", "STANDARD.md", "agents/*.md"]

A path is compared as written, made absolute against the call's directory with ~, $HOME and ${HOME} read as the home and . and .. resolved, and again as the filesystem resolves it, so a link to a rule file is that rule file. A new file the list covers (~/agents/new.md) counts, and so does a folder holding a rule file when it is deleted or moved.

What it refuses

  • A file tool whose path is a rule file (every path the tool names, a hashline header included).
  • A shell line, read by the shell's grammar and through every line it hands a shell (bash -c '…'), that redirects output into one (>, >>, >|, &>, &>>, <>); runs rm, unlink, rmdir, shred, srm, trash, truncate or mv on one or on a folder holding one; puts something where one stands with cp, install, ln, ditto, rsync or mv (the destination, the name a source takes inside a destination folder, and every name a folder's contents take when its contents are copied); edits one in place with sed, perl or ruby -i; writes one with tee or dd of=; or opens one in ed, ex, vi, vim, nvim, nano, pico or emacs.
  • A program — an eval or REPL call, or the code a shell line hands python, perl, ruby, node, bun, deno, php or osascript — that names a rule file under the home (after ~/, the home variable or the home's own path, or as quoted names in a text that asks for the home, as Path.home() / 'STANDARD.md' does) and calls something that writes, moves or deletes a file or runs a program (open(…, 'w'), write_text, writeFile, os.replace, subprocess, the harness's write(…), and their kin).

Reading passes: cat ~/AGENTS.md, grep … ~/agents/*.md, a copy of a rule file to somewhere else, and a program that only reads one. A file of the same name inside a repository is not a rule file.

The refusal

The refusal names every rule file the call changes, by its absolute path, comma-separated:

BLOCKED (block-operator-rule-files): this call writes, moves or deletes `<absolute path>`, which this gate's declaration (ruleFiles) lists as the operator's rule files. An agent never changes them; he edits them himself, in his own terminal. Read them, follow them, and say in the conversation what you would change and why. Only the operator's own words grant it: …

One exact change passes on the operator's words, recorded with tama justify record --kind rule-file, its action the exact command or the absolute path (see operator grants).

What it does not refuse

The gate reads its payload and nothing else: no model, no network, no lock. A declaration, payload or shell line it cannot read (a quote never closed, a program only the running shell knows) refuses nothing and says so on stderr, beginning block-operator-rule-files: and ending ; nothing is refused. A program run from a file it is given by name is not read.
