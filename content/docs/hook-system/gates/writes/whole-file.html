Writes are judged by the whole file they leave

Every gate on a write, an edit, a patch or a notebook edit judges the file as the write leaves it, not the text the write carries. Tama rebuilds that file once, through the replay in check_numeric_literals_payload::path_texts, and hands each gate the whole result:

  • a whole-file write: the content it writes;
  • a string edit (old_string/new_string, several edits in one call): the file on disk with each edit applied in order;
  • a hashline section: the file on disk with each anchored operation applied, an uncommitted change another session made to the file included;
  • an apply_patch envelope: each file it adds, updates or moves, as its hunks leave it;
  • a notebook cell edit: the whole notebook with the cell replaced, inserted or deleted.

So a violation the file already holds is refused on the next write to that file, whoever wrote it, and text the write removes is not judged as written. A write that removes the violation passes.

What a refusal says

A refusal names the file and the line in the whole file where each violation stands, as line N: <the line>, numbered from one as an editor numbers lines. The number is the line's place in the file the write leaves, not its place in the patch or the cell. Examples:

BLOCKED: legacy activation bypass detected in /repo/stage.sh: …
line 1: python -m …

block-direct-lsi-api: BLOCKED: … target: /repo/fill.py
  matched: project registry write/read endpoint (line 1: requests.post(…))

block-unapproved-tests: BLOCKED: /repo/src/lib.rs (test markers at line 5: #[test]) is test code the operator has not approved. …

A write the replay cannot rebuild is refused, never judged by the fragment it carries:

… the file this write leaves cannot be rebuilt to judge it: <cause>

The cause names the file and what failed: the file does not exist, an old_string was not found, a patch hunk (the hunk expecting `…`) does not match the file, a notebook cell is not there. Fix the write so it applies to the file as it is; there is no setting that lets an unrebuildable write through.

Where it comes from

Source: rust/crates/tama-hook-tools/src/ports/check_numeric_literals_payload/ (the replay, line_at and lines_holding) and each gate's own module. The journey cargo test --manifest-path rust/Cargo.toml -p tama-cli --test hooks_whole_file runs the built tama hook on real files: a patch beside a bypass the file already holds is refused naming line 1:, a patch the file does not hold is refused with the hunk it expected, and an edit of a hook file that introduces an always-false guard is refused naming line 3:. The suites lsi_api_edits, openai_api_key_writes, unapproved_tests_whole_file and numeric_literals_operations (the patch and notebook replay) assert the same per gate.
