Committed-line lookup

tama hook pre-write-edit checks a write or edit before it changes a file. A content refusal can be removed for lines already present in the target's committed version or in a changed donor file. Unrelated unchanged files do not exempt newly introduced content. Whole-file audits do not grant this exemption.

For a move, remove the lines from the donor first, then write the destination. Tama asks git diff HEAD --name-only -z for changed donor paths and adds the destination. Literal pathspecs prevent wildcard characters in a filename from widening that set.

Git receives escaped, anchored extended regular expressions for whole-line comparisons, allowing trailing blank characters. Punctuation such as a closing brace does not select every line containing it, and the lookup does not search the whole committed tree. Git's grep does not supply GNU grep's -x switch.

The input writer runs while stdout and stderr are drained and always closes stdin. The hook writes czekam and completion or failure diagnostics on stderr. A failed Git operation names the command, repository and cause; it retains the original content refusal rather than treating an unreadable tree as a successful lookup.

tama hook pre-write-edit < write-payload.json

The payload names tool_name: write and supplies tool_input.path and tool_input.content. Harness integrations consume the same decision, and graphical clients show the same refusal and hook progress. A passed hook is not proof that a subsequent file write succeeded.

The real journey is tests/pre-write-edit/committed_lines.rs, registered as pre_write_edit_committed_lines. It creates a real punctuation-heavy Git tree, sends a pattern set larger than ordinary pipe buffering to the built hook, permits a changed-donor move, and refuses content found only in unrelated committed files. Commands, exit statuses and the source revision remain in the test's build-directory artifacts.
