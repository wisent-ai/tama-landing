One implementation for all: block-single-implementation

A gate on pre_tool_use:edit, multiedit, notebook and write (tama hook block-single-implementation) that refuses a write into a repository adding text written for one implementation where every implementation of its kind is served. A refusal starts block-single-implementation: BLOCKED: <file>:, quotes the model's reason and ends with how to write it for every implementation. It appears as a {"decision":"block","reason":"…"} document, and the harness does not make the write. An allowed write prints nothing.

Why it exists

A product that abstracts over many interchangeable implementations of one kind (agent harnesses, model providers and models, platforms, clouds, browsers, the workshop's products) serves all of them through the part they share. Documentation and code in that part were written in terms of one implementation alone: a page that explained how hooks reload only through one harness's extension file left every other harness undocumented. An agent that works with one implementation all day writes that way without noticing, and nothing stopped the next write.

How a write is read

Only files inside a repository are read, and a path declared in the repository's .tama/violations-ignore is not. The text the write adds and the file it goes to are read by a model, through Oko's model call, against the rule in block_single_implementation/judge-prompt.md: the model first decides which kinds of implementation the file serves, from its place and what the text does, and then whether the added text describes or decides the behaviour of one of them as if it were all of them. No kind and no implementation name is listed in Tama: a list would be the keyword logic block-keyword-literals refuses, would miss the next kind, and would refuse what is rightly one implementation's own.

These pass: text in one implementation's own adapter, catalogue entry, configuration or test; one implementation named as one example among others or in a list of all of them; a statement true of every implementation that happens to mention one; code that reads an implementation's properties from the catalogue or declaration the product keeps for that kind.

Without a model

A question the model does not answer is decided as for every judged gate: on a machine that declared tama model set --none nothing is asked and nothing is refused for it; with a model declared, an unanswered question refuses the write with TAMA_HOOK_INFRASTRUCTURE: block-single-implementation: review unavailable: … and its actual cause. Oko answers the model call through Brama, or through the OpenAI-compatible service declared with oko model set on a machine without Brama.
