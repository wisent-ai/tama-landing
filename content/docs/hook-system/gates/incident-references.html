Incident references

The write gate (pre-write-edit) refuses a write that puts a pointer into the internal defect register or transcript store into product code or a public page. Such a pointer tells a reader nothing they can follow, and on a product's site it publishes the operator's internal history. Why a line or a page exists is said in the product's own terms; the incident stays in Oko.

What is refused

  • defect or session followed by an eight-character hexadecimal identifier;
  • a bare agent session identifier (01a0xxxx-xxxx…);
  • a session-numbered message (01a0xxxx #N).

Where

  • Product code: .rs, .swift, .ts, .tsx, .js, .mjs, .cjs, .py, .sh, .go, .kt, .java, .c, .h, .m, .mm, .cpp.
  • Public pages: every file in a product's site repository (a path containing -landing/), and any repository's README.md and CHANGELOG.md.

Private notes outside those places, such as workshop rules, are not judged. Like every content rule of pre-write-edit, this one judges the whole file a write leaves, lines it already held included (whole-file judgement).

Spelled-out addresses and fleet machines

In the same places the gate refuses an IPv4 address, a user-at-host destination, a loopback name with a port, and a machine name or hostname the fleet registry copy (~/.stado/cache/registry-last-good.json) declares. Read the value from where it is declared: the Stado registry, the service directory or the product's configuration. An example uses a host under a reserved example domain (.example, .invalid, .test, example.com, example.net, example.org), or an IPv4 address in a block RFC 5737 reserves for documentation (TEST-NET-1, TEST-NET-2, TEST-NET-3), which the gate admits; the journey is a_documentation_range_address_names_no_host in tests/content/addresses.rs.

What follows the at sign names a host only when its last label is not all digits, because no top-level domain is all digits. A font axis weight in a stylesheet request and a package pinned to a release version are therefore not addresses, and a page that loads its fonts that way can be edited. The journey is an_all_digit_label_after_at_names_no_host in tests/content/addresses.rs.

A dotted quad that stands in a version is not an address either: right after a product name and a slash (Chrome/<major>.0.0.0, the product token of a user agent) or right after a regular expression's back-reference spliced into one ('Chrome/$1 followed by .0.0.0'), it names a release. The same quad as a URL's host (after //) or standing alone is still refused. The journey is a_quad_in_a_version_token_names_no_host_and_one_in_a_url_does in tests/content/addresses.rs.

What the installation declares its own

block-internal-names also refuses, in a product checkout, what the installation running Tama declares its own in the shared-hooks/internal-names.json of a policy bundle it imported (tama policy import): its names anywhere in a file, the ids of the rulings its rulingRegisters keep (whole, or their first group), and any run of quoteWords consecutive words of what its operator said there. A checkout whose remote names one of its instanceRepositories is not judged, since that is where the instance's own decisions belong. Tama compiles in no installation's names. A ruling register the declaration names that cannot be read ends the hook with TAMA_HOOK_INFRASTRUCTURE: block-internal-names could not read the ruling register …, naming the file and the cause, instead of judging the write as one that names nothing.

The journey cargo test --manifest-path rust/Cargo.toml -p tama-cli --test internal_names_bundle imports a fixture bundle into a home under .build and refuses a declared host, a ruling id and a run of the operator's words in a product checkout, passes a sentence about behaviour there and the same ruling text in the instance's own repository, and names a missing ruling register.
