Build and restart registry: block-unregistered-build-or-restart

A gate on pre_tool_use:bash (tama-block-unregistered-build-or-restart) that refuses a command which would build a product or restart a service while the registry holds no open entry for it. Every refusal starts BLOCKED: unregistered build: or BLOCKED: unregistered restart:, goes to stderr, and exits 2 before the command runs. The registry is ~/.shared-hooks/build_restart_registry.json, and the only writer is tama-cli build.

Why it exists

On 2026-09-20 a single session submitted Brama 0.4.39, 0.4.40, 0.4.41, 0.4.42, 0.4.43 and 0.4.46, Stado 0.21.33, Weles 0.7.16 and 0.7.28 and Skarbiec 0.3.11. Several died after twenty to forty minutes in the builder queue on cargo fmt --check, on one clippy lint, or on a rollback declaration that was missing — each of them checkable locally in under a minute. The same session installed a launchd unit, restarted it, and retired it again; nobody had asked for it. The operator's words the next day named the shape underneath: an agent makes a minimal change, submits, waits forty minutes for the builder, reads the failure and makes another minimal change.

A build spends a fleet builder, of which there are two for darwin-arm64, and a restart spends a service that other work is reading. So each is stated before it runs — what it is for, which revision it carries, when the authorization stops — and the entries are rationed: three builds in any 24 hours, and a build has to carry a change worth a builder.

The ration

LimitValue in codeWhat it stops
builds_per_day3A fourth build inside a rolling 24 hours is refused, naming the targets that spent the first three and how many minutes until the next one frees. A retry after a failed build spends a slot, which is the point: the local gates cost a minute.
restarts_per_day10Counted separately, so a spent build allowance never holds back a service that has to come back.
minimum_changed_lines30A build is measured with git against the revision the last recorded build of that target carried. Under the threshold it is refused and told to travel with the next serious change; the same revision twice is refused as a build of nothing.
window_minutes60How long one recorded intent authorizes, and the ceiling on --minutes. Four hours is the hard maximum whatever the file says.

The limits live in ~/.shared-hooks/build_restart_policy.json and are read with tama-cli build policy. A machine with no policy file is still rationed by the values in code. Tightening a limit needs nothing; loosening one — more builds a day, a smaller change, a longer window — needs DEVICE_HOOK_EDIT_APPROVED=1 set outside the agent session, because an agent that can raise its own allowance has none. The rolling 24 hours is counted from ~/.shared-hooks/build_restart_ledger.json, which keeps every recorded intent for thirty days, so closing an entry ends the authorization and does not give the build back. A ledger or policy that cannot be read refuses the build instead of counting the day as unspent.

One entry authorizes one kind against one target, and expires:

tama-cli build record --kind build --target skarbiec \
  --reason "identity kind and duplicate refusal, suite green locally" \
  --revision 45a5c678042147f76241adf76fb7cf217e121ca6

tama-cli build record --kind restart --target brama-desktop-model-router \
  --reason "the router holds a revoked credential and reads it once at start" \
  --minutes 30

tama-cli build list
tama-cli build close --kind build --target skarbiec
tama-cli build policy
tama-cli build policy --builds-per-day 2 --minimum-changed-lines 80
FieldWhat the command demands
--kindbuild or restart. Nothing else is an entry.
--targetThe product for a build, the service or unit for a restart. A build whose command names no target of its own — stado release submit --source ., cargo build — is registered against the repository the command runs in.
--reasonAt least eight words. A reason of one word is refused, because the entry exists to be read later by somebody who was not there.
--revisionRequired for a build, and it must be a full forty-character source revision. A build that cannot name what it carries is not recorded.
--repositoryWhere the change is measured for a build. Without it, the repository the command runs in.
--minutesHow long the entry stays open: one to the policy's window, sixty by default, four hours at the very most. Past that it authorizes nothing, so an entry that is never closed cannot become a standing permission.

A registry file that is missing, empty or malformed holds no entries, which refuses every build and restart rather than letting them all through.

What is refused

KindCommands
buildstado release submit|prepare|resume|rollback|promote-version, cargo build, cargo install, swift build, xcodebuild, npm run build, bun run build
restartstado service restart|ensure|deploy|stop|bootout|refresh-image, stado host reboot, launchctl kickstart|bootout|bootstrap|load|unload, systemctl restart|start|stop, brew services restart|start|stop

The refusal prints the tama-cli build record line for that exact kind and target, so the route out of it is the command itself.

What passes

Reads of the same programs: stado release status, stado service list, launchctl list|print, any invocation carrying --help, cargo test, cargo fmt --check and cargo clippy — the local gates a build fails on are never themselves gated. The command is read the way a shell reads it, cut at separators outside quotes with quoted text blanked and env, sudo, nohup and timeout stepped over, so grep 'cargo build' notes.md and a commit message that mentions a restart run nothing and are allowed.

Where the refusal comes from

Source: rust/crates/tama-hook-tools/src/ports/block_unregistered_build_or_restart/mod.rs, with the command vocabulary as data in vocabulary.json beside it and the registry reader in registry.rs; binary: src/bin/block/safety/execution/block_unregistered_build_or_restart.rs; the writer: rust/crates/tama-cli/src/builds/mod.rs; the real-binary test that drives the gate and the real tama-cli against a disposable registry: rust/crates/tama-hook-tools/tests/build_registry_guard.rs; the declaration the registration reads: hook-declarations/block-unregistered-build-or-restart.json. Registration is two commands: DEVICE_HOOK_EDIT_APPROVED=1 tama hooks declare --file hook-declarations/block-unregistered-build-or-restart.json for the catalogue entry, the registry entry and the reseal, and DEVICE_HOOK_EDIT_APPROVED=1 tama hooks release for the binary and the installed release.
