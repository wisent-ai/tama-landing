Answering first, measured time, deadlines and local model servers

These gates hold rules the operator gave about how an agent works: his question is answered before anything else runs, a duration is read and never guessed, no call carries a deadline, a wait on another process is not work, a change is checked by reading it back, and no local model server stands in for a reviewer. Each decides without a model, without the network and without a lock; each lets one exact shell command through on the operator's own words, recorded with tama justify record. None is selected by default: the operator selects them.

block-calls-before-answer

A gate on every tool. It reads what the operator's newest message is from Oko's current open-work snapshot of the session (newestMessage.kind, the reading block-text-outside-tool-calls already lets an answer through on) and never classifies his words itself:

  • question: every call is refused until an assistant message carrying words stands after his message in the session's transcript. Once the session has answered him, the work goes on.
  • order — a message that stops or restricts the work for this turn, such as nie koduj or a tool ban: every call is refused until he writes again. The turn's answer is words, which the text gate lets through.
  • defect — he reports that something delivered is broken or wrong: every call but Oko's own is refused until a successful call after his message ran oko defects on one defect — record a new one, or show, assign or reopen the one it already is; a listing alone is not that. His report is taken as a defect before the session's own plan, never denied or carried past.

A snapshot that is missing, not current or unreadable, a message Oko reads as anything else, and a transcript that cannot be read decide nothing. The refusal quotes the first line of his message. Grant kind: before-answer.

inject-measured-time

A UserPromptSubmit hook that adds, before every turn, how long the session's last stretch of work took, read from the times its own transcript records: from the operator's newest message with any record after it to the last record before his next message, and the session's whole span. Asked how long something took, the agent reads the figure in front of it instead of guessing. It refuses nothing; a transcript with no times adds nothing.

Deadlines and waits on another process (block-wait-polling)

Besides sleeps and repeated looks, block-wait-polling refuses a shell call that sets itself a deadline: timeout or Homebrew's gtimeout in front of a command (inside bash -c lines too), sudo --command-timeout, or a positive number in the call's own timeout field. Zero and an absent field pass: a deadline is removed, not set to zero. Grant kind: deadline.

A shell line that only blocks until another process ends is refused as a wait, as gh run watch already was: caffeinate -w <pid> and tail --pid. caffeinate keeping the machine awake while a command does work passes.

block-local-model-server

A gate on bash calls that refuses fetching, installing or starting a model server on this machine: ollama serve|run|pull, llama-server, vllm serve, mlx_lm.server, lms server start, text-generation-launcher, brew install ollama and pip install vllm, as its servers.json declares their command paths. A push held for want of a model reviewer is answered by the commit's Tama attestation, which tama hook review-push and tama attestation check --commit read with no model. Grant kind: model-server.

A direct browser engine on the operator's word (block-browser-usage)

A browser still runs through Weles. One exact shell command the operator granted (--kind browser) runs a direct engine; a different command, and a browser tool or device, stay refused.

Checking a change by reading it (block-stop-without-verification)

A turn that changed files ends once every changed file was read back after its own last change, besides an execution-class call or a recorded external blocker. The refusal asks for the change to be read and checked and never orders a build.

Asking the operator only at a gate's refusal (block-ask-without-refusal)

A Stop gate. The answer that ends a turn asks the operator to act when it hands him a command to run: a line of a fenced code block whose program this machine runs (on PATH, or an executable path) and which no shell call since his newest message ran, or an inline code span running tama justify record. Such an answer is refused, naming each command, unless a tool result since his newest message is a refusal whose banner names a hook the installed registry owns: the proven boundary. A failed call whose text names no hook is no refusal. A session whose transcript header names a parentSession answers that session and is not judged. No model and no word list; a transcript or registry that cannot be read refuses nothing and says on stderr which file and why.

BLOCKED (block-ask-without-refusal): this answer hands the operator a command to run that this turn never ran: `…`. …

The journey cargo test --manifest-path rust/Cargo.toml -p tama-cli --test ask_without_refusal_stop refuses a fenced command and a tama justify record span with no refusal in the turn, passes them after a registered gate's refusal, refuses them after a plain failed call, passes a command the turn ran, a subagent's answer and an answer asking nothing, and names an unreadable registry on stderr.

Documentation, then a run, then building (block-build-before-docs)

A gate on the tools that write files. A change to a file of a checkout whose .wisent-release.json declares a product is refused until the session's own transcript, every turn of it, holds a look at that product's documentation (an address whose host's first label is the product and whose path starts with /docs, or a path below a docs folder of a checkout named for it, its site's repository included) and a shell run of a program named as the product. A product with no program of its name on PATH needs only its documentation, and stderr says so. The refusal names the file and each step the history lacks.

The journey cargo test --manifest-path rust/Cargo.toml -p tama-cli --test build_before_docs_history builds a product checkout and a PATH for each case: a change after reading only the README is refused naming both steps, one after the docs is refused naming the run, the docs site or the site repository's docs with a run pass, a product with no program passes on its docs alone, and a checkout that releases no product is not judged.
