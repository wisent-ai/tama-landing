Conduct gates: clipboard and screen, quotations, hung tools, uncleanable writes

Four gates hold rules the operator gave in words and sessions walked through. Each reads the call or the session transcript without a model, a network request or a lock, and each passes when what it reads cannot be read, saying why on standard error. Three of them admit one exact call on the operator's own words, recorded with tama justify record as an operator grant.

block-operator-screen

A blocking pre_tool_use:bash gate. It refuses a shell line that runs pbcopy (writes the clipboard), open (hands a file, folder, URL or application to the desktop to show) or qlmanage (shows a Quick Look preview), read by the words the shell runs and through any shell handed a line (bash -c '…'). Text that only names those programs — an argument, a quoted sentence — is no call.

The clipboard and the screen are the operator's. What a session needs from him goes through oko asks ask, where his answer is recorded; what it made for him stays a file in the checkout. Grant kind: screen, for the exact command.

block-unfound-quotes

A blocking stop gate. Every quoted passage of the ending answer — two or more words between "…", „…”, “…” or «…», with code blocks and inline code set aside — must stand in the session transcript outside the agent's own messages: in the operator's messages, the assignment, or a tool result that read them. Comparison is in lower case with whitespace collapsed; a passage with an elision (…) is checked fragment by fragment.

A quotation claims the words were written as quoted. Words attributed to the operator are quoted from his message as it stands, after reading it, or not attributed at all; text the agent proposes goes in backticks. The gate cannot see a decision attributed to him without quotation marks; the same rule covers it.

block-repeat-hung-call

A blocking gate on pre_tool_use:eval (every tool a harness does not name otherwise, such as the context advisor and web search) and pre_tool_use:lookup. It refuses calling a question-answering tool again when one of its calls in this session ended in error after running longer than every call the session completed without error. No duration is configured: the session's own call and result times are the measure, so a quick failure never counts as a hang. Shell, evaluation, process, file and wait tools are never held by it.

A tool that hung once hangs again for the same reason; reach the answer another way (read the code directly) and repair the hang as its own defect. Grant kind: hung-call, with the tool's name as the action.

block-uncleanable-writes

A blocking gate on the file tools (pre_tool_use:write, edit, notebook, multiedit). It refuses creating a file under ~/Documents that no session could remove again: outside every checkout, or at a path the checkout's Git ignores outside its .build/ and target/ — the only places block-unauthorized-deletion lets an agent delete. A new file belongs at a path its checkout keeps, to be committed, or in the ignored build output. An existing file is edited where it stands; a path outside ~/Documents is other gates' concern. Git answers both questions (git rev-parse --show-toplevel, git check-ignore). Grant kind: uncleanable-write, for the exact path.
