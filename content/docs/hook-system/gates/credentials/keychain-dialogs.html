Keychain dialogs: block-keychain-dialogs

A gate on shell calls (tama hook block-keychain-dialogs) that refuses a command which puts a keychain or authentication dialog in front of the operator. An agent's shell has nobody at it to answer a macOS dialog, and a command that reads a keychain secret in a loop raises the same dialog again and again while he is away. The gate is declared and registered, not selected: the operator turns it on with tama enforcement add block-keychain-dialogs.

It decides by each command's program and arguments alone, as the programs' manuals state it, and runs nothing: no command is tried to see whether it prompts, and no model is asked. The model-judged block-keychain-prompt-commands asks the same question of a model.

What it refuses

Every command of the line is read, through wrappers (sudo, env) and every shell handed a line (bash -lc '…'). From security(1):

  • find-generic-password and find-internet-password with -g or -w: they display the item's password, and reading an item's secret is what macOS asks the user to allow;
  • dump-keychain with -d (every item's decrypted data, one request per item) or -i (interactive access control editing);
  • export of anything but -t certs or -t pubKeys: private keys, whose export macOS asks to allow and whose passphrase is obtained via GUI without -P;
  • import of a PKCS#12 bundle (-f pkcs12, -t agg, a .p12 or .pfx file) without -P, whose passphrase is obtained via GUI;
  • unlock-keychain without -p, create-keychain with -P or without -p, set-keychain-password without both -o and -p: each prompts for a password;
  • set-generic-password-partition-list, set-internet-password-partition-list and set-key-partition-list without -k: the keychain's password must be presented;
  • add-generic-password and add-internet-password ending in -w, which prompts for the password;
  • add-trusted-cert, remove-trusted-cert and trust-settings-import, which require authentication via an authentication dialog;
  • authorize -u, authorizationdb write|remove and execute-with-privileges, each behind an administrator's authentication;
  • security -i or -p, which run commands read from standard input that no gate sees.

And signing with a keychain identity, whose private key macOS asks the user to allow unless it sits in a keychain made for signing: codesign -s|--sign (an ad-hoc -s - aside), productsign, pkgbuild and productbuild --sign, and security cms -S, when their --keychain (-k for cms) is missing or does not lie in a folder the gate's declaration lists. The list is the operator's data, signingKeychains in hook-declarations/credential-safety/block-keychain-dialogs.json, paths under the home:

"signingKeychains": [".stado/signing"]

That is where Stado's signing scope keeps the keychain it makes for one signature, with Apple's tools on its partition list. Reading attributes passes: find-generic-password without -g or -w, find-identity, dump-keychain alone, export -t certs, cms -D, codesign --verify and --display, and text that only names a command.

The refusal

The refusal names each command and its reason, as the manual says it, for example:

BLOCKED (block-keychain-dialogs): `security find-generic-password` displays the item's password (-g or -w), and reading a keychain item's secret is what macOS asks the user to allow (security(1)). Nobody at this shell can answer a macOS dialog, and refused it comes back. Read a secret through its owning product (Skarbiec) or a variable already set, sign through Stado's signing scope, and leave keychains alone. Only the operator's own words grant it: …

A signature outside a declared folder reads `codesign` signs with `<identity>` and names no keychain, so the identity is searched in the user's keychains, where macOS asks the user to allow the use of its private key; sign through a keychain in a declared signing keychain folder (~/.stado/signing), or, with a keychain named, … from the keychain `<keychain>`, which lies outside every declared signing keychain folder (~/.stado/signing), so macOS asks the user to allow the use of its private key.

One exact command passes on the operator's words, recorded with tama justify record --kind keychain-dialog (see operator grants).

What it does not refuse

A declaration, payload or shell line it cannot read (a quote never closed, a program only the running shell knows) refuses nothing and says so on stderr, beginning block-keychain-dialogs: and ending ; nothing is refused. A script run from a file is not read: the command that names it is.
