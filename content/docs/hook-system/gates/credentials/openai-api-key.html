OpenAI credentials: block-openai-api-key

A gate on shell calls, edits and reads (tama hook block-openai-api-key) that refuses OpenAI API credential material, and only that. It reads the command of a shell call, the whole file a write leaves, and the file a read names when it exists.

What it refuses

  • A key-shaped value: sk-, an optional proj-, svcacct- or admin-, then 32 or more characters of the key alphabet that mix digits, capitals and small letters, as issued keys do.
  • An assignment that gives a credential variable a value: OPENAI_API_KEY, OPENAI_API_BASE, OPENAI_API_URL or CHATGPT_RANK_API_KEY, in capitals as the environment spells it, followed by = or : (a closing quote between them allowed) and a value.
  • An authorization header that carries a token (one read from a variable, or of at least eight token characters) in the same text as an http or https request URL of the vendor's API endpoint.

A name, identifier or prose that mentions any of these passes: a message naming the variable, a test or manifest entry named after the gate (openai_api_key_writes), a document naming the header or the host, reading the variable, a branch whose name starts with sk-. The refusal begins BLOCKED: OpenAI API-key usage is forbidden for this agent., names the surface (the command, the file a write leaves with its line numbers, or the file read) and shows only the start of a key, the variable's name or the endpoint, never a key or a value.

Where it comes from

Source: rust/crates/tama-hook-tools/src/ports/block_openai_api_key/. It used to refuse the variable's name and the host wherever they appeared, which refused ordinary messages, the gate's own test entry in rust/crates/tama-cli/Cargo.toml and documents about it.
