Keychain prompts: block-keychain-prompt-commands

A gate on shell calls (tama hook block-keychain-prompt-commands) that refuses a command which can raise a macOS Keychain or interactive sign-in prompt. The prompt is native UI the agent cannot answer, so the session stands still until a person clicks it. The refusal carries a reason: line for the CLI it matched and names the non-interactive route: already-approved environment variables, an explicit connection string, service-role API calls, or a checked-in migration that invokes no keychain-backed CLI.

The first matching row decides the reason. Each pattern is assembled from the named subcommands and options of those CLIs.

Where it comes from

Source: rust/crates/tama-hook-tools/src/ports/block_keychain_prompt_commands/mod.rs. The journey cargo test --manifest-path rust/Cargo.toml -p tama-cli --test keychain_prompt_commands runs the built hook on prompting commands and requires each reason line, and on non-interactive forms (vercel deploy --token …, aws s3 ls, netlify status) requires no refusal.
