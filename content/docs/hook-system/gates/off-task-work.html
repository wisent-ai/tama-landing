Work outside the task

block-off-task-work refuses a change to a repository the session never said the operator's current instruction touches. It runs on the tools that change or publish a file — write, edit, refactor, apply_patch, and a git commit or git push in bash. Reads are never refused.

Why it exists

On 2026-09-21 a session was asked for one thing — a gate against one-off commands — delivered it, and then spent the next hour repairing an installer, a gateway, a credential pool and a provider sign-in, and starting fleet builds, none of which anybody had asked for. Every one of those things was really broken, which is what makes the drift invisible from inside: the work looks like work. The operator, reading the queue: dlaczego pracujesz nad czyms co nie jest Twoim zadaniem, and then to teraz dodajmy mechanizm ktory blokuje jakiekolwiek akcje niezwiazane z zadaniem.

Relatedness is not guessed. A gate that guessed it would be wrong in both directions — refusing a repair the instruction plainly needs, and waving through an hour of unrelated work because it looked useful. So it is declared, once per instruction, and checked mechanically.

Declaring what the instruction touches

tama task scope set --session <SESSION> --repository tama --repository tama-landing --defect df0d9346
tama task scope set --session <SESSION> --repository oko --task task-0d468fb998d4df51
tama task scope set --session <SESSION> --task task-0d468fb998d4df51
tama task scope show --session <SESSION> [--json]
tama task scope clear --session <SESSION>

set binds the declaration to Tama's capture of the latest prompt, so a later turn cannot silently reuse a stale scope. For --defect, it copies that prompt's words. For --task, it takes the task's original operator words from Oko, even when the task predates a smaller instruction. An open earlier task remains available after the smaller instruction is served: the agent can run tama task scope set --session <SESSION> --task <EARLIER TASK ID> itself, without asking the operator to say “continue”. show then names the earlier task and reports whether the declaration is bound to the latest turn. It does not claim that Oko has independently marked the smaller task done.

The open-work Stop refusal includes each open Oko task's identifier and the scope command. After recording evidence for a later defect, the agent reads the ledger, selects an earlier open task and continues it in the same session. Oko's pending independent verdict remains pending; selection is not a completion claim.

Every scope names an entry in Oko's register. An unknown task, a task already done, an unknown defect, or a defect closed by a revision is refused. The agent must select an open task whose work it is actually doing, not declare unrelated work under a convenient repository name.

A task's scope lives in its Oko contract, not in the session. With --task and no --repository, set takes the repositories the contract lists (oko-cli transcripts tasks show <task> --json, field current.contract.terms.scope). Given repositories that differ from the contract's are written back into it with oko-cli transcripts tasks state <task> --scope <repo>… --by <SESSION>, so the next session handed the same task declares the same scope, and the change appears in the contract's history. If Oko refuses that write, set fails with Oko's sentence and declares nothing. A scope with no repository — none given and none in the contract — is refused: work that touches nothing changes nothing.

What is refused

SituationWhat the session is told
Nothing declared for the current instruction The change is refused until the session says which defect or task the instruction is and which repositories it touches. It costs one command, and it makes the answer to "what are you working on" something the machine holds rather than something a model remembers.
A scope that names no defect and no task Refused. A repository is not a subject: until an entry in Oko's registers stands for the work, nothing says the change is part of anything.
A repository outside the declaration The refusal names the instruction being served and the repositories it was declared to touch. Something really being broken is not the same as being asked to fix it: record it with oko-cli defects record and say so in the answer.
A scope declared for an earlier instruction Refused as undeclared. The operator has spoken since, and that is exactly where a session drifts — one reasonable step at a time, under a scope nobody granted for the new prompt.
A completed or unknown earlier task Refused by set. Resume an open registered task; do not relabel the latest prompt as its work.

What passes

Every read. Every change inside the declared repositories. Everything outside ~/Documents/CodingProjects/Wisent — an installed program, the operator's own state, a build directory — which is other gates' subject: one-off repairs owns those.
