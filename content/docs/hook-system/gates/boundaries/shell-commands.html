Shell commands: pre-bash and block-inline-execution

Two gates read every shell command an agent runs. tama hook block-inline-execution refuses a program written inline instead of in a checked-in file; tama hook pre-bash refuses throwaway work and commands that cross a product boundary. Neither decides by a list of program names: an interpreter, wrapper or cloud CLI nobody listed walked past every list that did.

What is read from structure

Identity and shape stay structural, because they are facts a command carries:

  • the tool itself: the evaluator, notebook and REPL tools, a browser run, a debugger evaluate, and a write to one of their devices are inline execution by what they are;
  • Weles' own entry points (its keeper, trajectory folder, session start), the Supabase program, the LSI/PARP/NCBR endpoints, the Overleaf history API, and the OpenAI and Anthropic key and host names;
  • a browser's cookie store by its own file name, and a raw ssh to a host the Stado registry declares;
  • writes into ~/.shared-hooks, git checkout, patch and interactive Git modes, a tool's co-author trailer, and pull-request work against a wisent-supabase-* repository.

Hook bypass on commit and push (--no-verify, commit -n) is block-git-hook-bypass's, which runs beside pre-bash on every shell call.

What a model reads

What a command does is read by a model through Oko's model call, and only after every structural rule passed it. block-inline-execution asks only when the command's syntax can carry source at all (quoting, a here-document, a process substitution, /dev/stdin, a command list or group, eval), and is answered whether an interpreter's execute flag, a filter-language program, shell control flow or fed source runs there. pre-bash asks with the command and its working directory, and the model names the first forbidden shape it does: a write into to_check, a scratch script under /tmp, a source file written through the shell, a keyword search over code, a browser engine started directly, a program run out of a Weles checkout, a cloud/cluster/IaC/hosting CLI, a file under DO_NOT_RUN_quarantine_* executed, a local direct-API helper, or a script run out of the hook tree (which passes under HOOK_EDIT_AUTHORIZED=1 in settings). The refusal is the operator's sentence for that shape.

When no judgement can be obtained the command passes and stderr says so, with the judge's recorded state:

block-inline-execution: no judgement, the command passes: …
pre-bash: no judgement, the command passes: …

A judge answer naming a shape it was not asked for passes with pre-bash: the judge answered a shape it was not asked for (…); the command passes.

Trajectory runs

pre-bash counts a trajectory run when the command names the trajectory path or a script whose own source starts a Weles session, whatever program the script is handed to. The counters live in ~/.shared-hooks/state/trajectory_runs.json; post-trajectory-capture reads the same script the same way.

Where it comes from

Source: rust/crates/tama-hook-tools/src/ports/block_inline_execution/ and rust/crates/tama-hook-tools/src/ports/pre_bash/ (prompt: vocabulary/throwaway-prompt.md). Journeys, run against the built hook with the judge recorded as not answering:

cargo test --manifest-path rust/Cargo.toml -p tama-cli --test inline_execution_judged
cargo test --manifest-path rust/Cargo.toml -p tama-cli --test pre_bash_throwaway
cargo test --manifest-path rust/Cargo.toml -p tama-cli --test pre_bash_trajectory_runs

With TAMA_TEST_INLINE_JUDGE=1 or TAMA_TEST_THROWAWAY_JUDGE=1 and -- --ignored the first two ask the real judge: python3 -c and a shell loop refused and a commit message passed; a keyword search, gcloud compute instances list and an executed quarantined file refused, and listing the quarantine or reading one file passed.
