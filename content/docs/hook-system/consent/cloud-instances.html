Cloud instances need the operator's consent

block-cloud-instances refuses a shell command that runs a cloud provider's command line until the operator has directly consented to operations on cloud instances. It runs before every shell call; reads of files, edits and other tools are never touched.

Why it exists

Cloud instances cost money and hold the fleet's work. The operator's rule is that no operation on a cloud instance — creating, starting, stopping, resizing, deleting, listing or running on one — happens unless he said so himself, and that his consent is kept in a record rather than inferred from the task.

What is refused

Every command segment is read, one shell level down as well (bash -c '…'), and the program it runs is compared with the provider command lines the gate declares in rust/crates/tama-hook-tools/src/ports/block_cloud_instances/programs.json: gcloud, aws, az, vastai, runpodctl, doctl, hcloud, oci, ibmcloud and linode-cli. Every call of such a program waits for consent, listing included: which call of a provider's command line touches an instance is not decided by reading its words.

The refusal names the program, its provider and the capability to record:

block-cloud-instances: BLOCKED: `gcloud` operates on Google Cloud cloud instances, and no operation on a cloud instance runs without the operator's direct consent. He gives it in the conversation; record it as the Tama session capability {"tool":"cloud"} with the lifetime he names, which he confirms, then run the command.

What passes

  • A command with --help or -h, which runs nothing.
  • A command that only names a provider as an argument, such as echo gcloud or grep -rn vastai docs.
  • Stado's own commands: placement through the fleet is Stado's work, not an agent's call of a provider.
  • Any provider command in a session whose recorded capability grants {"tool": "cloud"}.
  • An az command while the operator's standing credit floor stands and Stado measures the Azure credits above it (below).

Giving consent

The operator says in the conversation that the agent may operate on cloud instances, and for how long. The agent records it by writing {"grants":[{"tool":"cloud"}],"lifetime":"single-use"} (or expires-at or current-session, as he named it) to xd://tama_request_session_capability. A capability an agent asks for is granted only when the operator confirms it, and the session's capability file in Tama's session-control directory keeps that confirmation for the lifetime he named. tama sessions capability revoke --session <ID> --agent <harness> withdraws it at once.

A standing floor of credits

The operator may allow cloud operations in every session for as long as a provider's credits stay above an amount he named. That ruling is recorded in Oko's ruling register with the subject capability:cloud@credits-floor:<billing>:<amount>:<currency>, the amount and currency his, and <billing> the variant under which stado billing show --json measures that provider's credits; programs.json names that variant for each provider Stado measures (az: azure). For such a program the gate reads the floor from the register (the file OKO_RULING_REGISTER names, else Oko's own), runs stado billing show --json, and compares the variant's available_balance with the floor in the same currency: above it the call is admitted; at or under it, refused with block-cloud-instances: BLOCKED: `az` operates on Microsoft Azure cloud instances: azure credits are <amount> <currency> (reported <time>), at or under the floor of <floor> <currency> the operator set in ruling <id>. …. A balance Stado cannot give (Stado not found or failing, no ok section, no amount, currency or report time) is refused naming why, since no measurement is never a pass; a floor in another currency than the measurement is refused rather than converted; a floor subject whose parts cannot be read is refused naming its ruling. The floor is his only when the words the ruling quotes state it: an amount in digits, at most one multiplier right after them (k or K for thousands, M for millions), and a currency mark beside it, a sign ($, €, £, zł) or a code in capitals (USD), in the same word or as the word next to it, so while there are over 50k$ of credits states 50000 USD. The multipliers and signs are declared, each multiplier with its source, in rust/crates/tama-hooks/src/oko_rulings/notation.json. A subject whose amount and currency his words do not state is refused for every billed call, since an agent typed it: the operator's credit floors cannot be read: ruling <id> names the credit floor <amount> <currency>, which the words it quotes do not state (they state [<amount> <currency>, …]): "<his words>". Of several standing floors for one billing, his newest ruling's decides, as his latest word does elsewhere. A session capability {"tool": "cloud"} still admits any provider command, and a provider no floor bills waits for it as before.
