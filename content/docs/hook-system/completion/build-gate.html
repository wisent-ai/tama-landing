How the build gate decides a build

Part of enforcement control, completion enforcement. The policy the gate applies — a build, compile or test waits until every open item carries a repair — is on the completion policy and work registers page; this page says who decides it and what the gate answers.

Oko decides, the gate asks

block-one-off-repairs keeps no count of open work. For every compile it asks Oko's one admission decision, oko admit build --product <product> --session <id> --json, once for each product the command builds. Oko answers from the operator's rulings first; where none decides a session's build, compile or test, from his standing rule that it waits until every open defect is repaired or kept as a claim and every task the newest control pass owes carries a repair (oko tasks owed). An item the build itself unblocks — an open blocker that names it and waits (oko blockers record --waits-on) on a defect whose repair is pushed — is not waited on; oko blockers held lists those items, and the stop gate (block-stop-with-open-work) holds exactly the same ones.

What the gate answers

  • A standing withdrawal (no-build or no-build:<product>): the build is refused quoting the ruling Oko answers with, whatever else consents.
  • A standing consent (build or build:<product>): the build is admitted, and stderr says build admitted by the ruling.
  • No ruling, and Oko holds the build on open work: the operator's answer to a build-consent ask or the build capability of this session admits it; otherwise the build is refused with `<build>` builds, compiles or tests, and Oko does not admit it: build waits until every open item carries its pushed repair, and <n> open item(s) carry none, first <item>; …, followed by the route to repair and record each item.
  • No ruling and nothing held: the build is admitted.
  • Oko installed but unreadable: the gate does not take silence for an admission; unless a consent of this conversation admits the build, it is refused with Oko's admission could not be read (<cause>); an unread answer is not an admission. A machine with no Oko CLI has no register and no rulings, so nothing holds the build there.

Each Oko reading the gates make announces itself on stderr through the shared wait mechanism before it waits and when it ends, so a reading that stands still names the command it stands on.

Qualification

tests/build-gate/consent.rs and tests/build-gate/standing.rs run the built tama hook block-one-off-repairs the way OMP's PreToolUse dispatch runs it, on a signed-in host, against the installed Oko CLI with defect, blocker and ruling registers of the run's own (OKO_DEFECT_REGISTER, OKO_BLOCKER_REGISTER, OKO_RULING_REGISTER) holding one open defect recorded through oko defects record with no repair: without consent the build is refused naming that item; a whole-session build capability and a standing build:<product> ruling admit it; a newer no-build:<product> ruling refuses it quoting the withdrawal, even with the capability. Oko's own journey tests/constraints/open_work.rs covers the rule itself, the held items and a run naming no session.
