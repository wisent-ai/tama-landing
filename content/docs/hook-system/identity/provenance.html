Identity provenance and incremental checking

How Tama sources newly introduced identities without rereading unchanged prose and transcript bodies.

block-identity-literals refuses an email address, a UUID, or an identifier that flattens an address when nothing issued it. It reads only the lines a write adds — the + lines of a hashline section or patch, an edit's replacement, a new file's content — never the lines the file already holds: an identity already on the page was sourced by the write that put it there. A value passes when the harness issued it as the name of a stored transcript (a session id: OMP names each session's transcript under ~/.omp/agent/sessions after it), when a file the written path's own git checkout already tracks carries it (a product's published identifier — a journey version id in a seed, a row id — asked of git grep, which reads only the index), when an artifact outside any conversation carries it (a token cache, a cloud profile, the machine registry), when Oko issued it as the id of an entry in its harsh-review queue (OKO_HARSH_REVIEW_QUEUE, else ~/Library/Application Support/Oko/harsh-review-queue.json; a UUID quoted in an entry's message is the author's text and sources nothing), when Oko issued it as a defect's id in its defects array (OKO_DEFECT_REGISTER, else ~/Library/Application Support/Oko/defects.json; evidence and notes issue no identities), when the operator used it in two or more stored sessions, or when identity_provenance.json records his verbatim quote declaring it. The transcript names and the checkout are asked first, so a write that names a session or an identifier the repository already holds does not wait on a read of every transcript on the machine; an untracked file beside the write counts for nothing. A path outside any checkout (no folder above it holds .git) is not searched. Inside a checkout, a git grep that cannot start, ends on a signal, or writes an error sources nothing while the other sources decide; a value none of them settles is then the gate's own failure, never a missing provenance: <path>: cannot establish provenance for <value>: the written file's checkout could not be searched: git grep in <folder> ended with <status>: <git's error>. The values none of those sources carries are looked up in the stored sessions together, in one walk per written file that reads each transcript's index once and ends when every value has two sessions. A word shaped like a flattened address that is part of an angle-bracket placeholder — a usage line's <gh-owner-name> argument — is read as the placeholder it is and never searched for. Any other value is refused naming it and saying which source was missing: the UUID <value> has no provenance -- no artifact carries it and no stored user message contains it. IDENTITY_TRANSCRIPT_ROOT, IDENTITY_ARTIFACT_ROOTS and IDENTITY_PROVENANCE_FILE move the three stores. The real tests are tests/identity-literals/session_ids.rs, tests/identity-literals/tracked_ids.rs, tests/identity-literals/placeholders.rs and tests/identity-literals/whole_file.rs (cargo test -p tama-cli --test identity_literals_session_ids --test identity_literals_tracked_ids --test identity_literals_placeholders --test identity_literals_whole_file), the second against a real git checkout it creates. The last copies the real long page named by TAMA_TEST_PROSE_FILE, then edits beside an untouched unsourced id. It requires TAMA_TEST_SOURCE_REVISION and retains the candidate, binary and page digests, page byte count, commands, durations and actual decisions under the ignored build directory; it never edits the original page.

An absent review queue issued nothing. A queue that cannot be read, is not JSON, or holds no entries array or an entry without an id is the gate's own failure to ask: a value nothing else settles is refused as <path>: cannot establish provenance for <value>: Oko's review queue <file> … with the read or parse cause, never as an invented identity. The real journey native_review_ids_are_sourced_but_request_prose_is_not in tests/identity-literals/issued_reviews/journey.rs (part of the identity_literals_mentions target, run with --ignored) has the real Oko CLI issue an entry into an isolated queue for an existing candidate tree, requires the actual hook to admit that entry's id and refuse a different UUID carried only in the entry's message, then damages and replaces the queue to observe both failure causes. It needs TAMA_TEST_SOURCE_REVISION, TAMA_TEST_CANDIDATE_TREE, TAMA_TEST_REVIEW_AUTHOR, TAMA_TEST_OKO_EXECUTABLE and TAMA_TEST_REVIEW_MESSAGE, and retains binary digests, commands, the issued queue and every decision under the checkout's ignored build directory.

The defect issuer reads only defects[].id, never a UUID quoted in evidence, notes, assignments or other prose. Its path follows Oko's native register contract: an explicit OKO_DEFECT_REGISTER is a native path, not a tilde-expanded shell expression; without one, HOME must be readable and absolute. A genuinely absent register issued no identities. An unreadable register, malformed JSON, missing defects array or missing entry id names the actual source path and read or decoding cause. One independent issuer's actual identity is sufficient; an unavailable unrelated issuer must not conceal it. When no source settles the identity, unavailable issuing sources retain their actual causes rather than accusing the caller of inventing the value.

The maintained native_defect_ids_are_sourced_but_note_prose_is_not journey in tests/identity-literals/issued_defects/journey.rs belongs to the identity_literals_mentions target. Run cargo test -p tama-cli --test identity_literals_mentions native_defect_ids_are_sourced_but_note_prose_is_not -- --ignored --nocapture with TAMA_TEST_SOURCE_REVISION, the absolute real TAMA_TEST_OKO_EXECUTABLE and the actual TAMA_TEST_FINDER_SESSION. It uses the real Oko CLI to issue and annotate a record under a fresh isolated HOME and register, then invokes the actual native hook. It checks genuine identity admission, refusal of another UUID carried only in a note, an independently valid issuer beside an unavailable one, retained causes when both fail, malformed and unreadable registers, genuine absence and restored persisted state. For empty, blank and padded register overrides, it also asks the actual Oko CLI to read the genuinely issued row, then requires the native identity hook to admit that same identity. The default-location case uses an isolated copy of the real issued register, not a fabricated record or an operator credential store. The issued fixture declares its observable completion criterion. Its record and note commands carry separate explicit local statements about those isolated mutations, using Oko's supported attestation path if no model supplies a judgment. Those statements neither override a negative judgment nor attest a repair or a passing test. The command's actual refusal remains a failed qualification; the journey does not borrow an operator credential or change the model route. It retains commands, statuses, both executable digests and actual decisions under .build/identity-issued-defects. The operator's registers are not changed. The journey exercises the source tree's hooks; installed enforcement and the rendered desktop are outside it.

When transcript content is required, hook subprocesses share per-file identity snapshots under Tama's state directory in identity-mentions. Each snapshot is bound to the source file's device, inode, byte length, modification time and metadata-change time, plus the identity extractor. Unchanged files are not reopened for their transcript bodies. A per-file OS lock gives a changed file one reader across sessions, and completed shards are atomically published so another hook can reuse them. There is no clock-based expiry. Removed, replaced, appended or permission-changed files do not retain their old provenance verdict. Only actual user-message identity tokens count; assistant messages are not independent operator evidence.

The shared index applies the transcript-name reader's artifact boundary: a directory beside a JSONL transcript with the same stem is not traversed. Its artifacts and subagent files cannot count as another independent user session. This avoids reopening artifact subtrees during each metadata walk; the real journey verifies both a nested user-shaped artifact and malformed artifact content while genuine independent transcript evidence still passes.

A read, parse or publication failure names its path and operation and refuses the write as unavailable provenance, rather than claiming the identity was invented. Cold or changed reads announce czekam; a contending hook announces its lock wait. These source mechanisms require actual cross-process qualification before an installed runtime is claimed to avoid repeated scans.

The explicit identity-provenance register follows the same diagnostic boundary: a genuinely absent file means no declarations, while an unreadable existing path names the failed read, exact path and filesystem cause and refuses the write. A warmed transcript index does not conceal that register failure. The real mention journey replaces its isolated register with a directory and checks the observed cause, then removes it to verify the documented absent-register state.

TAMA_TEST_SOURCE_REVISION=<full-candidate-revision> cargo test -p tama-cli --test identity_literals_mentions runs the actual hook in separate processes against isolated persisted transcripts. It retains the candidate and binary digest, commands and outcomes, covering a warm shared index, assistant exclusion, equal-size/equal-time replacement, deletion, malformed records and permission loss.
