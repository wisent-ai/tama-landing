Emergency disable

When a hook blocks work that genuinely must proceed, what is the recovery — and what does it cost? One confirmed, operator-owned action that bypasses every Tama-managed dispatcher on the machine for a stated number of minutes, records who threw it, why and until when, says so in every session record and hook answer, and lifts itself when the time has passed. It is deliberately the only way to weaken policy: sessions can enable, only operators can disable, and only globally (enforcement-control).

What it is

tama enforcement emergency on|off|expire|status (cli/enforcement/emergency), which the desktop runs through its bundled release's own tama from Posture and Settings. on takes --reason and --minutes (a whole number above zero) and records the account running it; without either, or from inside an agent session, it refuses before anything is moved. On:

  1. installs the session controllers from --release (the same install as tama hooks install-release --session-control-only) so session visibility survives the bypass;
  2. backs up ~/.claude/settings.json and ~/.codex/hooks.json into emergency-backup/ and empties their hooks maps, unless every hook command there is Tama's run-hook.mjs dispatcher, which reads the emergency state itself;
  3. moves entrypoints aside to <name>.tama-disabled: the OMP agent hooks directory and every Git hook source the installed registry declares;
  4. stops the editor watcher (the ~/.shared-hooks/editor-hooks.pid process, then the com.wisent.editor-hooks.plist LaunchAgent);
  5. writes emergency-backup/manifest.json once and hook-emergency-state.json (ai.wisent.tama.hook-emergency-state.v1, disabled: true, setBy, reason, changedAt and expiresAt, both ISO-8601 UTC);
  6. loads a LaunchAgent that runs tama enforcement emergency expire every minute, which restores every hook once expiresAt has passed and then removes itself.

No running agent session is stopped, paused or signalled: each session's loaded runtime reads hook-emergency-state.json and bypasses its hooks at once, so every terminal keeps its session in the foreground.

Success prints Disabled hooks for <N> minutes. Running agent sessions read the emergency state at once and keep running; the hooks run again when it expires.; repeating it prints Tama hooks are already disabled. and changes nothing.

Expiry and what every reader says

The switch holds while disabled is true and expiresAt has not passed. Once it has, every reader — the hook engine, the session records, tama enforcement status, the OMP adapter and the desktop — reads the switch as lifted and the hooks run again, without anyone touching the file, and the expiry agent then restores what was set aside and removes the file. A switch written by hand, without tama enforcement emergency on, still holds: Tama does not decide the operator's own file was a mistake. Every reader then names what its record lacks — names no one who set it (setBy), gives no reason (reason), records its time as "…", which is no ISO-8601 time (changedAt) (or records no time it was set), names no time it ends, so nothing lifts it but the operator (expiresAt).

While it holds, the switch is shown wherever a person or an agent reads:

  • every session record carries emergencySwitch — holds, set, setBy, reason, changedAt, expiresAt, expired, gaps — beside globallyDisabled;
  • tama enforcement status prints emergency switch: Tama's emergency switch is set by <who> since <when> because <why>; it lifts itself at <end>: …, and --json carries emergencySwitch and emergencyNotice (cli/enforcement/status);
  • every hook answer carries emergencySwitch, and the answer to a session start, a prompt and a turn end carries the same sentence in hookSpecificOutput.additionalContext, which the agent reads;
  • the OMP adapter puts that sentence before every turn started from a prompt (tama-emergency-switch), and appends it to the message that starts a turn without one — Tama's late stop refusal and the text gate's continuation, which OMP sends with triggerTurn and which run no before_agent_start;
  • the desktop's Posture alert says who set it, why, since and until when.

The real tests are tests/enforcement/emergency.rs (a complete switch, a hand-written one, an expired one and none, through tama enforcement status and tama run-hook), tests/enforcement/emergency_command.rs (every command and refusal of tama enforcement emergency) and tests/omp-adapter/emergency-notice.mjs (the OMP entry through OMP's own extension runner).

What it costs

The desktop's confirmation states the price before the button exists — title Disable all policies on this machine, then verbatim:

  • Unsafe actions will no longer be blocked.
  • Current sessions will keep running.
  • The policies return by themselves when the time below has passed.

with the full listing of blocking hook ids, a reason field (Why every policy must be off) and a duration stepper (Policies return by themselves after <N> minutes, 5 to 1440, 60 at first), and its actions: Read the blocking decision (shown when a hook has blocked, it jumps to Session), destructive Disable all policies — enabled only once a reason is given —, primary Keep policy active.

How state is judged

Tama treats the machine as disabled while the state file holds the switch, exactly as the hooks read it, and the desktop re-reads that durable state after the command returns — Tama could not persist the emergency hook state. is a failure, never claimed success. A machine-wide hook selection remains recorded, but the emergency bypass takes precedence: none of its selected ids run until re-enable succeeds, with one exception. block-stop-with-open-work, the gate that refuses to end a turn while work is open, keeps running whenever the selection names it (or the selection is all): a break-glass switch stops the gates that wedge work, not the one that keeps a session from walking away from it (tama-hooks KEPT_UNDER_EMERGENCY, the same id in shared-hooks/enforcement-selection.mjs; journey tests/enforcement/emergency.rs). Every reader's sentence says so: every Tama hook is off on this machine but block-stop-with-open-work, …. During the bypass, a session's generation-bound enabledHookIds allowlist can run as well (session-enable).

Re-enable

tama enforcement emergency off. A switch written by hand set nothing aside, so off lifts it by removing it: Lifted an emergency switch that set nothing aside (no emergency-backup/manifest.json): every hook runs again. …; with no switch and no manifest it refuses with Tama has no emergency switch set and no emergency backup manifest to restore. With a manifest, the bundled release must pass its seal gates. It performs the full transactional installation with the manifest — restoring every moved entrypoint, regenerating provider configs from the backups, re-bootstrapping the editor LaunchAgent — and only then removes the emergency state, manifest and expiry agent, printing Enabled approved hook release <first-12>. Running agent sessions read the cleared emergency state at once and keep running. A failed restore keeps the switch and the recovery evidence. After successful re-enable, the retained all-hooks or selected-hooks machine policy resumes.

Where it lives

PathContent
~/Library/Application Support/Tama/hook-emergency-state.jsonThe switch: disabled, setBy, reason, changedAt, expiresAt
~/Library/Application Support/Tama/hook-enforcement.jsonThe independent all-hooks or selected-hooks baseline; retained while emergency state takes precedence
~/Library/Application Support/Tama/emergency-backup/manifest.jsonconfigs emptied, moved entrypoint pairs, editorWatcherStopped — written once
~/Library/Application Support/Tama/emergency-backup/claude-settings.json, codex-hooks.jsonOriginal provider configs, restored on enable

The desktop wrapper (HookEmergencySwitch) runs the bundled release's own tama enforcement emergency, waits for its exit and for its output to close, and reports its exit status and what it printed. Its own failures (The Tama bundle does not contain the bundled hook release's tama, …, Tama could not read local policy output: <reason>, …) are listed in the runbook.

Not to be confused with

  • Deactivate. Settings → Deactivate everything runs this same global disable and then unregisters the privileged daemon, System Extension, and network filter independently (desktop/settings). Emergency disable alone leaves the privileged backend registered.
  • A per-session disable. Does not exist, anywhere in the product (core-contracts).
  • Uninstalling. The bypass moves entrypoints aside and empties config maps; every byte needed to restore enforcement stays on disk, deliberately (operations).
