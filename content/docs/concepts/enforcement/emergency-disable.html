Emergency disable

When a hook blocks work that genuinely must proceed, what is the recovery — and what does it cost? One confirmed, operator-owned action that bypasses every Tama-managed dispatcher on the machine for a stated number of minutes, records who threw it, why and until when, says so in every session record and hook answer, and lifts itself when the time has passed. It is deliberately the only way to weaken policy: sessions can enable, only operators can disable, and only globally (enforcement-control).

What it is

emergency_disable_hooks, a bundled POSIX script the desktop runs from Posture and re-runs with TAMA_EMERGENCY_ACTION=enable for re-enable (scripts). A disable takes its terms from the environment and refuses without any of them, exit 2, before anything is moved: TAMA_EMERGENCY_SET_BY (who throws it; the desktop passes the macOS account), TAMA_EMERGENCY_REASON (why) and TAMA_EMERGENCY_MINUTES (a whole number above zero: how long it holds). A missing one answers Tama will not disable its hooks without <NAME>: …; minutes that are not a whole number above zero answer TAMA_EMERGENCY_MINUTES is <value>; it must be a whole number of minutes above zero. Disable, in order:

  1. reinstalls the session controllers (tama hooks install-release --session-control-only) so session visibility survives the bypass;
  2. backs up ~/.claude/settings.json and ~/.codex/hooks.json into emergency-backup/ and empties their hooks maps, unless every hook command there is Tama's run-hook.mjs dispatcher, which reads the emergency state itself;
  3. moves entrypoints aside to <name>.tama-disabled: the OMP agent hooks directory and every Git hook source the installed registry declares;
  4. stops the editor watcher (the ~/.shared-hooks/editor-hooks.pid process, then the com.wisent.editor-hooks.plist LaunchAgent);
  5. writes emergency-backup/manifest.json once and hook-emergency-state.json (ai.wisent.tama.hook-emergency-state.v1, disabled: true, setBy, reason, changedAt and expiresAt, both ISO-8601 UTC).

No running agent session is stopped, paused or signalled: each session's loaded runtime reads hook-emergency-state.json and bypasses its hooks at once, so every terminal keeps its session in the foreground.

Success prints Disabled hooks for <N> minutes. Running agent sessions read the emergency state at once and keep running; the hooks run again when it expires.; repeating it prints Tama hooks are already disabled. and changes nothing.

Expiry and what every reader says

The switch holds while disabled is true and expiresAt has not passed. Once it has, every reader — the hook engine, the session records, tama enforcement status, the OMP adapter and the desktop — reads the switch as lifted and the hooks run again, without anyone touching the file; the file stays as the operator's record until a re-enable removes it. A switch written by hand, without the script, still holds: Tama does not decide the operator's own file was a mistake. Every reader then names what its record lacks — names no one who set it (setBy), gives no reason (reason), records no ISO-8601 time it was set (changedAt), names no time it ends, so nothing lifts it but the operator (expiresAt).

While it holds, the switch is shown wherever a person or an agent reads:

  • every session record carries emergencySwitch — holds, set, setBy, reason, changedAt, expiresAt, expired, gaps — beside globallyDisabled;
  • tama enforcement status prints emergency switch: Tama's emergency switch is set by <who> since <when> because <why>; it lifts itself at <end>: …, and --json carries emergencySwitch and emergencyNotice (cli/enforcement/status);
  • every hook answer carries emergencySwitch, and the answer to a session start, a prompt and a turn end carries the same sentence in hookSpecificOutput.additionalContext, which the agent reads;
  • the OMP adapter puts that sentence before every turn started from a prompt (tama-emergency-switch);
  • the desktop's Posture alert says who set it, why, since and until when.

The real tests are tests/enforcement/emergency.rs (a complete switch, a hand-written one, an expired one and none, through tama enforcement status and tama run-hook) and tests/omp-adapter/emergency-notice.mjs (the OMP entry through OMP's own extension runner).

What it costs

The desktop's confirmation states the price before the button exists — title Disable all policies on this machine, then verbatim:

  • Unsafe actions will no longer be blocked.
  • Current sessions will keep running.
  • The policies return by themselves when the time below has passed.

with the full listing of blocking hook ids, a reason field (Why every policy must be off) and a duration stepper (Policies return by themselves after <N> minutes, 5 to 1440, 60 at first), and its actions: Read the blocking decision (shown when a hook has blocked, it jumps to Session), destructive Disable all policies — enabled only once a reason is given —, primary Keep policy active.

How state is judged

Tama treats the machine as disabled while the state file holds the switch, exactly as the hooks read it, and the desktop re-reads that durable state after the script returns — Tama could not persist the emergency hook state. is a failure, never claimed success. A machine-wide hook selection remains recorded, but the emergency bypass takes precedence: none of its selected ids run until re-enable succeeds. During the bypass, only a session's generation-bound enabledHookIds allowlist can run (session-enable).

Re-enable

A switch written without the script set nothing aside, so enable lifts it by removing it: Lifted an emergency switch that set nothing aside (no emergency-backup/manifest.json): every hook runs again. …; with no switch and no manifest it refuses with Tama has no emergency switch set and no emergency backup manifest to restore. With a manifest, the bundled release must pass its seal gates. It performs the full transactional installation with --emergency-manifest — restoring every moved entrypoint, regenerating provider configs from the backups, re-bootstrapping the editor LaunchAgent — and only then removes the emergency state and manifest, printing Enabled approved hook release <first-12>. Running agent sessions read the cleared emergency state at once and keep running. A failed enable preserves the recovery evidence. After successful re-enable, the retained all-hooks or selected-hooks machine policy resumes.

The desktop wrapper (HookEmergencySwitch) waits for the script's own exit and for its output to close, and reports the script's exit status and what it printed. Its own failures (The Tama bundle does not contain the emergency hook controller., Tama could not read local policy output: <reason>, …) are listed in the runbook.

Not to be confused with

  • Deactivate. Settings → Deactivate everything runs this same global disable and then unregisters the privileged daemon, System Extension, and network filter independently (desktop/settings). Emergency disable alone leaves the privileged backend registered.
  • A per-session disable. Does not exist, anywhere in the product (core-contracts).
  • Uninstalling. The bypass moves entrypoints aside and empties config maps; every byte needed to restore enforcement stays on disk, deliberately (operations).
