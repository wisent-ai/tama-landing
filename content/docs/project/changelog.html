Changelog

All user-visible changes follow the categories required by docs/releases.md. A published section maps to the canonical immutable signed Git tag with the same semantic version.

0.2.0 — Unreleased

Added

  • block-unlinked-operator-messages is a stop gate that refuses the end of a turn while any operator message of the session is linked to no Oko record: it runs oko rulings unlinked --session <ID>, which names for each message the ruling recorded from it or the defect its task is related to, and relays Oko's refusal with the two commands that link an unlinked one. A correction the operator gives is open work in the registers from that turn on, not words he teaches again in the next session. No model decides it; a machine without the Oko CLI is left alone. See finishing work; real journey tests/operator-rules/unlinked.rs.
  • Every gate built on the write replay judges an apply_patch envelope and a notebook cell edit by the file they leave. The replay rebuilds each added and updated file of an envelope (*** Add File, *** Update File with its @@ hunks and *** Move to, *** Delete File leaving nothing) and a notebook as its cell edit leaves it (replace, insert after the named cell or at the head, delete, by cell_id or cell_number); a hunk the file does not hold, a cell the notebook lacks, a notebook that is not JSON or an unknown edit_mode refuses the write naming it, and nothing is judged by its fragment. Before, an envelope was refused as unreplayable and a notebook edit as having no supported operation. Real journeys tests/numeric-literals/replay/patch.rs and tests/numeric-literals/reconstruction.rs.
  • block-hidden-subcommands reads the hyphen clap derives without one being spelled: a variant of a Subcommand enum whose CamelCase name has more than one word and carries no name attribute (GpuPowerLimit, which clap serves as gpu-power-limit) is refused as clap subcommand whose CamelCase variant derives a hyphen-joined name (no name attribute) with its line. A dozen host-side verbs passed the gate this way while spelling none of their hyphens. A variant whose attribute names it, a one-word variant, an acronym and an enum that is not a Subcommand pass. Real journey tests/hidden-subcommands/refusal.rs.
  • block-unrepaired-negative-report is a stop gate for a session whose Oko role is supervisor: Brama's reviewer names every sentence of the ending answer that reports something broken, stopped, refused or missing and that no action of the turn answers, with the Oko defect it cites, and Oko's register (oko defects show <id> --json) decides whether that defect has a recorded repair or an owner. A sentence citing no such defect refuses the stop, quoted with its cause. See supervisor negative reports; real journey tests/supervisor-stop/negative_report.rs.
  • The managed pre-push dispatcher runs tama hook review-route first: it resolves the reviewer's route exactly as review-push will, and a push no reviewer can address is refused at once (review-route: no reviewer can be addressed, so this push is refused before its checks run: <cause>) instead of after minutes of formatting and quality checks. Real journey tests/review/route/preflight.rs.
  • The push reviewer finds Brama through the fleet authority's directory when this host's Stado cannot answer: after the fleet route and the relay fail, Tama reads the registry copy the authority last served (~/.stado/cache/registry-last-good.json) and carries the review over a system-SSH forward it owns, so a broken Stado release no longer leaves its own repair without a reviewer. Every refusal names each cause in order. Real journey tests/review/route/authority.rs.
  • The standing-rules block that inject-operator-rules and tama assignment show print gives each distinct rule text once, under the newest message carrying it, with said N times since <time> when the operator said it in several sessions. Malformed ledger reports carry their decoding cause instead of becoming an empty rules block or invented message provenance. The live-ledger journey tests/operator-rules/distinct.rs checks every distinct text and retains the source revision, working-tree diff, commands, exits and raw outputs; a ledger changed during the journey is reported as an inconclusive run.
  • OMP sessions receive the operator's standing rules after every compaction: the OMP adapter puts the context of the session_start:compact hooks (inject-operator-rules) into the session as a displayed message, or the reason the hooks refused or failed. Before, the adapter ran the hooks and dropped what they returned, so no OMP session got the rules back. A passing user_prompt_submit hook's context is delivered the same way.
  • tama hardcodes, its hardcodes/scan request and Tama Desktop's Hardcodes screen are removed. The command reported every number, address and name in a tree as one undifferentiated count, which is no operation on an object Tama owns and no step toward giving a value its source; a value that decides behaviour is refused where it is written, by block-numeric-literals and its citation rule.
  • tama sessions remind (--session ID | --default) [--text SENTENCE | --clear] sets the sentence the remind-open-work hook puts after every tool result: one session's own sentence always, the machine-wide one while Oko holds open work. The hook's sentence was compiled in; it now comes only from session-control/reminders.json, so set the machine-wide sentence with --default after installing this release.
  • Tama computes SHA-256 with the sha2 library everywhere; the two hand-written copies of the algorithm and their constant tables are gone.
  • The local build ration's builds a day, when the policy file does not set it, is the operator's stated number read from numeric-provenance.json instead of a constant. The adaptive telemetry corpus stores each hook payload whole: a payload over 65,536 UTF-16 units used to be stored as a cut JSON string that no candidate repair could replay. A Brama route named in TAMA_OBJECTIVE_AUTHORITY_MODEL_ROUTE is no longer refused for being over 160 characters; only whitespace makes it unusable, and whether Brama serves it is Brama's answer.
  • block-wait-polling refuses a shell call that blocks until the operator answers (oko asks wait, declared in block_wait_polling/operator_waits.json), with his rule that waiting for his decision is forbidden: an agent that ran one stood still for as long as he did not answer. The ask stays open and delivered; oko asks show reads its answer when it comes. Asking, reading and listing asks pass.
  • tama find-violations reads every file whole: a file over 524,288 bytes is no longer skipped as larger than 524288 bytes, and a file counts as binary when it holds a NUL byte anywhere rather than in its first 8,192 bytes. The rule-gaming check reads every changed file whatever its size.
  • Hooks decide with no number nobody stated. block-wait-polling refuses only a shell call that does nothing but pass time; the third identical hub look in two minutes is no longer counted. block-repeated-blocker accepts a blocker's still-blocks check made since the operator's latest message, read from the transcript, instead of within an hour. Session records carry liveness as the owner process, the heartbeat the launcher states in TAMA_SESSION_HEARTBEAT_TTL_SECONDS, or unknown with livenessError; the 900-second default and the 5–3600-second clamp are gone, and Tama Desktop shows the reason. block-internal-names reads a prose part as a sentence when plain words are most of its tokens, not at five words. Completion refusals name every open task and defect by identifier and quote none of their text, with no 140-character clip or 12-item cut. The session-start context carries every standing rule and ruling, with no 7,000/2,500-character split.
  • tama sessions revoke-capability --session ID withdraws the capability granted to one session — a build consent the operator takes back — at once instead of at its expiry: the override's capability becomes null, the build gate refuses the next build, and the running session reports "capability": null. Before, a capability could only be granted.
  • CUA consent recording, listing and removal through tama justify --kind cua, tama request and Justifications → CUA consent. Grants are taken from actual session user messages and validated against installed application metadata without manual protected-file edits.
  • Product contract, onboarding, operational, core, integration, example, testing, release, security, and support documentation.
  • Authenticated guided setup that records completion only after the sealed runtime, enabled privileged backend, and a matching live kernel-gated agent session are all observed.
  • Desktop build provenance and immutable release packaging contract.
  • Public Tama CLI for catalog listing and validation with opt-in local install-drift checks, exact hook inspection, live session state, registry-declared provider coverage, Git dispatcher installation, repository scans and cleanup, adaptive recovery, MCP configuration, and tama request, the per-operation entry point the desktop runs.
  • Runnable examples/ shell commands with inline risk, required-input, side-effect, and rollback comments; CLI link installation is retry-safe, and prose runbooks plus the Markdown coverage matrix were removed.
  • Session destination that renders the capability a supervised session holds — lifetime, expiry, remaining uses and every tool grant — together with the register of semantic decisions that session published.
  • Coverage destination for registry-declared provider coverage, and an Install plan destination that states each scope's target paths, the exact commands that write them, and the MCP server snippet.
  • Settings destination for local enforcement — runtime installation, privileged backend registration and macOS approvals, and the confirmed deactivation of everything — plus the product and hook-release build identities.
  • Documentation corpus: per-screen desktop reference under docs/desktop/, concept pages under docs/concepts/, two executed walkthroughs (release seal verification, runtime status), a runbook of exact refusal sentences, a scripts reference, and runnable read-only integrity examples under examples/integrity/.

Changed

  • Every gate reads a tool call through one reader, tool_vocabulary::Call: the tool's name under tool_name, tool or name or nested as tool: {name, input}, compared without regard to case; its arguments under tool_input or input; the file under file_path, path or notebook_path; the shell line under command or cmd; and what a call runs (a shell line, an evaluation program, a started process). Each gate used to read the payload itself, and the ones written for Claude Code's spelling (Bash, Read, file_path) let the same OMP call through. The journey tests/payload-shapes/every_gate.rs runs every registered pre_tool_use gate on the same calls in both harnesses' shapes and requires the same decision. block-subagent-spawn no longer keeps a list of agent program names: a command handing a program a headless argument (-p, --prompt, exec, …) is read by a model, which answers whether it starts a coding agent; no judgement lets it through and says so.
  • block-overleaf-api judges a write by each file as the write leaves it — a hashline section, a string edit, an apply_patch envelope or a notebook cell edit replayed on the file, a written file's content — instead of by every string of the tool input: an Overleaf history call the file already holds is refused on its next edit, text being removed is not read as written, and the refusal names the file and the line of each match (matched: <reason> (line N: …)). A write the replay cannot rebuild — a file that does not exist, an edit whose old text is absent — is refused with the file this write leaves cannot be rebuilt to judge it: <cause>, never judged by its fragment. A call that names no tool is still judged by everything it carries. Real journey tests/boundaries/overleaf.rs (a_write_is_judged_by_the_file_it_leaves).
  • block-direct-lsi-api, check-raw-api-calls, block-openai-api-key and check-humanized-actions judge a write only by the file it leaves. Each used to fall back, when the replay could not rebuild the file, to the text a patch or a notebook cell writes — so a direct API call, a raw site call or a credential another cell of the notebook or the rest of the file already held passed the edit. Now a write whose file cannot be rebuilt is refused with the file this write leaves cannot be rebuilt to judge it: <cause>, the cause naming the file, and a notebook cell edit is judged by the notebook as the edit leaves it. Real journeys: tests/lsi-api/edits.rs, tests/raw-api-calls/edits.rs, tests/openai-api-key/writes.rs and tests/humanized-actions/edits.rs.
  • The pre-push dispatcher runs a product's declared quality gate through tama hook quality-check (stado quality check --if-declared in the checkout) and refuses in Stado's own terms. It used to print run stado quality format there, commit the result and push again whatever Stado refused, so a check that failed because a release input could not be read (Skarbiec unreachable) sent the pusher to reformat a tree whose formatting had passed. Now a formatting gate's refusal — the one Stado marks with `stado quality format` writes what it reads — prescribes stado quality format; any other refusal repeats Stado's failure line as quality-check: stado quality check refused this push of <checkout> at <failure_point> [<error_code>]: <detail>; this is not a formatting finding, so `stado quality format` changes nothing for it; repair that operation and push again; a refusal without a failure line says so. Everything Stado printed stays above the sentence. Real journey tests/quality-check/refusal.rs: an unformatted committed tree, a committed Cargo.lock that does not resolve its manifest, and a tree the check passes.
  • Every write gate names a refusal by its line in the whole file the write leaves (line N: …, numbered as an editor numbers lines), from one shared locator: check-legacy-activation-bypass, block-direct-lsi-api, block-openai-api-key, check-reward-hacking and block-unapproved-tests used to name only the file, or joined every file a patch leaves into one text; check-humanized-actions now shows its model each line with its number in the file. block-unapproved-tests exempts a test/ directory inside a Next.js app/ tree by that directory, not by a list of file stems. See Writes are judged by the whole file they leave. Real journey tests/hooks/whole_file.rs.
  • A judge request belongs to the hook process that sent it. One request Brama never answered held the resolver adapter, and every other hook's judge was refused with another request is not sent while that channel is waiting until the process that sent it was killed, with nothing saying whose request it was. Each judge request now records itself under ~/.tama/judge-channels/ while it waits; the refusal names the route, the hook process and its command line and the client process; a request whose hook ended has its client ended by the next judge, so the channel goes with its hook. Before sending, Tama asks Brama's own /readyz, and a Brama that declares it serves no traffic refuses the request with its declared reason instead of leaving it unanswered. See Adapters. Real journey tests/hooks/judge_channel.rs.
  • check-visual-before-logs checks OMP's reads: it compared the tool name with Read and took the file only from file_path, while OMP sends read with path, so no OMP read of a run log was ever held for the visual summary. Real journey tests/visual-before-logs/read_tool.rs.
  • check-frame-density, check-animation-verdict, check-artifact-inspection, check-failure-inspection and inspect-required-check count the reads an OMP transcript records (toolCall blocks of read with arguments.path), not only Claude Code's tool_use Read blocks, so an OMP session that read the frames or the recording is no longer told it read none. The journey tests/artifact-inspection/formats.rs runs an OMP transcript.
  • block-git-hook-bypass, check-git-hooks-path, block-keychain-prompt-commands, block-overleaf-api, block-direct-lsi-api and check-legacy-activation-bypass read a shell call in every spelling a harness gives the shell tool — Claude's Bash, OMP's bash, functions.bash, Codex's exec_command — from one declaration, case-blind. Each kept its own case-sensitive list holding Bash, so every OMP shell call passed them unread; their edit checks likewise read every write tool spelling. Real journey tests/shell-tool-names/spellings.rs.
  • check-legacy-activation-bypass no longer lets a shell command through because its first word is on a list of reading programs: a command that carries a marker of the retired upload path is read by a model, which answers whether it only reads or searches for the text or runs, writes or configures the path. A judgement nobody could obtain lets the command through and says so on stderr.
  • check-merge-deletion-loss judges every tracked file of a pushed merge, not only prose files picked by extension: arithmetic names a candidate, and a model reads the cut and the re-added diff and answers whether the merge quietly undid a deliberate condensation or carried the other side's own work. The refusal carries the judge's sentence; no judgement lets the push through.
  • tama vocabulary report counts word lists written as named constants: words bound one by one to names in a file and used together as one class — a collection of the names (&[WRITE_TOOL, EDIT_TOOL]), the arms of a pattern (matches!(tool, WRITE_TOOL | EDIT_TOOL)) or a comparison chain with them — reported with the words the names hold. Moving a list's words into names made the count fall while the classifier stayed. block-keyword-literals does not refuse this shape. Real journey tests/vocabulary-report/named_constants.rs; see tama vocabulary report.
  • Tama is one program. Every native hook runs as tama hook <name>, the hook engine as tama run-hook, the MCP server as tama mcp and the test runners as tama testkit <name>; no tama-<hook>, tama-run-hook or tama-mcp-server binary is built. tama hooks release installs only tama, removes the separate programs an earlier release installed, and refuses a registry or adapter that still names one; tama hook migrate-registry-to-rust rewrites the registry.
  • The CLI is built, bundled and installed as tama. The earlier tama-cli name is gone: tama hooks release removes the old ~/.local/bin/tama-cli copy, and the sealed release carries bin/tama.
  • Every backend operation runs as one tama request <operation> process that exits once it has answered, instead of a resident tama serve loopback server kept alive for the whole session; cancelling a scan or cleanup, or quitting the app, ends that operation's process tree.
  • The file/test justification recorder uses the shared justifications/record operation instead of spawning a separate CLI command from the native view.
  • Runtime installation and macOS policy registration require explicit authenticated confirmation instead of running during model initialization.
  • Session discovery is read-only when Tama has not been configured.
  • Session monitoring starts only while the authenticated control surface is visible.
  • Policy controls now require a current recognized Wisent organization role, and mutation-capable models enforce an explicit construction-time authorization boundary.
  • Tama opens Wisent session restoration directly; the explicitly selected read-only inspector uses isolated bundled-catalog state, while incomplete authenticated setup resumes until its evidence is complete.
  • In-flight repository scans and cleanup can be stopped; scan cancellation is read-only, while cleanup preserves partial edits and performs the final rescan.
  • Runtime-drift CLI checks now resolve Claude and Codex adapter configuration from the current or explicitly selected user home instead of maintainer paths embedded in the signed catalog.
  • Local setup and emergency commands now drain output concurrently, enforce bounded output and runtime, and terminate their process tree on timeout.
  • Leaving the authenticated control surface cancels active repository scan or cleanup process trees and requires inspection plus a new read-only scan after partial cleanup.
  • Product and hook-release identities are displayed separately.
  • OMP session-control reload operations await the common native hook engine and expose its observed generation or exact failure, without inserting a prompt or restarting the agent. A legacy adapter needs one command-handler reload before it can use this path.
  • Per-session controls now expose only policy-permitted enable operations and wait for the live supervisor response; the desktop no longer offers or optimistically reports prohibited hook disablement.
  • The interface is organized by operator decision rather than by data container: a grouped sidebar of eight destinations, a 44 pt context bar on every screen instead of a hero header, three-zone data screens with counted facet rails and inspectors, and the repository under repair selected once in the sidebar header.
  • Disabling every managed hook, repairing violations with a headless agent, and deactivating local enforcement now open a decision dialog that quotes the exact effect, lists what it touches, and keeps the safe verb as the primary button.
  • Mutations report the backend's own sentence in place on the screen that started them, instead of a modal alert that closes without a trace.

Fixed

  • Tama Desktop no longer shows Policy active when the emergency hook state or the installed-release record exists but cannot be read or decoded. Posture shows Policy protection cannot be confirmed with the file and the cause, protection is not shown as on, and switching hooks refuses with that cause; only a missing file still means not disabled or not installed. A session-control record that cannot be read refuses the session listing naming every such record, instead of the live session silently disappearing.
  • tama hooks release says the installed runtime's provenance is unknown, with the manifest path and the cause, when native-hook-binaries.json cannot be read or does not state its revision and whether the checkout was dirty; before, it said nothing, and a manifest without dirty was reported as a build with nothing uncommitted.
  • check-rust-format checks the Rust files a push changes - those that differ between the remote's current commit and the pushed commit - each with rustfmt --check under its package's committed edition, instead of cargo fmt --check over every workspace of the commit. A file already unformatted on the remote refused every push of the checkout, including pushes that never touched it, while push review refused the reformat-only commit that would have cleared it; such a file now holds back only the push that changes it, whose author formats it as part of that change. The real journey tests/review/format.rs pushes an unformatted file to a remote before the dispatchers are installed, then proves a push that leaves it alone passes and a push that changes it without formatting is refused naming that file alone.
  • Judge waits stream their route and endpoint to hook stderr and the adapter's progress indicator. A stop reviewer that cannot obtain a verdict refuses with the infrastructure cause. Native dispatch cancellation and input closure terminate owned hook groups without labelling cancellation a hook malfunction; runtime status inspects descendants and signals identity-proven orphans, reporting unsafe legacy records rather than guessing ownership.
  • tama assignment show, the Stop guard and the build gate read the open defects through the register's own filter (oko defects list --open --json) instead of the whole register with every closed and withdrawn record. The reading's registers are each one call for open items only; the real test tests/assignment/show_registers.rs runs both forms against the machine's Oko, checks the open-defects section against the register and records each form's wall time with the source revision.
  • block-keyword-literals and tama vocabulary report read the regex literals of JavaScript and TypeScript files. Only quoted literals were read, so /Try again|Retry/i.test(text) passed while 'Try again|Retry' was refused, and the report's count stood still as quoted lists were removed while every such regex classifier stayed. A / is read as a regex where an operand is expected, and after a name only when a method call follows the literal (return /a|b/.test(x)); a division, a URL in a comment and slashes inside a string are not regex literals. The real test tests/keyword-regex-literals/regex_literals.rs drives the built hook and the report.
  • block-keyword-literals refuses a vocabulary written as a comparison, which it let through before: a chain of == against two or more quoted words on one line (word == "okay" || word == "sure", kind === 'task' || kind === 'detail') and the arms of a matches! or match pattern joined with |. Each is the same classifier as a list, spelled without brackets. A comparison with one word, an argument list handed to a process in any language and a command line bound to a name still pass. The real test tests/keyword-literals/argument_vectors.rs reads the built hook's decision document for every shape; its refusal assertions had read the exit status, which a refusal never changes, so they could not have passed.
  • block-keyword-literals reads the name arrays of a Cargo.toml as Cargo's own declaration: a dependency's features, a workspace's members, default-members and exclude, and a package's include, keywords and categories. A manifest whose dependency enabled two features was refused as "a data list of N words" on every edit, whatever the edit changed, so no test or dependency could be added to it. The same arrays in any other file are still judged.
  • Cargo's [features] table also passes the keyword gate: default and arbitrary named features declare Cargo feature dependencies, not classifiers. A following metadata table is checked again, and a filename merely ending in Cargo.toml is not treated as the Cargo manifest. The registered keyword_literals_cargo_manifest journey covers these boundaries with the built hook. Qualification requires TAMA_TEST_SOURCE_REVISION, a matching clean tracked candidate and retained binary identity; malformed decision documents cannot count as permission. Run cargo test -p tama-cli --test keyword_literals_cargo_manifest only within an authorized qualification run with that declared candidate. Committed journey source alone is not a passing result.
  • block-keyword-literals reads each step of a Stado catalog recipe's after_install as the command it is. stado/catalog/products.yml declares Tama's own install step as - [tama, hooks, release], and the guard refused every edit anywhere in that file as "a data list of 3 words", so no product's catalog record could be changed. A step list holding anything but sequences of strings is still judged.
  • block-numeric-literals reads a Cargo.toml's edition, rust-version and license values as the names they are. A new Rust package could not be written at all: edition = "2021" was refused as the number 2021 and license = "BSD-3-Clause" as the number 3, and a manifest without an edition builds as Rust 2015. The same keys in any other file are still read.
  • block-keyword-literals no longer reads punctuation inside a string as code when it decides whether a word list is a call's argument. A list of a game's moves handed to a call was refused as a kept vocabulary whenever the description string beside it held a semicolon, and passed once the arguments were reordered.
  • An open OMP session takes a newer Tama adapter without restarting. OMP imports an extension once per process, so every session kept the adapter it started with after a Tama install, and a gate added since never ran in it. omp-shared-hooks.js is now a shell that imports the adapter from shared-hooks/omp/adapter.js; tama_reload_hook_runtime loads the installed adapter in place when it changed, and keeps the loaded one, naming why, when the new one fails. A session started before this release needs one OMP restart to get the shell.
  • A turn no longer ends unchecked because its Stop hooks were slow together. The engine ran every Stop hook one after another, so their times added up past the budget OMP gives a session_stop handler, and OMP then ended the turn as if no hook had refused. The Stop hooks now run side by side; checking an ending takes as long as its slowest hook, and the refusal text and result records keep registry order.
  • A model request the text gate forces to call a tool is no longer refused by Anthropic. OMP asks Anthropic to clear old thinking (a clear_thinking_20251015 context edit) whenever thinking is on, and Anthropic answers that edit with HTTP 400 once thinking is dropped (clear_thinking_20251015 strategy requires thinking to be enabled), so every forced request would have failed instead of calling a tool. The OMP adapter now drops that edit with the thinking and keeps every other context edit.
  • Agent text no longer reaches the operator while Oko holds open work. block-text-outside-tool-calls refused text only on Stop, after OMP had streamed and shown it; it now also runs before every model request, and the OMP adapter answers its refusal by requiring the request to call a tool (tool_choice any for Anthropic, with extended thinking dropped, or required for OpenAI), so no prose is generated. A request whose tools cannot be required is sent unchanged with a line on standard error and keeps the Stop refusal.
  • block-stop-with-open-work no longer resends its whole open-work list on every Stop. When OMP's last stop continuation in the session already carries the same refusal and the operator wrote nothing since, the gate holds the turn with one line naming the next item to take; an operator message, or open work that changed, brings the full text back. One session received the same list about four hundred times, each a full turn with the whole list as input.
  • block-numeric-literals reads a release version that is a whole path segment of an address as an identifier, as it reads a quoted version: a formatter's $schema (https://biomejs.dev/schemas/<version>/schema.json) or a package's release page cited in a comment was refused, so Weles could not pin a formatter at all. A segment with fewer than two decimal points (/api/2.5/) is still a number and is still refused.
  • block-numeric-literals reads .cjs, .cts and .mts files as code. They were scanned as data, so a number in a comment, a string or a regular expression's backreference of a CommonJS module was refused and a comment citing a constant's source was never read; a bare constant in them is still refused with its line.
  • Installing or reloading a Tama release no longer drops the consent the operator gave in the conversation. The OMP adapter bound a session's capability to the release it was recorded under and nulled it on every reload, so a build, test or hook-edit grant vanished at each stado product install tama and the next build was refused as if he had never agreed. The adapter now rebinds the grant to the release it loads, on reload and when a session resumes, with its lifetime and expiry unchanged.
  • Every Oko call reads the one task-ledger group oko tasks and passes --json where it parses the answer; refusal texts and routes name oko tasks … instead of oko transcripts tasks …. Install Oko with this release: an older Oko does not answer oko tasks --open … --json.
  • Completion enforcement now reads Oko's authoritative task ledger using the native OMP session identity. It preserves every executable open request and consumes independent saved verdicts rather than allowing a second Tama model to overrule them. Activation names ledger availability and pending work separately; unavailable evidence fails closed.
  • Real OMP completion journeys retain actual Brama exchanges, tool results, source identities and persisted task verdicts. They cover real delivery, refusal beyond the host's advisory continuation cap and explicit interruption. The host fix is a separate OMP dependency, not implied by installing hooks.
  • OMP session records and overrides now use the documented v2 agentId identity, allowing the desktop to discover live sessions and exchange validated controls; a legacy-only v1 state now produces an actionable runtime-reinstall diagnostic instead of an unexplained empty session list.
  • Session-discovery failures remain visible instead of being represented as an empty successful result.
  • Optional violation tooling no longer depends on a hard-coded maintainer directory.
  • Nonzero cleanup-agent exits cannot be reported as successful cleanup even when partial edits remove the final violation.
  • Hook registration now rejects invalid timeout and registry-path arguments before mutation, reports registry-load, registry-I/O, or mutator-launch failures without an unhandled stack trace, preserves registry permissions across atomic replacement, and retains the primary error if temporary-file cleanup also fails.
  • Session control now labels hook-registry load failures explicitly and displays the runtime diagnostic instead of allowing a scheduled or required reload label to hide the error.
  • Runtime prerequisites now consistently distinguish local Node.js execution, Python-based installation/restoration, and macOS backend approval across README, onboarding, core, and integration contracts.
  • Build, CLI, and runtime installation now reject unsupported Node.js versions; installation validates Node before managed writes, canonicalizes its executable through symlinks, pins that path into installed hook commands and the supervisor launcher, preloads a sealed version guard before every installed target and supervised semantic dispatch, records path and validated version in release provenance, exposes them in Overview, and POSIX-quotes generated shell paths without expansion.
  • Release packaging and publication now reject signed v tags that are not strict Semantic Versioning, including leading-zero numeric identifiers; publication also verifies the sidecar against the artifact digest, byte size, signed embedded build/hook identities, source revision, dependency pins, channel, and canonical examples before upload.
  • Release packaging and publication rejection paths now return failure statuses instead of allowing automation to mistake a printed diagnostic for success.
  • Prerelease and build metadata remain in Tama's exact embedded product identity while Apple bundle versions use the required numeric SemVer core; packaging and publication reject drift across the app, Network Extension, tag, manifest, or component build number.
  • Channel promotion no longer implies relabeling prerelease bytes as stable: an exact preview remains preview, while a stable SemVer is a distinct signed candidate that must be qualified before one-time publication.
  • Packaging and publication accept an explicit TAMA_RELEASE_TAG to select one signed release identity when preview and stable candidates share a source commit, reject ambiguous implicit discovery, and reject a selected tag that does not resolve to HEAD.
  • Publication rejects duplicate ZIP member names, absolute or parent-traversing member paths, and any archive root other than Tama.app or optional __MACOSX resource-fork metadata before upload.
  • Packaging and publication both require the app to pass signature, stapled-ticket, and Gatekeeper assessment; publication repeats those checks from the exact zip before upload.
  • Publication now requires an immutable qualification sidecar bound to the exact candidate, complete coverage of each canonical example and required suite kind, repeated identity and cleanup evidence, passed/redacted records, and an asset link injected into release notes.
  • Publication requires exactly one matching release-notes section and rejects missing, duplicate, reordered, or empty canonical categories before creating the immutable GitHub release.
  • GitHub publication now requires the repository immutable-release policy, creates and retains one stable GitHub release ID, verifies the exact remote signed-tag object, stages exactly the four canonical assets in a private draft, rejects missing or foreign asset names, validates ID, title, tag, notes, draft state, and preview/stable classification, downloads and compares every uploaded byte, rechecks policy immediately before publishing that exact ID with an explicit stable-only latest decision, confirms the published metadata and immutable state, redownloads and rechecks the locked asset set, reports the stable ID after failure, and never automatically deletes a GitHub release where draft state cannot be an atomic deletion precondition.
  • Remote asset verification now paginates the retained release ID's complete asset collection and downloads every canonical byte stream by its unique release asset ID before and after publication.
  • Canonical assets are now uploaded through URLs bound directly to the release ID returned by draft creation; upload and verification no longer resolve a mutable release tag.
  • Release publication now classifies preview versus stable from the SemVer prerelease component only, so hyphens inside build metadata cannot suppress a stable release or mark it prerelease.
  • App builds now read valid Keychain signing identities once and require an exact certificate-name or case-insensitive hash match, while also rejecting unsupported channel or code-signing timestamp modes and missing app or Network Filter provisioning-profile files before compilation. Build output and optional installation are assembled and signature-checked in private staging directories, then promoted with sibling backups and rollback instead of deleting the previous bundles before fallible work completes.
  • Violations command output is retained within explicit bounds and output-limit failures remain visible.
  • Cleanup rejects changed HEAD, checked-out branch, or local branch refs and states the remaining external-provider verification boundary.
  • Backend status exposes partial installation, and deactivation attempts every privileged component while preserving aggregate failure and restart-required recovery.
  • Backend unavailability is reported as a full-width panel carrying the backend's literal sentence and a reproducing command, rather than a dismissable alert or a swallowed read; the catalog, session control, provider coverage, install plan and repository scan each name their own command.
  • The session capability document was decoded from every session record and displayed nowhere.
  • A privileged backend that is merely not registered, a provider with no declared mapping, and a justification whose evidence is incomplete are no longer coloured as failures.
  • A refresh that fails keeps the previous read on screen instead of replacing it with an empty state.

Removed or deprecated

  • Automatic service registration on application launch.
  • Automatic session-controller installation on application launch.
  • Supported-runtime dependence on ~/Documents/CodingProjects/Wisent/tama.

Security

  • Policy-changing setup is moved behind explicit user intent.
  • Read-only catalog inspection remains available during Wisent Auth outages without exposing control actions.
  • Distributed builds ignore development hook-root and Node executable overrides; unauthenticated inspection does not load local justification or policy state.
  • Release artifacts record source provenance and carry independent SHA-256 verification.

Configuration

  • Developer-only source overrides remain unsupported for binary releases.
  • Writable cleanup state is kept outside immutable release bytes.

Data or state migrations

  • Installed hook-release state and existing v2 session records remain readable. Legacy v1 session-control records and overrides are deliberately ignored because they lack the v2 agentId identity contract; reinstall the bundled runtime, then stop or resume affected sessions so the supervisor publishes fresh v2 records.
  • The former tama.hasSeenWelcome and tama.hasSeenTrustScreen preferences are no longer read. Existing installations retain only independent tama.hasCompletedSetup state without changing installed policy.

Compatibility requirements

  • Apple-silicon macOS 14 or newer.
  • Python 3 and Node.js 20 or newer for installed runtime and violations workflows.

Operator actions

  • Review setup permissions and explicitly install/register components after upgrading.
  • Confirm product build identity and loaded hook release before resuming supervised sessions.

Known limitations

  • No supported preview artifact has been published yet.
  • Intel macOS, Linux, and Windows have no supported policy backend.

Qualification evidence

  • Packaging intentionally creates no qualification claim. Publication augments this source-level notice with a link to the completed immutable qualification sidecar for the exact candidate.
