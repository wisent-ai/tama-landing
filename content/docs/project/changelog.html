0.2.0 — Unreleased

Added

  • block-numeric-literals refuses an edit of an existing file for the literals the edit adds, as numeric values describes, instead of for every literal the file holds: an edit that adds no number to a file holding one passes, and a literal the edit writes, a second copy of a held one included, is refused. A literal is named on the line it stands on in the source; counted in the text with strings and comments blanked, the line drifted after every multi-line comment or string and named a line the literal is not on. See whole-file judging; real journeys tests/numeric-literals/existing_file.rs and tests/numeric-literals/replay/patch.rs.
  • block-fallbacks recognises a fallback in the file's syntax tree, in every language it judges, instead of matching lines of text: each construct is a tree-sitter query in constructs.json, declared once per language family with the grammar each file extension is parsed by (Rust, JavaScript, TypeScript and TSX, Python, Swift, shell). It now also refuses what drops the error that says why a value failed — Rust .ok(), Result::ok, map_or and an Err(_) arm; a JavaScript or TypeScript catch that binds no error, is empty or answers a literal, and .catch(() => literal); a Python except that only passes or continues or returns a literal, getattr with a default and suppress; an empty Swift catch; shell || true — and a construct named in a string or a comment is no longer refused. The refusal quotes the operator's rule; a file whose grammar or construct cannot be read is refused with that cause. tama violations find --fallbacks (and the Desktop's Fallbacks and dropped errors pass) lists every fallback each repository still holds, per repository. See no fallbacks; real journeys tests/fallbacks/languages.rs and tests/violations/fallbacks.rs.
  • The standing-rules block writes one instruction said in reworded variants once. The operator repeats a rule when a session forgets it, each later saying inserting words into the earlier one's sentences, and the block after every compaction carried every variant in full, about a third of a fresh context. A text every word of which stands, in order, in a fuller text is one rule with it: the fullest text is written once, under its newest message, with said N times since <time> counting every variant, and a ruling whose words a standing rule carries is listed as words a standing rule above carries in full instead of copied. No word of any variant is cut. See enforcement control; real journey tests/operator-rules/carried.rs against a ledger fixture.
  • block-crowded-folders judges every file a hashline edit names. A script editing two existing files in one call reached the gate as the call's own path, which the harness fills with the session folder when the script names its files itself, and was refused as a new file in that folder; the gate now reads the script's section headers and judges each file on its own, an apply_patch envelope by the files it leaves, a plain write by its one path, and refuses a section creating a file in a crowded folder naming that folder. See hook management; real journey tests/crowded-folders/hashline.rs.
  • block-keyword-literals tells a data document's references to itself from a vocabulary by the document, not by a key name: a list in a JSON or TOML file whose every word is a key the same document declares passes, and a list naming anything else is judged. A Cargo [features] table passed whole and a JSON Schema's required passed only beside its own properties, so each new misfire was answered with one more exempt key; now default = ['signal', 'process'] passes when the manifest declares both features, and default = ['accepted', 'rejected'] naming nothing it declares is refused. Cargo's array keys (a dependency's features, members, include, keywords and the rest) stay as Cargo's manifest schema. Real journey tests/keyword-literals/cargo_manifest.rs.
  • The open-work completion refusal counts instead of copying. block-stop-with-open-work and check-open-items-with-model say how many open tasks and defects Oko holds and how many carry no pushed repair, list only the session's own tasks and the defects Oko records it as owning, name the one item to take now and the commands that print the rest (oko tasks owed, oko defects list --unrepaired, oko defects list --open --owner SESSION_ID); the operator's answers to excuses are no longer appended, since they stand in the session's context from its start and every compaction. A session's own plan is refused with its count and first item. tama assignment show prints the defect counts and the session's owned defects instead of every open defect with its plan, and no longer repeats the standing rules. The standing-rules block writes one line per ruling message with every subject it decides, and a ruling in a standing rule's words points at that rule instead of copying it. Each refused turn had carried the whole register, and the session read it again on every later call. See finishing work and assignment show; real journeys tests/completion/summary.rs, tests/stop-gate/repeat.rs and tests/assignment/show_registers.rs.
  • The build gate reads the operator's standing build consent through one reader before it opens any dialog: a ruling Oko records on build or build:<product> admits the build without asking the session window, and tama attestation list --kind build lists those standing consents (store oko rulings, lifetime until withdrawn). Swift package builds (swift build|test|run, stado product swift) are named by their checkout. A consent given in a conversation for SSH, a local browser or a hook edit stays a session capability. See finishing work; real journey tests/build-gate/standing.rs.
  • A release install names Tama an announcer in Oko (oko asks announcers add tama), so the grant window's announcement through oko asks ask is recorded and delivered on its own and the grant is applied as soon as the window answers, never held on Oko's channels. installed.json carries okoAnnouncer: named, or the command and its cause, also on stderr; a machine without Oko keeps the install. See hook releases; the native install journey tests/harnesses/install.rs checks the field.
  • block-identity-literals reads each source once per written file: the values no cheaper source carries are looked up in the stored sessions in one walk that reads each transcript's index once and ends when every value has two sessions, a path outside any checkout is not searched, and a git grep that cannot start, ends on a signal or writes an error is named, with git's own error, in every refusal of the written file instead of read as no match. An artifact folder or file it cannot read is named on stderr. See identity provenance; real journeys tests/identity-literals/tracked_ids.rs and tests/identity-literals/mentions.rs.
  • Every registry path the gates read has one definition: the hook folder is named once, and the file, CUA and SSH justification registries are defined by the gate that reads each (the variable that moves a registry included). tama justify, tama attestation, require-new-file-justification (whose refusal names the registry it read), the frustration detector and check-numeric-literals resolve through them. check-numeric-literals recognizes the SSH grant registry by the SSH gate's own path, so a registry moved by TAMA_SSH_JUSTIFICATION is read as grant text and a file of the same name elsewhere is judged as configuration, and takes grant text out by its shape (a string, or a list of strings) instead of a list of field names. Real journey tests/numeric-literals/consent.rs.
  • Every attestation is one record in one ledger. Session records, file, CUA and SSH justifications and test approvals are written by their verbs through one primitive into attestations/ledger.json under the Tama state root, each naming the registry the gate reads, which stays where the hook catalogue declares it as a view. tama attestation migrate (and attestation/migrate, the Desktop's Migrate) brings what the registries hold into the ledger, and a release install migrates on its own; list reads the ledger and refuses until it is written; verify names each record a registry and the ledger disagree on. See tama attestation.
  • The rules block inject-operator-rules puts in front of a session at its start and after every compaction writes each of the operator's sentences once. He rewords a standing rule by inserting words into some of its sentences, so one instruction stood in the block five times as standing rules and again as rulings, about 30,000 tokens re-sent after every compaction; now a variant or a ruling keeps only its sentences not yet written and says how many stand above. Sentences are compared whole, so a sentence that differs by one word (a nie included) is written and no order is merged into another. See tama assignment show; real journey tests/operator-rules/distinct.rs.
  • pre-bash refuses a shell command that hides what it says. A redirection into the null device by the shell's own syntax (>/dev/null, 2>/dev/null, &>/dev/null and the rest) is refused naming the construct; a filter that keeps only part of the producing command's output (first or last lines, a column range, a count instead of the lines) is the judge's new shape TRUNCATE, refused by what the command does and not by the filter's name. A failed or hung step read as quiet success when its errors went into the null device or its output was cut on the way. See shell commands; real journey tests/hidden-output/null_sink.rs.
  • pre-bash refuses a Git command that would discard another session's uncommitted work in the one shared checkout. git restore <path>, git reset --hard and git clean are read against the session's own transcript, which says which files it wrote; every other uncommitted change the tree holds (Git's own diff --name-only HEAD and untracked listing) is another session's or the operator's, and a command that would discard one is refused naming the files (BLOCKED: `git restore src/lib.rs` would discard uncommitted changes this session did not make in <checkout>: src/lib.rs. …). A restore or a reset --hard is judged against the tracked changes and untracked files under its paths, a clean against the untracked files alone, and git -C <dir> names the checkout judged. Discarding only one's own files and unstaging pass; a discard whose ownership cannot be read (no readable transcript, a checkout Git cannot list) is refused naming the cause. See shell commands; real journey tests/shared-checkout/discard.rs.
  • pre-bash refuses a commit in the one shared checkout that would take changes this session never wrote. Git commits the whole index, so git add <own file> && git commit committed whatever another session had staged under this session's message, and unfinished or unformatted work landed on main. What the commit would take (the index, the named paths, the index and the paths with --include, every tracked change with -a) is read against the files the session's transcript shows it wrote, and each other path is named; git commit -m <message> -- <your paths> commits one's own work. The discard guard's and the repository-copies runbook's advice now name that pathspec commit. See shell commands; real journey tests/shared-checkout/commit.rs.
  • Brama's fleet route is read first from the adapter this machine's resolver publishes as listening for Tama's consumer (~/.stado/resolver-state.json, or STADO_RESOLVER_STATE_FILE), and only then from a stado service directory connect child: a child that stood for hours on a channel the object API never answered held every hook judge on the machine behind it while the published adapter was listening all along. The state counts only while the process that published it still runs (ps -p): the file outlives the resolver that wrote it. An adapter published as not listening, or by a process that is gone, is not a route; the search goes on to Stado as before. See model provider; real journey tests/brama-route/published.rs.
  • A fourth managed Git dispatcher, reference-transaction, runs tama hook review-ref-move on every move of a local branch. A rewrite or reset (git rebase, filter-branch, commit --amend, reset --hard) is read from Git's own old and new tips; every unpushed commit it drops is looked up in the defect register (oko defects naming <repository>@<commit>), and a commit an open defect records as its found-in or repair whose patch no commit under the new tip carries refuses the move before Git lets the history go (review-ref-move: BLOCKED: refs/heads/<branch>: the move drops <sha>, which the register names …). A rewrite that keeps every named patch passes, and once the refs have moved oko defects rebased --apply moves each entry to the new id. A recorded repair used to vanish from main silently when an unpushed history was rewritten, the register still naming an id no branch carried. A machine without Oko has no register to ask and says so. See tama install; real journey tests/review/ref_move.rs.
  • review-push and the turn-end stop gates check-stop-asking, block-false-blockers and block-stop-on-own-work ask no model: a pushed commit carries the commit standard's claims in its own message and an ending answer carries the claims each gate declares in standards/turn.json, read word for word, and a text that lacks one is refused naming every missing claim (review-push: BLOCKED: … commit <sha> carries no commit attestation in its message: / missing: "<claim>"). No key, Brama or other product is involved, so a push and a turn end are judged the same on a machine with nothing but Git and Tama. tama attestation standard --commit|--turn prints what to carry and tama attestation check --commit REV|--turn HOOK --file PATH gives the gate's verdict; Tama Desktop's Carried attestations section does the same through attestation/required and attestation/check. The recorded commit attestation (tama attestation record --commit), the pre-bash commit gate that read it, the push model review with its grounding and retained exchanges, and tama hook review-route are removed. See tama attestation; real journeys tests/review/attested.rs and tests/task-attestation/turn.rs.
  • block-unlinked-operator-messages is a stop gate that refuses the end of a turn while any operator message of the session is linked to no Oko record: it runs oko rulings unlinked --session <ID>, which names for each message the ruling recorded from it or the defect its task is related to, and relays Oko's refusal with the two commands that link an unlinked one. A correction the operator gives is open work in the registers from that turn on, not words he teaches again in the next session. No model decides it; a machine without the Oko CLI is left alone. See finishing work; real journey tests/operator-rules/unlinked.rs.
  • Tama's push gate and name gate run on a machine without Stado. tama hook quality-check, with no ~/.stado/bin/stado installed, reads the checkout's .wisent-release.json itself and runs each gate it declares for this platform in the checkout, the first that does not pass refusing the push by its name (quality-check: the declared gate <name> refused this push of <checkout> …); a checkout declaring none passes, a manifest that cannot be read refuses by its cause. block-internal-names says that the fleet registry and the vault listing are not here and judges this account's own names, instead of refusing every write because stado credentials ls cannot run; a Stado that is installed and cannot answer stays unread. The catalog declares Tama's dependency on Stado with this alternative, so stado product dependencies reads it. Real journeys tests/review/quality/declared.rs and tests/internal-names/without_stado.rs.
  • The open-work stop gate runs on a machine without Oko. With no Oko CLI installed, block-stop-with-open-work reads the session's own task-scope declaration (tama task scope set … --task | --defect, the entry require-task-scope makes it) as the register: a declaration that still names a task or a defect refuses the stop naming the entry and the operator's words (BLOCKED: this machine has no Oko CLI, and the session's own declaration still names open work: …) and the way out, tama task scope clear --session <ID>; a cleared declaration lets the stop through, and one that cannot be read refuses as an unreadable ledger. The catalog declares Tama's dependency on Oko with this alternative. See finishing work; real journey tests/stop-gate/without_oko.rs.
  • A judge request waits only while Brama keeps declaring it serves. While the hook's client waits on an accepted request, Tama asks Brama's readiness (GET /readyz) again on the same adapter, each answer pacing the next question; a Brama that stops declaring it serves, or an adapter that stops answering readiness, ends the client and the request is refused as the judge request to … was ended while it waited: Brama no longer declares it serves (…) with Brama's declaration. One request forwarded to a Brama that never answered held the resolver adapter for hours, and every later judge on the machine was refused behind it; no time limit is guessed. See adapters; real journey tests/hooks/readiness_watch.rs.
  • Every gate built on the write replay judges an apply_patch envelope and a notebook cell edit by the file they leave. The replay rebuilds each added and updated file of an envelope (*** Add File, *** Update File with its @@ hunks and *** Move to, *** Delete File leaving nothing) and a notebook as its cell edit leaves it (replace, insert after the named cell or at the head, delete, by cell_id or cell_number); a hunk the file does not hold, a cell the notebook lacks, a notebook that is not JSON or an unknown edit_mode refuses the write naming it, and nothing is judged by its fragment. Before, an envelope was refused as unreplayable and a notebook edit as having no supported operation. Real journeys tests/numeric-literals/replay/patch.rs and tests/numeric-literals/reconstruction.rs.
  • block-hidden-subcommands reads the hyphen clap derives without one being spelled: a variant of a Subcommand enum whose CamelCase name has more than one word and carries no name attribute (GpuPowerLimit, which clap serves as gpu-power-limit) is refused as clap subcommand whose CamelCase variant derives a hyphen-joined name (no name attribute) with its line. A dozen host-side verbs passed the gate this way while spelling none of their hyphens. A variant whose attribute names it, a one-word variant, an acronym and an enum that is not a Subcommand pass. Real journey tests/hidden-subcommands/refusal.rs.
  • block-unrepaired-negative-report is a stop gate for a session whose Oko role is supervisor: Brama's reviewer names every sentence of the ending answer that reports something broken, stopped, refused or missing and that no action of the turn answers, with the Oko defect it cites, and Oko's register (oko defects show <id> --json) decides whether that defect has a recorded repair or an owner. A sentence citing no such defect refuses the stop, quoted with its cause. See supervisor negative reports; real journey tests/supervisor-stop/negative_report.rs.
  • Tama's model calls no longer carry a request over a system-SSH forward to the host a stale registry copy names (~/.stado/cache/registry-last-good.json) when this host's Stado cannot answer. That route reached hosts outside Stado and answered from a copy of any age; a call is now refused naming the fleet route's and the relay's own causes.
  • The standing-rules block that inject-operator-rules and tama assignment show print gives each distinct rule text once, under the newest message carrying it, with said N times since <time> when the operator said it in several sessions. Malformed ledger reports carry their decoding cause instead of becoming an empty rules block or invented message provenance. The live-ledger journey tests/operator-rules/distinct.rs checks every distinct text and retains the source revision, working-tree diff, commands, exits and raw outputs; a ledger changed during the journey is reported as an inconclusive run.
  • OMP sessions receive the operator's standing rules after every compaction: the OMP adapter puts the context of the session_start:compact hooks (inject-operator-rules) into the session as a displayed message, or the reason the hooks refused or failed. Before, the adapter ran the hooks and dropped what they returned, so no OMP session got the rules back. A passing user_prompt_submit hook's context is delivered the same way.
  • tama hardcodes, its hardcodes/scan request and Tama Desktop's Hardcodes screen are removed. The command reported every number, address and name in a tree as one undifferentiated count, which is no operation on an object Tama owns and no step toward giving a value its source; a value that decides behaviour is refused where it is written, by block-numeric-literals and its citation rule.
  • tama sessions remind (--session ID | --default) [--text SENTENCE | --clear] sets the sentence the remind-open-work hook puts after every tool result: one session's own sentence always, the machine-wide one while Oko holds open work. The hook's sentence was compiled in; it now comes only from session-control/reminders.json, so set the machine-wide sentence with --default after installing this release.
  • Tama computes SHA-256 with the sha2 library everywhere; the two hand-written copies of the algorithm and their constant tables are gone.
  • The local build ration's builds a day, when the policy file does not set it, is the operator's stated number read from numeric-provenance.json instead of a constant. The adaptive telemetry corpus stores each hook payload whole: a payload over 65,536 UTF-16 units used to be stored as a cut JSON string that no candidate repair could replay. A Brama route named in TAMA_OBJECTIVE_AUTHORITY_MODEL_ROUTE is no longer refused for being over 160 characters; only whitespace makes it unusable, and whether Brama serves it is Brama's answer.
  • block-wait-polling refuses a shell call that blocks until the operator answers (oko asks wait, declared in block_wait_polling/operator_waits.json), with his rule that waiting for his decision is forbidden: an agent that ran one stood still for as long as he did not answer. The ask stays open and delivered; oko asks show reads its answer when it comes. Asking, reading and listing asks pass.
  • tama find-violations reads every file whole: a file over 524,288 bytes is no longer skipped as larger than 524288 bytes, and a file counts as binary when it holds a NUL byte anywhere rather than in its first 8,192 bytes. The rule-gaming check reads every changed file whatever its size.
  • Hooks decide with no number nobody stated. block-wait-polling refuses only a shell call that does nothing but pass time; the third identical hub look in two minutes is no longer counted. block-repeated-blocker accepts a blocker's still-blocks check made since the operator's latest message, read from the transcript, instead of within an hour. Session records carry liveness as the owner process, the heartbeat the launcher states in TAMA_SESSION_HEARTBEAT_TTL_SECONDS, or unknown with livenessError; the 900-second default and the 5–3600-second clamp are gone, and Tama Desktop shows the reason. block-internal-names reads a prose part as a sentence when plain words are most of its tokens, not at five words. Completion refusals name every open task and defect by identifier and quote none of their text, with no 140-character clip or 12-item cut. The session-start context carries every standing rule and ruling, with no 7,000/2,500-character split.
  • tama sessions revoke-capability --session ID withdraws the capability granted to one session — a build consent the operator takes back — at once instead of at its expiry: the override's capability becomes null, the build gate refuses the next build, and the running session reports "capability": null. Before, a capability could only be granted.
  • CUA consent recording, listing and removal through tama justify --kind cua, tama request and Justifications → CUA consent. Grants are taken from actual session user messages and validated against installed application metadata without manual protected-file edits.

Changed

  • The judge channel gate tells which waiting connection is a running hook's request by the connection, not by how many there are. It compared the count of judge requests running hooks recorded with the count of connections the resolver listed, so a running hook's own request the resolver did not list let a connection no hook watches through. Where the resolver records the client address of a held connection, Tama asks lsof which processes hold that loopback port, and the connection is a running hook's only when one of them is the client process that hook recorded; connections listed without a client address are still known only by count. Real journey: tests/hooks/judge_channel.rs (a_waiting_connection_is_known_by_its_client_not_counted).
  • A judge request a running hook owns no longer holds back every other hook's judge on the host. The channel gate refused a new request whenever the resolver listed any connection on the Brama adapter, so while one model answer was being written every other judged hook of every session answered review unavailable … another request is not sent while that channel is waiting, and judging ran one request at a time. A connection a running hook owns is watched against Brama's readiness and ended if Brama stops serving, so it is no longer a reason to refuse: the new request goes out after Brama's own /readyz. A waiting connection no running hook owns still refuses, with running Tama hooks own N request(s) (…); M of the connections is no running hook's request: … or no running Tama hook owns any of them. Real journey tests/hooks/judge_channel.rs.
  • A judge request's body travels on a file curl reads by path (~/.tama/judge-requests/, owned by the hook process and removed when the request ends), and the config document on curl's standard input keeps only the endpoint and headers. The body used to be one data-binary line of that document, and curl reads a config line only up to its own fixed length: a stop hook's prompt carrying the turn's transcript outgrew it, curl answered cannot read config from - (exit 26), and every judged hook reported review unavailable with nothing naming the line, indistinguishable from Brama's own refusals. A config document curl still refuses is named line by line, each by its option and length in bytes, with the body file and its size; the values, the bearer among them, are never printed. Real journey tests/judge-request/body.rs against the real Brama endpoint.
  • Every gate reads a tool call through one reader, tool_vocabulary::Call: the tool's name under tool_name, tool or name or nested as tool: {name, input}, compared without regard to case; its arguments under tool_input or input; the file under file_path, path or notebook_path; the shell line under command or cmd; and what a call runs (a shell line, an evaluation program, a started process). Each gate used to read the payload itself, and the ones written for Claude Code's spelling (Bash, Read, file_path) let the same OMP call through. The journey tests/payload-shapes/every_gate.rs runs every registered pre_tool_use gate on the same calls in both harnesses' shapes and requires the same decision. block-subagent-spawn no longer keeps a list of agent program names: a command handing a program a headless argument (-p, --prompt, exec, …) is read by a model, which answers whether it starts a coding agent; no judgement lets it through and says so.
  • block-overleaf-api judges a write by each file as the write leaves it — a hashline section, a string edit, an apply_patch envelope or a notebook cell edit replayed on the file, a written file's content — instead of by every string of the tool input: an Overleaf history call the file already holds is refused on its next edit, text being removed is not read as written, and the refusal names the file and the line of each match (matched: <reason> (line N: …)). A write the replay cannot rebuild — a file that does not exist, an edit whose old text is absent — is refused with the file this write leaves cannot be rebuilt to judge it: <cause>, never judged by its fragment. A call that names no tool is still judged by everything it carries. Real journey tests/boundaries/overleaf.rs (a_write_is_judged_by_the_file_it_leaves).
  • block-direct-lsi-api, check-raw-api-calls, block-openai-api-key and check-humanized-actions judge a write only by the file it leaves. Each used to fall back, when the replay could not rebuild the file, to the text a patch or a notebook cell writes — so a direct API call, a raw site call or a credential another cell of the notebook or the rest of the file already held passed the edit. Now a write whose file cannot be rebuilt is refused with the file this write leaves cannot be rebuilt to judge it: <cause>, the cause naming the file, and a notebook cell edit is judged by the notebook as the edit leaves it. Real journeys: tests/lsi-api/edits.rs, tests/raw-api-calls/edits.rs, tests/openai-api-key/writes.rs and tests/humanized-actions/edits.rs.
  • The pre-push dispatcher runs a product's declared quality gate through tama hook quality-check (stado quality check --if-declared in the checkout) and refuses in Stado's own terms. It used to print run stado quality format there, commit the result and push again whatever Stado refused, so a check that failed because a release input could not be read (Skarbiec unreachable) sent the pusher to reformat a tree whose formatting had passed. Now a formatting gate's refusal — the one Stado marks with `stado quality format` writes what it reads — prescribes stado quality format; any other refusal repeats Stado's failure line as quality-check: stado quality check refused this push of <checkout> at <failure_point> [<error_code>]: <detail>; this is not a formatting finding, so `stado quality format` changes nothing for it; repair that operation and push again; a refusal without a failure line says so. Everything Stado printed stays above the sentence. Real journey tests/quality-check/refusal.rs: an unformatted committed tree, a committed Cargo.lock that does not resolve its manifest, and a tree the check passes.
  • Every write gate names a refusal by its line in the whole file the write leaves (line N: …, numbered as an editor numbers lines), from one shared locator: check-legacy-activation-bypass, block-direct-lsi-api, block-openai-api-key, check-reward-hacking and block-unapproved-tests used to name only the file, or joined every file a patch leaves into one text; check-humanized-actions now shows its model each line with its number in the file. block-unapproved-tests exempts a test/ directory inside a Next.js app/ tree by that directory, not by a list of file stems. See Writes are judged by the whole file they leave. Real journey tests/hooks/whole_file.rs.
  • A judge request belongs to the hook process that sent it. One request Brama never answered held the resolver adapter, and every other hook's judge was refused with another request is not sent while that channel is waiting until the process that sent it was killed, with nothing saying whose request it was. Each judge request now records itself under ~/.tama/judge-channels/ while it waits; the refusal names the route, the hook process and its command line and the client process; a request whose hook ended has its client ended by the next judge, so the channel goes with its hook. Before sending, Tama asks Brama's own /readyz, and a Brama that declares it serves no traffic refuses the request with its declared reason instead of leaving it unanswered. See Adapters.   • tama adaptive install and tama adaptive uninstall, with the hidden adaptive-runner entry they wired: install replaced the dispatcher a release install writes with a shell shim, which the provider configurations run under node; uninstall put a backup back. The release install (tama hooks release) writes that dispatcher on every install and is the one way it changes.

Security

  • Policy-changing setup is moved behind explicit user intent.
  • Read-only catalog inspection remains available during Wisent Auth outages without exposing control actions.
  • Distributed builds ignore development hook-root and Node executable overrides; unauthenticated inspection does not load local justification or policy state.
  • Release artifacts record source provenance and carry independent SHA-256 verification.

Configuration

  • Developer-only source overrides remain unsupported for binary releases.
  • Writable cleanup state is kept outside immutable release bytes.

Data or state migrations

  • Installed hook-release state and existing v2 session records remain readable. Legacy v1 session-control records and overrides are deliberately ignored because they lack the v2 agentId identity contract; reinstall the bundled runtime, then stop or resume affected sessions so the supervisor publishes fresh v2 records.
  • The former tama.hasSeenWelcome and tama.hasSeenTrustScreen preferences are no longer read. Existing installations retain only independent tama.hasCompletedSetup state without changing installed policy.

Compatibility requirements

  • Apple-silicon macOS 14 or newer.
  • Python 3 and Node.js 20 or newer for installed runtime and violations workflows.

Operator actions

  • Review setup permissions and explicitly install/register components after upgrading.
  • Confirm product build identity and loaded hook release before resuming supervised sessions.

Known limitations

  • No supported preview artifact has been published yet.
  • Intel macOS, Linux, and Windows have no supported policy backend.
