0.2.0 — Unreleased

Added

  • block-inline-execution reads a shell line's structure before any model: every program the line starts, through wrappers, command substitutions and the lines shells are handed, is checked against the interpreters its declaration names with the grammar each manual gives (interpreters: source, program and value options, source subcommands) and against the shells /etc/shells declares. A program handed its source through a source option (python3 -c, node -e, perl -ne), a source subcommand (deno eval) or a process substitution, or one that names no program file and reads its program from a here-document, a here-string or a pipe, is refused without a model; python3 -m json.tool, a script file and bash -c '…' go on to the model reading. On a machine that declares no model the shell half used to pass every inline program.
  • block-internal-names and tama violations find --internal-names read what an installation declares its own from the shared-hooks/internal-names.json of every imported policy bundle: names refused anywhere, rulingRegisters whose ruling ids are refused anywhere and whose runs of quoteWords consecutive words of the operator are refused as his quotes, and instanceRepositories, whose checkouts are not judged because that is where the instance's decisions belong. Tama compiles in no installation's names; tama policy remove takes them away with the bundle. The commit message review reads the same declaration.
  • block-ask-without-refusal, a Stop gate declared and not selected (tama enforcement add block-ask-without-refusal turns it on): an answer that hands the operator a command to run, a fenced line whose program this machine runs and that no shell call of the turn ran or a code span running tama justify record, is refused unless a tool result since his newest message is the refusal of a hook the installed registry owns. A session whose transcript names a parentSession answers its supervisor and is not judged. No model and no word list: the reading is the answer's structure, PATH and the registry's hook ids.
  • block-build-before-docs, a gate on the tools that write files, declared and not selected (tama enforcement add block-build-before-docs turns it on): a change to a file of a checkout whose .wisent-release.json declares a product is refused until the session's own transcript, every turn of it, holds a look at that product's documentation (an address whose host's first label is the product and whose path starts with /docs, or a path below a docs folder of a checkout named for it) and a run of a program named as the product. A product with no program on PATH needs only its documentation.
  • block-stop-with-uncovered-correction, a Stop gate declared and not selected (tama enforcement add block-stop-with-uncovered-correction turns it on): a turn may not end while an operator correction of the session is not repaired as a class. It reads Oko, not what the agent recorded: oko requirements coverage --session S --json names the defect Oko's transcript reader recorded for each of his corrections, and oko defects list --without-class-coverage --json names each defect that lacks its class, its sweep across every product or its prevention shown active, with the step and command for each. It also refuses while the reader has not read the session or one of its operator messages, naming oko requirements read --session S. A message the reader holds back because no model answered, a correction with no defect yet, and an Oko that is absent or cannot be read refuse nothing and are said on stderr. No model.
  • Two gates, declared and not selected, each admitting one exact call on the operator's recorded words: block-operator-rule-files (--kind rule-file) refuses a file tool, shell line or program that writes, edits, moves or deletes one of the operator's rule files, which ruleFiles in its declaration lists (the operator's rule files); block-keychain-dialogs (--kind keychain-dialog) refuses a shell command that puts a keychain or authentication dialog in front of the operator, decided from its program and arguments as security(1) and the signing tools' manuals state it, with signing allowed only from a keychain in a folder signingKeychains in its declaration lists (keychain dialogs). block-repository-copies also refuses git clone and gh repo clone of a repository the workspace already holds a checkout of, a task tool call with isolated: true (it is now bound to pre_tool_use:task), and a recursive copy of the workshop root, a folder above it, or a folder inside the workspace with a .git below; it reads every line a shell is handed (repository copies runbook).
  • Three gates, declared and not selected, each admitting one exact call on the operator's recorded words: block-osascript (--kind osascript) refuses running osascript from a shell, an evaluated program or a started process; block-consent-switches (--kind consent-switch) refuses an agent setting a variable Tama reads as the operator's consent or as turning its gates off (DEVICE_HOOK_EDIT_APPROVED and its kin, TAMA_CLEAN_DISABLED, AGENT_STRUCTURED_CAPABILITY, TAMA_DISABLED_HOOKS, TAMA_ONLY_HOOK_ID), so no session grants itself his consent; and block-unowned-failures (--kind unowned-failure), a Stop gate, refuses ending a turn while a Wisent product's call failed or hung since his newest message, has not succeeded since and no open defect binds it.   • block-text-outside-tool-calls names, in its refusal over open defects, the first open defect with no repair and no owner but the session, with the oko defects assign that takes it, and says waiting on a build, install, commit or review is no reason to stop or to ask for a build; its one-line repeat names the same command. Before a model request the OMP adapter forces a tool call on Anthropic models OMP declares able to take one (tool_choice any, thinking and clear_thinking edits removed); Claude Fable and Mythos 5, which refuse it, keep their request unchanged.

  • tama history rebase [--repository <path>] [--prefer upstream] [--json] writes the unpublished commits of a checkout's branch again on the current tip of its upstream. When others push to the same remote the unpublished commits stand on an older tip and the push is refused, and a rebase in a checkout where people still work could not run, since Git's own rebase needs a clean index and working tree.
