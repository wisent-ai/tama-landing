tama copies remove

Removes every repository copy under the roots you name, previewing the whole pass unless --apply is given, and refusing the entire pass before deleting anything when a selected copy carries work that exists nowhere else.

Invocation

tama copies remove [--root <PATH>]... [--except <PATH>]... [--only <PATH>]... [--apply] [--force] [--json]

Inputs and options

OptionMeaning
--root <PATH>Repeatable, and required at least once. Each value is a directory whose checkouts are walked. There is deliberately no default root
--except <PATH>Repeatable. The path of one copy to leave completely alone: neither removed, nor counted as removable, nor able to refuse the pass
--only <PATH>Repeatable. Narrows the pass to the copies it names and accepts each as removable even when it is the sole checkout of its repository here. Not combinable with --except
--applyPerforms the removal. Without it the command previews and mutates nothing
--forceProceeds past every refusal, including uncommitted changes and commits on no remote. Without it any of them refuses the whole pass
--jsonPrints the exact document below instead of the text report, in both preview and applied mode

What is proved before a directory is deleted

A copy goes by deleting its directory, so the pass asks git first, and each answer is a refusal with its own sentence:

<path> has uncommitted changes; commit them there, then run the pass again.
<path> holds commits that are on no remote; push them from there, then run the pass again.
<path> has no origin remote, so this pass cannot prove its history exists anywhere else.
<path> is the only checkout of its repository under the roots given, so it is not a copy of anything.
<path> owns linked worktrees; remove those first with 'tama worktrees remove --root <PATH> --apply'.

The pass is all-or-nothing: with any refusal outstanding an --apply removes none of the copies it selected, so Tama never deletes the first three and then discovers the fourth carries work. Immediately before each deletion the filesystem is checked again — the reads behind a document are minutes old by the time an operator types --apply — and a path that is a symlink, or that no longer lies under the roots given, is an operational failure rather than a deletion.

Sparing with --except, claiming with --only

--except is the operator's exclusion: an excepted copy is dropped from the pass before anything judges it, so a dirty copy cannot refuse a pass it is not part of. --only is the opposite move: it narrows the pass to the paths it names and answers the one question the pass cannot answer for itself — whether losing a directory that is the sole checkout of its repository here loses anything the operator wants. It answers nothing else: a claimed copy that is dirty, unpushed or without an origin is still refused.

They are two answers to the same question, so a command carrying both is a usage error, and a value of either that matches no copy the pass found is one too: a pass the operator believed narrowed must not quietly become a pass over everything.

Output document

Under --json, the list document plus four fields, with the same schema version:

{... list fields ...,"excepted":[String],"applied":Boolean,"removed":[String],"refused":[{"path":String,"reason":String}]}

excepted echoes what --except held back, so the document states what the pass deliberately left alone; those copies appear in neither removed nor refused, in a preview and in an applied pass alike. applied is true only for an --apply pass that was free of refusals. reason is one of the five keys named above, and the sentence beside it is the one the command prints. --force empties refused in both modes, because nothing blocks a forced pass.

The same document is served by POST /v1/copies/remove with body {"roots":[String],"except":[String],"only":[String],"apply":Boolean,"force":Boolean} on the loopback desktop backend (tama serve), where a body carrying both except and only is refused with 400. That route is what the Copies screen drives.

Refusal boundary

Passing no --root is a usage error, exit code two:

tama copies needs at least one --root; a machine-wide default would walk directories Tama does not own.

So is a value that names nothing this pass found:

tama copies does not know the copy <path>; --only takes the path of a copy this pass found.
tama copies does not know the copy <path>; --except takes the path of a copy this pass would otherwise remove.

A refused --apply exits one and prints every refusal to stderr; under --json it exits one with "applied":false and "removed":[]. A failed deletion is an operational failure, exit one. Otherwise the command exits zero: every preview does, and so does an applied pass that removed everything it selected, including the pass that found nothing to remove.
