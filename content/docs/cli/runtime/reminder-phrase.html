tama reminder-phrase

The operator's reminder phrases: his exact sentences, each bound to the Oko defect whose repair makes it no longer needed. The remind-open-work hook puts every applying phrase after each tool result, and the block-missing-reminder-phrase gate refuses a call whose window of the agent's own text since the previous tool result holds a missing phrase, with the phrases to repeat.

Invocation

tama reminder-phrase add --text <SENTENCE> [--defect <ID>] [--session <ID>] [--json]
tama reminder-phrase list [--json]
tama reminder-phrase remove --id <ID> [--json]

Adding

add takes the operator's exact sentence — it is repeated and demanded verbatim, case, white space and Polish diacritics aside — and binds it to the Oko defect named with --defect, which must be one Oko holds open (a full id or the short form Oko prints), so the entry stops applying by itself when Oko records that defect repaired. --session limits the phrase to that session; without it the phrase applies on the whole machine. The same sentence twice for one scope is refused rather than kept twice.

Every entry carries the authority it stands on. The operator's phrase names his words with --operator-quote (the sentence itself when none is named); a rule Oko generates for a recurring defect class is added with --by-oko --generated-by <WHAT GENERATED IT>, standing on its defect, so an Oko-added rule is told from the operator's own words at a glance and cannot be added without its defect. The sentence the older tama sessions remind kept in session-control/reminders.json is migrated into the list the first time it is read: one machine entry for the default sentence and one session entry per session's own.

list prints one row per entry: its id, its scope (machine or session <ID>), the defect it is bound to, its source (the operator's quote, or what generated an Oko rule), the sentence, and whether it applies now — applies, or repaired: no longer applies once Oko records its defect repaired. While Oko's open-defect register cannot be read, every entry applies and the row saying so names the cause. --json prints {"entries": [{"id", "sentence", "defect", "session", "source", "applies"}], "unread"}. remove --id takes one entry out; an id no entry holds is refused with exit 1.

State

The list lives in session-control/reminder-phrases.json, schema ai.wisent.tama.reminder-phrases.v1. Tama Desktop answers the same operations through tama request reminder-phrase/list|add|remove with the same refusals. See enforcement control for how the hook and the gate read it.
