tama rules

Reads proposed policy repairs, drafted rules, and unresolved corrections from Oko. It groups evidence across agent sessions without silently installing a hook.

Invocation

tama rules list [--json]
tama rules remove --id <id>
tama rules digest [--json]
tama rules dismiss --id <proposal-id>

Why a digest

The adaptive bridge queues one repair row per contested hook (see adaptive enforcement). The frustration drafter records runtime rules in ~/.shared-hooks/auto_rules.json. Oko records operator corrections and any cause the operator has named, with links to defects. digest reads all three through their owning interfaces and returns one proposal per hook, drafted rule or unresolved cause. It does not infer a cause from an unexplained correction or turn a lesson into an enforced rule. An answered correction is not open work.

Proposals

idkindaction
hook:<hook-id>repair: the operator contested this hook evidence timestama adaptive repair <hook-id> drafts and validates a candidate against the labeled cases
rule:<rule-id>drafted-rule: a rule the drafter recorded, with the quote it was drafted fromtama rules remove --id <rule-id>
cause:<defect-id-or-cause-digest>lesson: unresolved operator corrections grouped by linked defect, or by identical named cause when unlinkedoko frustration show <moment-id> inspects the source; repair the producing process separately

--json prints {"proposals": [...], "dismissed": N, "unreadable": [{"source", "error"}]}. A lesson carries sources with each Oko moment's id, session, operator quote and named cause, plus the first and last observation. For example, tama rules digest --json shows a single lesson when two unanswered moments link to the same defect; oko frustration show <moment-id> reads the underlying record. It does not create or approve a hook. When Oko cannot run or refuses its read, unreadable names oko-frustration and the failed operation. Other proposals remain visible. Reading adaptive evidence may take minutes on a large Transcript Lake.

Dismissing

dismiss hides one proposal until new evidence arrives. A hook dismissed at three contests returns at the fourth. A lesson dismissed now returns when Oko records a correction it had not seen, even if an earlier correction has since been answered. Older count-only decisions remain hidden until their evidence count grows. Decisions are kept in ~/.shared-hooks/rule_decisions.json. Which proposal the operator never sees again is his decision, so dismiss needs DEVICE_HOOK_EDIT_APPROVED=1 set outside the agent session; Tama Desktop sets it for the one request its own button sends.

A missing decisions file means no proposal has been dismissed. An unreadable, malformed or invalid rule_decisions.json is different: digest refuses to print proposals rather than reopening hidden decisions. The error names the path and failed read or parse operation. dismiss does not overwrite damaged state. The Desktop digest request returns HTTP 500 with the same error, and the Learned screen shows the refusal instead of an empty history.

Refusals

  • refusing to dismiss <id>: which proposal the operator never sees again is his decision. Set DEVICE_HOOK_EDIT_APPROVED=1 outside the agent session to dismiss it. — exit 2, nothing written.
  • no open proposal <id> is in the digest — exit 2; the id is not open (already dismissed, or never proposed).
  • refusing to remove <id>: it was drafted from something the operator really said… — remove of a rule whose quote is in a stored operator message, without the approval.

Desktop

The Learned screen runs tama request rules/digest and tama request rules/dismiss with {"id": "<proposal-id>"}, and shows the same document.
