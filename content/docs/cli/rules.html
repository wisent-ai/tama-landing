tama rules

Reads what Tama learned across every agent session and puts it in front of the operator as proposals: the rules the frustration drafter recorded, and one proposal per hook he kept contesting.

Invocation

tama rules list [--json]
tama rules remove --id <id>
tama rules digest [--json]
tama rules dismiss --id <proposal-id>

Why a digest

Two learners write where nobody reads. The adaptive bridge queues a repair proposal each time the operator contests a block (see adaptive enforcement), one closed telemetry row per contest, so tama adaptive queue lists the same hook once for every time it was contested, across every session. The frustration drafter records rules in ~/.shared-hooks/auto_rules.json. digest reads both and answers with one proposal per hook or rule: how many pieces of evidence, the first and the last, what the evidence says, and the command that acts on it.

Proposals

idkindaction
hook:<hook-id>repair: the operator contested this hook evidence timestama adaptive repair <hook-id> drafts and validates a candidate against the labeled cases
rule:<rule-id>drafted-rule: a rule the drafter recorded, with the quote it was drafted fromtama rules remove --id <rule-id>

--json prints {"proposals": [...], "dismissed": N, "unreadable": [{"source", "error"}]}. A source that cannot be read is named in unreadable with its error; the rest of the digest still answers. Reading the adaptive evidence walks the Transcript Lake, which takes minutes on a machine with a large lake.

Dismissing

dismiss hides one proposal until more evidence arrives than it had when it was dismissed: a hook dismissed at three contests returns at the fourth. Decisions are kept in ~/.shared-hooks/rule_decisions.json. Which proposal the operator never sees again is his decision, so dismiss needs DEVICE_HOOK_EDIT_APPROVED=1 set outside the agent session; Tama Desktop sets it for the one request its own button sends.

Refusals

  • refusing to dismiss <id>: which proposal the operator never sees again is his decision. Set DEVICE_HOOK_EDIT_APPROVED=1 outside the agent session to dismiss it. — exit 2, nothing written.
  • no open proposal <id> is in the digest — exit 2; the id is not open (already dismissed, or never proposed).
  • refusing to remove <id>: it was drafted from something the operator really said… — remove of a rule whose quote is in a stored operator message, without the approval.

Desktop

The Learned screen runs tama request rules/digest and tama request rules/dismiss with {"id": "<proposal-id>"}, and shows the same document.
