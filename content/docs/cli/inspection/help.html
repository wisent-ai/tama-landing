tama help

Prints the sealed public top-level command summary.

Invocation

tama help
tama --help
tama -h
tama

The named command, both flag forms, and an invocation with no command select the same help path. It takes no required input or public options.

Output and state

tama help, --help and -h write usage beginning tama <command> and the public command list to stdout, perform no product action, and exit 0.

Help for one command

tama <command> [<verb>…] --help
tama <command> [<verb>…] -h

--help or -h answers for the deepest command the words before the first option name: tama violations --help prints every violations line of the summary, tama violations find --help only the violations find lines, each headed by tama <the command>, to stdout, exit 0, and never run the command: tama show --help does not look up a hook, and tama install --help installs nothing. A verb written as one of a <a|b|c> choice in the summary is answered with its entry; words after the deepest command (a hook id, a path) are its arguments. The groups that write their own usage, one line per verb (hooks, adaptive, enforcement, worktrees, copies, tests), answer a verb with its own line of that usage, as tama hooks seal --help does. A verb neither lists answers with its group's lines.

Refusals and failures

The help path has no refusal of its own, and answers before any checkout is looked for. Every other command line is first dispatched: its first word chooses the command, then the Tama checkout the command reads is found (--root, the checkout the working directory is in, TAMA_ROOT, the installed release's record, then the tree the program was built in). A line that cannot be dispatched is refused with a cause of the failure catalogue cli.dispatch, which tama errors show cli.dispatch prints: on stderr tama: <what failed>: <why>; observed: <state>, then fix: <what fixes it>, then cause: <id>; `tama errors show cli.dispatch` lists every cause of this command; with --json anywhere on the line, one failure envelope on stdout with failure_point cli.dispatch, detail, remedy and context.cause. The words in braces are filled in with the values the refusal met. Retrying unchanged will not help any of them.

  • home-unset (config), exit 1: tama: locating per-user Tama state (the registry, the ledgers, the releases): HOME is not set, so per-user Tama state cannot be located; observed: HOME is {home} (unset or set to an empty value); fix: set HOME to your home directory and run the command again. Every command and hook is refused this way before it reads anything.
  • option-before-command, exit 2: tama: reading the command from `{word}`: `{word}` is an option, and an option comes after the command it belongs to; observed: no command precedes `{word}`; the commands tama has: {commands}; fix: write the command first, as `tama <command> {word}`; `tama help` prints every command with its usage
  • command-unknown, exit 2: tama: choosing the command `{word}`: tama has no command named `{word}`; observed: the commands tama has: {commands}; fix: run one of those commands; `tama help` prints each with its usage
  • root-value-missing, exit 2: tama: reading the checkout --root names: --root is the last word, so it names no checkout; observed: the command line ends at --root: tama {line}; fix: name the checkout after it, as `--root <checkout>`, or drop --root to read the checkout the working directory is in
  • working-directory-unreadable (not_found), exit 1: tama: finding the Tama checkout the working directory is in: the working directory cannot be read; observed: the system answers: <the system's cause>; fix: run the command from a directory that exists, or name the checkout with --root <checkout> or TAMA_ROOT
  • checkout-unexaminable (config), exit 1: tama: finding the Tama checkout to read: a path searched for shared-hooks/registry.json (a directory above the working directory, or the tree this program was built in) cannot be examined; observed: <the path> cannot be examined: <the system's cause>; fix: make that path examinable (the observed state names it and the system's cause), or name the checkout with --root <checkout> or TAMA_ROOT
  • checkout-missing (not_found), exit 1: tama: finding the Tama checkout to read: no --root was given, the working directory is in no Tama checkout, and nothing else names one; observed: TAMA_ROOT is unset, {record} records no checkout that holds a registry, and {built}, the tree this program was built in, holds none; fix: name the checkout with --root <checkout>, set TAMA_ROOT to it, or run the command inside it; a Tama checkout holds shared-hooks/registry.json
