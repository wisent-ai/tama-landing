tama errors

Prints every way a command fails, as the command declares it, and holds Tama's source to the error standard. Each declared cause states what failed, why, the state the refusal shows, what fixes it, its code, its exit status and the test that provokes it; the refusal a reader meets, this listing and the command's documentation page are written from that one declaration.

Invocation

tama errors list [--json | --markdown]
tama errors show <operation> [--json | --markdown]
tama errors check --source <dir>... [--json]

list prints one line per operation that declares a failure catalogue: its id, how many causes it declares, the command and its documentation page. Today these are cli.dispatch (dispatching any command line), cli.show (tama show) and cli.errors (this command). show <operation> prints each cause of one operation: its id, code and exit status, then failed:, cause:, observed:, fix: and test:. --json prints the catalogues as JSON, --markdown as documentation sections.

check is the gate. It refuses a catalogue that is not one (a cause with an empty field, a catch-all unknown code, a duplicate id, a test that is not tests/<area>/<file>::<name>), a cause whose test file declares no test function of that name, and a generic failure sentence ("did not succeed", "operation failed", "something went wrong" and the rest of wisent-errors' list) inside a string literal of a Rust, Swift, Go, JavaScript, TypeScript or Python file under each --source. Comments, tests, build output and installed dependencies are not read. Tama holds no such sentence, so there is no baseline: every one found is refused.

Output and state

The command reads only; it writes nothing. list and show exit 0. check exits 0 and prints <n> operation(s) declare <n> cause(s), each with its test; <n> source file(s) hold no generic sentence when nothing is refused.

Refusals and failures

Every refusal is a cause of the catalogue cli.errors, printed like every declared refusal: tama: <what failed>: <why>; observed: <state>, then fix: and cause: lines on stderr, or one failure envelope on stdout with --json. The words in braces are filled in with the values the refusal met. Retrying unchanged will not help any of them.

  • verb-unknown, exit 2: tama: choosing the `tama errors` verb `{verb}`: `tama errors` has no verb `{verb}`; observed: its verbs: list, show <operation>, check --source <dir>; fix: run `tama errors list` to see the operations, `tama errors show <operation>` for one, or `tama errors check --source <dir>` for the gate
  • verb-missing, exit 2: tama: choosing the `tama errors` verb: no verb was given, so `tama errors` does not know what to print or check; observed: the words after `errors`: {rest}; the same fix.
  • operation-missing, exit 2: tama: reading the operation `tama errors show` prints: `tama errors show` takes exactly one operation id; observed: the words after `show`: {rest}; fix: name one, as `tama errors show cli.show`; `tama errors list` prints every id
  • operation-unknown (not_found), exit 1: tama: looking up the failure catalogue of `{id}`: no operation `{id}` declares a failure catalogue; observed: the operations that do: {declared}; fix: name one of those exactly
  • source-missing, exit 2: tama: reading the source directories `tama errors check` scans: no --source <dir> was given; observed: the words after `check`: {rest}; fix: name each directory to scan, as `tama errors check --source rust/crates`
  • source-absent (not_found), exit 1: tama: scanning the source directory {path}: {path} does not exist; observed: <the system's cause>; fix: name a directory that exists; a relative path is read from the working directory
  • source-unreadable (config), exit 1: tama: scanning the source directory {path}: {path} exists but cannot be listed; observed: <the system's cause>; fix: make {path} a directory this user can list (the observed state names the system's cause), then run the check again
  • file-unreadable (config), exit 1: tama: reading the source file {path}: the file cannot be read as UTF-8 text; observed: <the system's cause>; fix: make {path} readable UTF-8 text, or move it out of the scanned directories if it is not source
  • standard-unmet, exit 1: tama: holding the source to the error standard: {count} problem(s) were found; observed: <each problem, as <path>:<line>: "<sentence>" <why a reader cannot act on it>: <the line>, or the catalogue problem>; fix: declare each generic message's cause and say what failed, the state observed and what fixes it; give every declared cause a test function in the file it names

Before tama errors runs, the command line itself can be refused; those refusals are listed on tama help.
