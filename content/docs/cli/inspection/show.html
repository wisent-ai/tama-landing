tama show

Looks up one hook by its exact catalog id and reports its source, command, description, rationale, and event bindings.

Invocation

tama show <hook-id> [--json] [--root <checkout>]

<hook-id> is required and must match a catalog hook id. --json prints the full structured hook entry; otherwise Tama prints human-readable fields and one blocking= line per event.

Output and state

The command writes one hook and does not modify the catalog, hook files, or runtime state. A successful lookup exits 0.

Refusals and failures

Every refusal is a cause of the failure catalogue cli.show, which tama errors show cli.show prints. On stderr it is three lines: tama: <what failed>: <why>; observed: <state>, then fix: <what fixes it>, then cause: <id>; `tama errors show cli.show` lists every cause of this command. With --json the refusal is one failure envelope on stdout instead: failure_point cli.show, error_code, retryable, detail (the first line), remedy (the fix) and context.cause (the id). The words in braces are filled in with the values the refusal met. A refusal of the command line's own form exits 2; every other exits 1, and retrying unchanged will not help.

  • hook-id-missing, exit 2: tama: reading the hook id `tama show` looks up: no hook id was given; observed: the words after `show`: {rest}; fix: name one, as `tama show <hook-id>`; `tama list` prints every hook id
  • argument-extra, exit 2: tama: reading the hook id `tama show` looks up: `tama show` looks up one hook, and more than one id was given; observed: the id `{id}`, then `{extra}`; fix: run `tama show` once per hook id
  • option-unknown, exit 2: tama: reading the options of `tama show`: `{word}` is not an option of `tama show`; observed: `tama show` takes --json and --root <checkout>; fix: drop `{word}`, or spell the option as one of those
  • registry-missing (not_found), exit 1: tama: reading the hook registry {registry}: the checkout {root} holds no shared-hooks/registry.json, so it declares no hook; observed: no file at {registry}; fix: name a Tama checkout with --root <checkout> or TAMA_ROOT; a Tama checkout holds shared-hooks/registry.json
  • registry-unreadable (config), exit 1: tama: reading the hook registry {registry}: the registry cannot be read; observed: reading {registry} answers: <the system's cause>; fix: make {registry} a readable file (the observed state names the system's cause), then run the command again
  • registry-not-json (config), exit 1: tama: reading the hook registry {registry}: the registry is not JSON; observed: {registry} is not JSON: <the parser's cause, line and column>; fix: repair {registry} at the line and column named (`git -C {root} diff shared-hooks/registry.json` shows a hand edit), then run `tama validate`
  • catalogue-invalid (config), exit 1: tama: building the hook catalogue from {registry}: the registry, shared-hooks/catalog-metadata.json or the hook source directories hold something the catalogue cannot be built from; observed: <the catalogue builder's sentence, such as "registry.json event PreToolUse does not say whether it blocks (no `blocking`)">; fix: correct the declaration or file the observed state names; `tama validate` reports every catalogue error at once
  • hook-unknown (not_found), exit 1: tama: looking up hook `{id}` in {registry}: the catalogue declares no hook with that id; observed: {count} hooks are declared; the ids nearest it: {nearest}; fix: pass one of the declared ids exactly; `tama list` prints every one

Before tama show runs, the command line itself can be refused; those refusals are listed on tama help.
