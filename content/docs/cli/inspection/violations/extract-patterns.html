tama extract-patterns

Moves a guard's pattern table out of its Rust source and into a JSON declaration beside it, keeping the comment above each entry as that entry's reason.

Invocation

tama extract-patterns --file <rust-file> --const <NAME> --into <json> [--as words] [--why <text>]

--file is the Rust source, --const the name of a const NAME: &[&str] = &[ … ]; table in it, and --into the JSON file to write. --as words writes the entries as one array of words instead of one object per pattern. --why sets the document's reason; without it the reason names the table and the file it came from.

Why it exists

Several guards carry a long table of regexes, each added the day an operator was let down by its absence and each with the comment saying which day and why. That table is a record, not logic: in Rust it cannot be read, sorted or audited, and every word in it reads as a keyword list to block-keyword-literals.

Output and state

Writes {"why": …, "patterns": [{"why": …, "pattern": …}]}, or {"why": …, "words": […]} with --as words, to --into, and prints NAME: N pattern(s) -> <json>. The source file is never modified: the guard is changed by hand to load the declaration.

Refusals and failures

Each exits 2 and writes nothing: a missing --file, --const or --into (the usage goes to stderr); cannot read <file>: <error>; NAME is not a `const NAME: &[&str] = &[` table; NAME carries an entry this command cannot read: <the first characters> for an entry that is not a string literal; and cannot write <json>: <error>. --help prints the command's lines of the summary and exits 0.
