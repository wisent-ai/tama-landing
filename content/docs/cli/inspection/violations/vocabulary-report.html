tama vocabulary report

Lists every keyword list still written into a repository's code or data files, grouped by the words themselves, so every copy of one list is removed in the same change.

Invocation

tama vocabulary report --repo <path> [--repo <path>...] [--json]

--repo names one checkout and may be repeated. --json selects the structured report.

Why it exists

violations find answers which files break a rule, one finding per file: the right shape for a gate and the wrong one for a repair. The same words live in several files, and fixing them one file at a time is how the copies drifted apart. This report reads exactly what block-keyword-literals refuses — lists in code and in data files, with no declaration hiding any of them — and groups every flagged run by its word set.

Output and state

Text output prints one block per word set: N site(s): "word", "word", … followed by each site as path:line, then a final vocabularies: V, sites: S. Sets written in the most places come first, then the widest sets. --json prints {vocabularies: [{words, sites, copies}], vocabularyCount, siteCount} in the same order. Nothing is written.

Refusals and failures

Without any --repo the usage is printed to stderr and the command exits 2. A file that cannot be read is left out of the report rather than refused. --help prints the command's lines of the summary and exits 0.
