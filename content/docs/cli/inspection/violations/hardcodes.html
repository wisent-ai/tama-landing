tama hardcodes

Reports every line of every git repository the roots you name hold that writes down a fleet host name, a vault item id, a number block-numeric-literals refuses, or a host with a port. It writes nothing.

Invocation

tama hardcodes --root <PATH>... [--origins] [--summary] [--json]

Inputs and options

OptionMeaning
--root <PATH>Required and repeatable. A root that is itself a git repository is that one repository; any other root stands for every git repository directly under it. The command does not guess a tree.
--originsAdds the commit that wrote each line and its subject. That is where the question "who decided this value" starts.
--summaryPrints only the count of each kind per repository.
--jsonPrints one document instead of the text report.

What counts as a finding

Host names come from Stado's registry (stado registry pull) and vault item ids from the credential store Stado selects (stado credentials ls --json), both read live. A name that is also the directory name of a repository beside a scanned one is a product's own name and is not reported; because the names are read from each scanned repository's parent directory, one repository scanned on its own is judged against the same product names as when its whole workspace is scanned. A number counts exactly when block-numeric-literals would refuse it, so a number declared in numeric-provenance.json with the operator's words is not reported.

An address is scheme://host:port, or an IP address or localhost followed by :port. In a code file it is read with the comments blanked and the strings kept: an address a program writes in a string or a default is reported, and one a comment cites as an example or an incident is not, because it decides nothing. A file in no known programming language is read whole.

Output

The text report starts with looked for <n> host names, <m> vault item ids, numbers and addresses. Each repository with findings prints <repo>: <count> <kind>, …, then one line per finding, <path>:<line> <kind> <value>, with [<commit> <subject>] appended under --origins, and skipped <path>: <reason> for a file it did not read. A repository it could not read prints unreadable: <repo> (<error>). The last line is <total> findings in <n> repositories: <count> <kind>, ….

--json prints {"vocabulary":{"hosts","vaultItems"},"repositories":[{"repo","counts","skipped","findings"}],"unreadable":[{"repo","error"}],"totals":{"repositories","findings","byKind"}}; --summary leaves out each repository's findings.

Exit status and refusals

Exits 0 when nothing is found, 1 when something is found or a source cannot be read, and 2 for a usage error. The usage errors print the sentence and then the usage:

tama hardcodes needs at least one --root; it does not guess which tree to read
--root needs a path
unknown argument "--bogus"

A root that is neither a git repository nor a directory holding one exits 1 with root <path> is not a git repository and holds none directly under it; name a repository or the directory that holds repositories, so a mistyped root never reads as a clean inventory. A root that cannot be read exits 1 with cannot read root <path>: <error>, and a host or vault vocabulary that cannot be read exits 1 with cannot read what counts as a name: <error>. --help or -h prints the usage and exits 0.

The same inventory is the Tama Desktop Hardcodes screen, through the request hardcodes/scan.
