tama declare-root

Declares a repository root to the audit when every file it holds is fixed there by somebody else's tooling, and refuses while anything movable is still in it.

Invocation

tama declare-root (--repo <path> | --tree <dir>) [...] [--apply] [--commit] [--push] [--json]

--repo names one checkout and --tree walks every Git checkout under a directory, so a workshop of two hundred repositories is one command. Without --apply the run is a report. --commit records what it wrote in the repository that received it, --push publishes that commit, and both also finish a declaration an earlier run left uncommitted in a working tree.

Why a root is different

The five-files-per-folder rule holds wherever a person decides the layout. A repository root is not such a place: npm reads package.json and package-lock.json there, cargo reads Cargo.toml and Cargo.lock there, SwiftPM reads Package.swift there, git reads .gitignore there, GitHub shows README.md and the licence from there, and the release tooling reads .wisent-release.json there. Six such files already exceed the limit and no arrangement of folders can help, so the audit's own answer is the . entry in .tama/violations-ignore. Writing that by hand once per repository is the one-off repair this workshop refuses; this command is its repeatable form.

What it refuses

A root that still holds a file a person could move into a folder is not declared, and the refusal names those files: they belong in a folder, not in a declaration. A root holding something nothing reads at all — .DS_Store, Thumbs.db, desktop.ini — is refused with a different sentence, because those are deleted rather than moved. Neither refusal writes anything, so the declaration can never launder ordinary clutter into an exemption.

What it writes

The entry is appended to .tama/violations-ignore, never replacing what a repository already declares, and it carries a comment naming every root file with the tool that fixes it there. A second run reports the root is already declared and changes nothing.

Output and state

Text mode prints one line per repository and ends with how many roots were declared; with a single target it also lists the files and their tools. JSON returns an array of reports with fixed, movable, junk, declared, reason and the commit revision when one was made. Exit 1 means at least one root was not declared; missing paths and unknown arguments print usage and exit 2.
