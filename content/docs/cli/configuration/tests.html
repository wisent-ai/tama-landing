tama tests

Records the operator's approval of test code. block-unapproved-tests refuses every write of test code outside an approval, so a test exists only where the operator asked for it.

Invocation

tama tests approve <path>…
tama tests revoke <path>…
tama tests list [--json]

A path names a file or a directory; an approved directory covers everything below it. A relative path is read against the current directory and stored absolute. approve prints approved <absolute path> per path, revoke prints revoked <absolute path>, and list prints each approval with the time it was granted, or {"approved": […]} under --json.

What counts as test code

A file under a tests/, test/ or __tests__/ directory; a file named x_test.go, x.test.ts, x.spec.ts, test_x.py, tests.rs or XTests.swift; and a change anywhere that carries Rust's test attribute or test-only gate, a Python test_ function or Swift Testing's @Test macro. The hook reads structure — a directory, a file-name convention, an attribute — not the words of a sentence.

Who approves

Only the operator. The record is ~/.config/agent-policy/approved_tests.json. block-unapproved-tests refuses tama tests approve run from an agent session, a write tool aimed at the record and a shell command that names it, so an agent cannot approve its own test. Tama Desktop's Tests screen makes the same change through tama request tests/approve and tests/revoke.

What the hook refuses

  • block-unapproved-tests: BLOCKED: <path> is test code the operator has not approved. … — a write, an edit or a shell redirection of test code outside every approval.
  • block-unapproved-tests: BLOCKED: `tama tests approve` records the operator's own approval and runs only in his terminal. … — the command run from a session.
  • block-unapproved-tests: BLOCKED: <record> is the operator's record of approved tests. … — a session write to the record.

Reading test code is never refused, and neither is removing a test file from the shell: a shell command is judged only by what it redirects into.

Refusals

approve and revoke with no path print tama tests: name at least one path and the usage and exit 2; a record that cannot be written prints tama tests: the approval record was not written: <path>: <error> and exits 1. An unknown subcommand prints the usage and exits 2.
