tama policy

Imports, lists and removes retained inactive policy bundles: hook policy trees validated and kept beside the runtime without being installed or enabled. Nothing here changes which hooks a machine runs; tama enforcement decides that.

Invocation

tama policy import --source <dir> [--replace] [--json] [--home <path>]
tama policy list [--json] [--home <path>]
tama policy remove --source <path|key> [--json] [--home <path>]

Inputs and options

OptionMeaning
--source <dir>import: required; the bundle directory to validate and keep. remove: required; the path or source key an imported bundle was recorded under
--replaceimport only. Overwrites a bundle already retained from the same source whose content differs; without it that case is a conflict and nothing is written
--home <path>The home whose policy store is read or written instead of this account's; the value must be a directory
--jsonPrints the result document instead of the text report

What import answers

One transaction validates the whole bundle and then writes it, or writes nothing. Its status is one of imported, replaced (an earlier bundle from the same source was overwritten under --replace), unchanged (the same content is already retained), conflict (a different bundle from the same source is retained and --replace was not given) or rejected (the bundle is not valid; the result names what is wrong). The desktop's Settings screen runs the same transaction. tama request policy-bundles/import answers the same document.

list prints one line per retained bundle — source path, source digest, hook count, file count, inactive — or No inactive policy bundles imported.; remove prints Removed the inactive policy bundle imported from <path>. or No imported policy bundle came from <source>; nothing changed., and under --json {"source":String,"removed":Boolean}.

Reservations a bundle declares

Tama reserves nothing itself. What one installation keeps out of agents' hands — another owner's checkout, files only the operator edits, a command only he runs — is that installation's policy, declared in the shared-hooks/reserved.json of a bundle it imports. The installed block-reserved-changes gate reads that file from every imported bundle from the moment of import, and remove takes the reservations away with the bundle; the import itself still installs and enables no hook.

{
  "reserved": [
    {
      "subject": "example-model",
      "why": "the model and its inputs are edited only when the operator asks",
      "said": "the operator's own sentence, copied from the conversation",
      "directories": ["example-model"],
      "files": ["assumptions.json"],
      "repositories": ["example-grant-repository"],
      "newFileWords": ["notes"],
      "commands": [["example-cli", "workbook", "build"]],
      "commandsOnlyInside": false
    }
  ]
}

Every field is required. directories refuses a file written under a directory of that name; files a file of that name; repositories with newFileWords a new file in a checkout of that name whose name holds one of those words; commands a shell command that runs the program with those words in that order, only where it names or runs in a reserved directory when commandsOnlyInside is true. The refusal reads BLOCKED (block-reserved-changes): `<path or command>` is reserved (<subject>: <why>; the operator: "<said>"). Leave what is reserved as it is and do the work that was asked., followed by how the operator grants one exact change (tama justify record --kind reserved-change). A bundle whose reserved.json cannot be read is named on stderr (block-reserved-changes: <path> cannot be read: <cause>; this bundle's reservations are not held) and the other bundles' reservations still hold; a store that cannot be listed refuses nothing and says block-reserved-changes: the imported policy bundles cannot be listed: <cause>; nothing is refused.

A bundle that only declares reservations still carries the shared-hooks/registry.json the import validates: it registers block-reserved-changes on the events it configures (pre_tool_use:bash, edit, write, multiedit, notebook), each entry with "command": "$HOME/.local/bin/tama hook block-reserved-changes" and "source": "shared-hooks/reserved.json".

Exit status

import exits one on conflict or rejected and zero otherwise; list and remove exit zero, a removal of nothing included. A wrong invocation exits two:

policy import requires --source <dir>
--home requires a directory
unknown policy import option: <argument>
unknown policy list option: <argument>
tama policy remove needs --source <path or source key> of an imported bundle
usage: tama policy import --source <dir> [--replace] [--json] [--home <path>] | tama policy list [--json] [--home <path>] | tama policy remove --source <path|key> [--json] [--home <path>]

A store that cannot be read or written is reported with its path and cause and exits one.
