tama hooks

The halves of adding, changing or keeping a hook, each behind one verb. declare writes the repository documents — the catalogue entry, the registry binding, the reconciled sources and the seal; undeclare is its reverse. release builds the native hooks from published main, installs the ones that changed, and stages, seals and installs the live release this machine runs. warm runs each installed binary once so the operating system's first-execution assessment is paid outside a live event. The packaging verbs — stage, seal, source-identity, install-release, integrity, digest — are the release build's and the installer's own steps, exposed so a person can run and verify each one.

Invocation

tama hooks declare --file <declaration.json> [--dry-run]
tama hooks undeclare --file <declaration.json> [--dry-run]
tama hooks release [--dry-run] [--enforce <hook-id>,…]
tama hooks warm [--only <hook-id>,…] [--json]
tama hooks running [--json]
tama hooks stage --source-root <tree> --release-root <release> --cargo <cargo> [--codesign-identity <id>] [--codesign-timestamp <flag>]
tama hooks seal [--source-root <tree>] <release>
tama hooks source-identity --source-root <tree> [--shell]
tama hooks install-release --release <dir> --home <dir> [--emergency-manifest <file>] [--session-control-only]
tama hooks integrity [--release <dir>] [--home <dir>]
tama hooks digest <file-or-release>

Verbs

VerbEffect on stateDocumented in
declareWrites the catalogue entry, the registry binding and the reconciled sources for one declaration file, then reseals; --dry-run prints the plan and writes nothing. Requires DEVICE_HOOK_EDIT_APPROVED=1 in the operator's own shell; without it the command refuses before writing and prints the command for that shellhook management
undeclareThe reverse, in reverse order: each event the registry still binds to the hook is unbound, the catalogue entry is removed, the sources are reconciled and the release is resealed, then the declaration is removed. Same approval, same --dry-runhook management
releaseBuilds from origin/main, installs the one tama program and removes the separate programs an earlier release installed, warms every registry hook, installs the sealed release into the hook runtime, and records the checkout in ~/.tama/installed-from. Stado runs it as the install's after_install step. --enforce <hook-id>... adds those hooks to the machine's selection as tama enforcement add does, keeping every hook already selectedhook management, hook releases
warmRuns each installed binary once and prints the state, measured milliseconds, hook id and path per line — warm ran and exited, missing is a registry entry with no binary at that path — and the summary names the costliest. tama request hooks/warm answers the same reporthook warming
runningReads the records each session runtime keeps while it runs a hook — one in-flight.<core pid>.<hook pid>.json per running hook in the session-control directory (TAMA_SESSION_CONTROL_ROOT, else ~/Library/Application Support/Tama/session-control), written when the hook's process starts and removed when it ends — and prints per record the event, hook id, the session it runs for (? when the payload named none), how long it has run, the hook and core process ids, whether each is alive, and under it every process the hook started that still runs (waiting on pid <n>: <command line>, from ps), which names the call a stuck hook waits on: the vault, a gateway request, a fleet lookup; --json prints them as {root, running}, longest first, each with sessionId and waitingOn. A session runtime runs each tool call's hooks on their own thread, so a hook that does not end holds only the call that started it; this names that hook from any other terminal. A stop or user_prompt_submit hook still running when the same hook starts for the next such event of its session is ended by the runtime, so it does not stay listed. A record whose core is gone is reported as left behind, not as running. Exit 1 when the directory cannot be read, 2 on another argumenthook warming
stageBuilds, from the source tree, every native program the prepared release's registry runs plus the one tama program, and places them in the releasescripts
sealComputes the release's tree digest — every file except release.json and bin/, in sorted path order, each file's path, permission bits and bytes — and writes it as releaseId; refuses the whole release with External hook source is missing for the first external source it cannot openseal, hook releases
source-identityPrints the revision and dirtiness a release of that tree carries; --shell prints them as shell assignments. A missing Git revision reports the failed Git operation and checkout pathscripts
install-releaseInstalls a sealed release into a home as one transaction behind two integrity gates, rewriting the registry for that home; one JSON result on stdout on success, and on any failure one line on stderr — Tama hook release installation failed: <reason> — and exit onescripts, runbook
integrityReports, without writing, whether a release still digests to its seal (--release: recorded vs actual digest and every file written after the seal) and whether every installed tree digests to its directory name (--home, marking current). Without either it prints its usage line and exits twoscripts, runbook
digestPrints a directory's release digest or a file's SHA-256; artifact not found: <path> exits twoseal

Records a killed core leaves behind

A core removes a hook's running record when the hook ends and ends every run it holds when its input closes; a core the system kills does neither. tama hooks running then says which case a record is: core gone; hook still running with nobody waiting for it names an orphaned hook that still runs, with what it waits on, and core and hook gone; record left behind names a record nothing can still be waiting on. Each core removes the second kind as it starts serving. It never signals an orphaned hook's process group, because a hook process id a dead core recorded may already belong to another program; that record stays until the hook ends. The real test is tests/hooks-running/left_behind.rs (cargo test -p tama-cli --test hooks_running_left_behind).

Exit status

A verb other than the ten above prints unknown hooks command <name> and the usage, exit two; tama hooks alone, help, -h or --help print the usage and exit zero. Each verb's own refusals are listed on the page that documents it.
