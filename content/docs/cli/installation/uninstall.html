tama uninstall

The reverse of tama install: removes the Tama-managed pre-commit and pre-push dispatchers and puts back the hook each one displaced, kept beside it as .before-tama. A hook Tama did not write is left alone, by name.

Invocation

tama uninstall [--git-hooks-path <path>] [--home <path>] [--unset-git-config] [--json]

--git-hooks-path names the dispatcher directory; otherwise Tama uses global core.hooksPath, falling back to ~/.config/git/hooks, exactly as install chose it. --home controls home expansion and the Git configuration environment. --unset-git-config clears global core.hooksPath, and only when it still points at the directory being emptied: a person's own hooks path is never taken away. --json selects structured output.

Output and state

Each hook ends as one of removed (the managed dispatcher is gone and nothing was displaced), restored (the dispatcher is gone and the .before-tama hook is back under its own name), absent (there was nothing at that path) or kept (the file there is not a Tama dispatcher). Output names the resolved hooks path, both outcomes and whether Git global configuration was unset; a second run reports absent twice and changes nothing.

{"hooksPath":String,"preCommit":{"target":String,"outcome":String},"prePush":{"target":String,"outcome":String},"unsetGlobalConfig":Boolean}

Refusals and failures

Filesystem and process errors are written to stderr and exit 1. Both hooks are handled before the configuration is touched, so a refused --unset-git-config — core.hooksPath is not <path>, so it is not Tama's to unset; the dispatchers were handled first — leaves the dispatchers removed and the configuration as it was. When Git's unset returns nonzero, Tama reports Git's stderr, or exactly git config --unset failed when Git produced no message.
