tama uninstall

The reverse of tama install: removes the Tama-managed pre-commit, commit-msg and pre-push dispatchers and restores the hook each displaced from .before-tama. A hook Tama did not write is left alone.

Invocation

tama uninstall [--git-hooks-path <path>] [--home <path>] [--unset-git-config] [--json]

--git-hooks-path names the dispatcher directory; otherwise Tama uses global core.hooksPath, falling back to ~/.config/git/hooks, exactly as install chose it. --home controls home expansion and the Git configuration environment. --unset-git-config clears global core.hooksPath, and only when it still points at the directory being emptied: a person's own hooks path is never taken away. --json selects structured output.

Output and state

Each hook ends as removed, restored, absent or kept. Output names every target and outcome, the resolved hooks path and whether Git global configuration was unset. A restored foreign hook is kept on subsequent runs.

{"hooksPath":String,"preCommit":{"target":String,"outcome":String},"commitMsg":{"target":String,"outcome":String},"prePush":{"target":String,"outcome":String},"unsetGlobalConfig":Boolean}

Refusals and failures

Filesystem and process errors reach stderr with a nonzero exit. Every hook is handled before configuration is touched. If core.hooksPath names another directory, unsetting it is refused with that cause; completed hook removals are not silently reversed. A failed Git configuration operation retains its actual stderr.
