tama hook commit-lock

Git keeps one message file per repository (COMMIT_EDITMSG), whichever index a commit is made from, a private GIT_INDEX_FILE included. It writes the message after the pre-commit hook and reads it back after commit-msg. Two commits running at once in one checkout therefore each record whichever message was written last: one commit can land with the other's message over its own staged files, after each review passed the pair it was shown. The managed Git dispatchers allow one commit at a time per checkout.

Invocation

tama hook commit-lock take <git pid>
tama hook commit-lock release <git pid>

The managed pre-commit dispatcher runs take "$PPID" before Git writes the message, for the git commit process that runs the hook. It creates tama-commit.lock in the repository's common Git directory (git rev-parse --git-common-dir), holding that process id. The managed reference-transaction dispatcher of the same process runs release "$PPID" at committed or aborted. Release removes only a lock that names that process.

Refusals

  • commit-lock: another git commit (process <pid>) is running in this checkout and holds <lock>; …; commit again when it ends, followed by tama: another commit is running in <checkout>; no commit created. Another running process holds the lock. Nothing was written and no message file was touched; commit again once that commit ends.
  • commit-lock: the commit lock <lock> holds "<text>", not a process id. The lock was written by something other than this program. Remove it once no commit runs in the checkout.
  • commit-lock: cannot create|read|remove|release the commit lock <lock>: <cause>. The Git directory cannot be written or read; the cause is the filesystem's.

A commit that ended early

A commit that ends before any ref transaction, for example one refused by a hook or one with nothing to commit, leaves a lock naming a process that no longer runs. The next commit takes it over and prints commit-lock: process <pid>, which held <lock>, no longer runs; this commit takes the lock. git commit --no-verify runs no hook and takes no lock.
