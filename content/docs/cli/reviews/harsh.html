tama reviews harsh

A commit is made only on rounds of harsh review by a reviewer that is not its author. The author's own attack lines in the commit attestation are one pass he writes himself; they can say an attack failed while he knows the defect, and nothing repeats them. So tama hook review-commit, which Git's commit-msg hook runs for every commit of every session, reads the rounds recorded for the commit being made and refuses it until a round by someone other than the author, over the exact staged tree and message, found nothing and names nothing the change suggests. Every round states the two parts of the operator's standard for finished work: what it finds to improve in the change, and what new the change suggests would further improve the codebase (the same shape elsewhere, the root cause, its visibility, the real case left untested).

Before a round is recorded on a staged candidate (record --message), and before review-commit reads any round, the staged tree is written out beside the checkout's .build/tama-quality and every gate its .wisent-release.json declares except those of kind test runs on it: the format gates first, which compile nothing, then the lint gates, where a product declares its compile check (cargo check, cargo clippy, a compile script). Each is told what the tree changes against the published main in WISENT_CHANGED_PATHS as stado quality check tells it, and Cargo builds into .build/tama-quality/target (CARGO_TARGET_DIR), kept between trees, so a compile gate starts from the last tree's build. A written-out tree a run ended before removing (named <tree>-<pid> after the process that wrote it) is removed by the next run in the checkout once that process no longer runs: quality: removed <path>, the written-out tree of process <pid>, which ended before it removed it. stderr names each gate as it starts: quality: running the declared gate <name> on the staged tree <tree>. A tree a gate refuses gets no round and no commit: the staged tree <tree> does not pass the declared gate <name> (<exit>); its output is above; no round is recorded on, and no commit admits, a tree the product's own gates refuse: repair what it reports in the staged change and stage it again, with the gate's own output above it. Test gates run with the build. A product with no manifest, or no gate but test gates, is judged by the rounds alone. In a checkout .build/tama-quality must be ignored by Git, and a round is refused with the quality scratch directory <path> must be ignored by Git when it is not; in a bare repository, such as the candidate repository stado change run reviews before landing, nothing written there can enter a commit and the check is not asked.

A round over a queued entry (record --queue) whose parent is no longer HEAD is kept only when the tree carries every commit that landed since that parent: Git merges those commits onto the tree with the parent as the merge base (git merge-tree --write-tree --merge-base), and a tree that already holds them merges to itself. Any other tree is refused before the round is kept, naming each path and each commit since the parent it would take back: tree <tree> was staged on <parent> and HEAD has moved to <head> since; the tree does not carry what these commits since its parent changed, so committing it would take them back: <path>: <subjects> … stage the change again on HEAD (or say Revert "<subject>" for each in its message when it reverts them) and queue it again. Commits that do not merge onto the tree at all are refused with tree <tree> was staged on <parent>, HEAD has moved to <head> since, and the commits in between do not merge onto it; stage the change again on HEAD and queue it again. Either refusal is the same for every reviewer, so the entry is ended in Oko with it (oko review harsh end <id> --by <reviewer> --reason <refusal>) and the refusal ends no round was kept; Oko ended entry <id>, so no reviewer is handed it and its author is told; Oko hands it to no reviewer after and answers its author's next ask with it, and the same change staged again on HEAD and queued again reopens it. When Oko cannot end it, the refusal ends no round was kept, and Oko did not end entry <id> (<Oko's cause>); running this record again ends it. A merge Git cannot run at all is refused with Git's own cause and ends nothing. A HEAD the parent descends from has not moved past it: a reviewer's checkout whose main lags behind the commit the author staged on holds no commit since the parent, so the round is kept without a merge (git merge-base --is-ancestor HEAD <parent>).

A model that does not answer stops no commit

On a machine that declared a model, each commit attempt asks it for a round. When it does not answer (Brama down, the route refusing, any failure), the commit is not held for it: the hook keeps the round as owed in the register ({"entry": "owed", "tree", "parent", "message", "text", "cause", "atMs"}), says on stderr review-commit: the round by the declared judge is owed: <cause>; this commit stands on its other rounds, and the owed round runs by itself on the next commit attempt that reaches the model, and decides the commit on the rounds it has, a reviewer session's included. A commit admitted that way carries the owed round in its Harsh-Review-Rounds: line (…; the round by the declared judge is owed, the model did not answer). The next commit attempt in the repository whose model round is answered also runs every round the repository's registers still owe, over each owed candidate's patch read from objects against its parent, and keeps it beside the owed entry; its findings are printed with their tree, to be repaired in a later commit or recorded with dispose. A round the model still does not answer stays owed. show lists each owed round as model round owed over tree <tree>: <cause>; …, and show --json as owed: [{"tree", "cause", "atMs"}], every register of the repository read. The journey tests/harsh-review/owed.rs (target harsh_review_owed) commits through the built hook with a model declared at an address nobody answers on and a reviewer session's round recorded: the commit is made, the hook says the round is owed, the message names it, and show lists it.

The queue: a reviewer for every executor's commit

An executor cannot start a reviewer of its own, and on a machine where no model answers (no model declared, or Brama answering nothing) no model round runs. So a candidate no reviewer other than its author has read is not left to its author: the hook puts it in Oko's harsh-review queue (oko review harsh enqueue) with the repository, the parent it follows, the staged tree and the message, and its refusal names the entry: it waits in Oko's harsh-review queue as entry <id>, which Oko's supervision pass hands to a reviewer session of its own; commit again once `tama reviews harsh show` lists it reviewed. When Oko cannot take it, the refusal says so and why: it could not be put in Oko's harsh-review queue, so no reviewer session is handed it: <cause>. The same candidate refused again finds its own entry; a changed tree or message is a new entry, since a round covers one candidate only. An author queues its own candidate without a refused commit with tama reviews harsh request --message <file> [--item <id>] [--within-minutes <n>]: oko work next hands the entry to a free session by the rank of the item the commit repairs, then the oldest, and an entry held past the minutes declared goes to the next session that asks; it answers queued harsh-review entry <id> for tree <tree> on <parent> in <repository>: <state>; `oko work next` hands it to a free session that did not stage it, and refuses a missing --message, a message file that holds no text (<file> holds no message; a round covers the message too), a repository that cannot be resolved, and an entry Oko refuses, a --within-minutes that is no positive number among them, with <oko> review harsh enqueue … failed: <what Oko said>.

Every supervision pass (oko sessions supervision run, or oko review harsh assign for this step alone) starts, for each entry with no running reviewer, a session of its own in the candidate's checkout, recorded as an executor under the author's supervisor, with a brief to review that entry and nothing else. The reviewer reads the candidate with show --queue <id>: the entry's message and the patch its tree makes over its parent, read from the repository's objects, so a candidate staged in an index of its own is read as it was staged. It records its round with record --queue <id> --findings <file> --improvements <file>, which keeps the round in the parent's register and marks the entry reviewed in Oko. The author is refused as the reviewer of its own entry (entry <id> was staged by session <id>, who cannot review it), and an entry another reviewer's round already answered is refused before any round is kept (entry <id> was already reviewed by <session>, whose round Oko keeps, so no round of <session> was kept). When Oko does not mark the entry, the command fails with the round kept and says that the same record run again marks it and keeps no second round. The author's next commit attempt then finds the round.

A reviewer that reads the candidate where it is staged instead, with record --message <file>, records the very round an entry waits for. The round is kept first. Then every entry of another author that no round has reviewed yet (waiting, or assigned to a reviewer by the supervision pass: Oko keeps the first round whoever records it), queued from a checkout whose rounds go to the same register, and naming the same staged tree, parent and message (the message as the Rounds section below defines the one a round covers) is marked reviewed with it, and the answer ends with ; Oko marks queue entry <id>[ (assigned to <session>)][, …] reviewed, naming the session an assigned entry was handed to. An open entry of the same tree and parent whose message differs is not covered and is named: ; queue entry <id>[, <id>…] names this tree over this parent with another message, so this round does not cover it and it stays open. When Oko refuses to mark an entry, the entry is read again: one another round marked since it was listed is named, ; queue entry <id> (reviewed by <session>) was marked by another round meanwhile, which Oko keeps, and one this round's own mark reached is counted as marked. When no open entry matches, the answer is the round's line alone.

A staged round names the tree its reviewer read with --tree <tree> (git write-tree when the reading began). An index restaged after that writes another tree, which nobody read, so the round is refused before anything is kept: the round names tree <read>, but the index of <repository> now writes tree <now>: it was restaged after the review read it, so no round was kept; review the tree it holds now. A --queue round is always kept over the tree its queue entry names.

Recording a round is safe to repeat: when the newest round over the same candidate in the register is this very round (the same reviewer, findings and improvements), no second copy is kept and the line begins found this very round already kept. So every failure after the round is kept fails the command with the round standing, and the same record run again finishes the job. When the queue cannot be listed (Oko cannot be run, exits nonzero or answers no JSON) nothing is marked: <the round's line>; no harsh-review queue entry was marked, since Oko's queue could not be listed: <cause>; the round stands, and only once <oko> lists its harsh-review queue (an Oko without that queue never does) does running this record again mark an entry, keeping no second round, naming the Oko program Tama runs; a listing with no entries list, or an entry lacking a field, says since Oko's listing is not its queue instead. Otherwise every covered entry is tried, and the answer fails after saying everything else when Oko refused an entry no round has marked, or one cannot be read again (; Oko did not mark harsh-review queue entry <id>: <refusal>[, and it cannot be read again to tell whether a round marked it: <cause>][; entry …]; running this record again marks it and keeps no second round), or when an entry queuing this very candidate comes from a checkout that cannot be read to tell which register its author's commit reads (; queue entry <id> (queued from <path>, which cannot be read: <cause>; `tama reviews harsh record --queue <id>` records a round where it was queued) queues this very candidate, but whether its author's commit reads this round's register cannot be told). The author's own round over its staged tree marks nothing.

Who reviews

  • A reviewer session. A session that is not the author reads git diff --cached and the message the commit will carry, attacks every changed line, and runs record with two JSON lists, each item {"quote", "problem", "require"} quoting the patch or the message: --findings, what it found in the change, and --improvements, what the change suggests further, each [] when there is none; both are required, so no round leaves the second part unsaid. The reviewer is the session whose recorded agent process runs the command, found the way owner consent finds it; a command no recorded session runs is the operator's own.
  • A model. On a machine that declared a model (tama model set), every commit attempt first runs one round by the declared judge over the staged patch and message, and keeps it. The judge is asked both parts and names each improvement the change suggests as a finding, so its round states both in its findings.

A literal, call or construct spelled another way so that a repository gate does not see it is a finding of the gate it dodges, and an attack line saying an attack failed where the patch shows the defect is a finding; the model reviewer is told so, and a reviewer session reviews the same way.

Rounds and the verdict

Every round is kept, in order, in <git common dir>/tama-harsh-review/<parent>.jsonl, where the parent is the commit the new one will follow, and records that parent beside the tree it read. A round covers one candidate: the staged tree and the message as Git records it, without comment lines and without the rounds line. A round over the same change on an earlier parent covers it too: when the candidate was rebased onto a new parent and its diff against that parent equals the reviewed tree's diff against its own (the index lines naming blobs aside) under the same message, the round carries, and the commit says the round over tree <tree> on parent <parent> reviewed this same change and carries to tree <tree> on parent <parent>. A differing diff still needs a round of its own; a round whose old patch can no longer be read says so and does not carry; a round recorded before parents were kept never carries. Rounds recorded by the commit's author count for nothing. The commit is refused

  • with no round of harsh review by a reviewer other than the author (…) covers staged tree <tree> and this message while there is none;
  • with the newest harsh review round, by …, found: and each finding while the newest such round found anything. Each finding is repaired in the staged change, or recorded as an Oko defect with dispose, which refuses a quote no round found and a defect oko defects show does not hold; then a new round runs on the result, until a round finds nothing;
  • with the newest harsh review round, by …, states only what it found in the change, not what the change suggests while the newest such round was recorded without its improvements (a round kept before the second part was asked);
  • with the newest harsh review round, by …, names what this change suggests would further improve the codebase: and each item while its improvements are not empty: each is done in the staged change or recorded as an Oko defect with dispose, then a new round runs, until one finds nothing and suggests nothing;
  • with earlier harsh review findings still stand: their quoted text is still staged and none was recorded as a defect or settled as repaired while any earlier finding's or improvement's quoted text is still staged and it was neither disposed nor settled: a later round that passes it does not settle it, and neither does an attack line saying the attack failed. A finding repaired on other lines while the line it quoted stays staged (a declaration whose wrong case is refused a few lines later) is settled with settle --quote <quote> --reason <where it was repaired> by a reviewer other than the author; settle refuses a quote no round found and an empty reason, and a settlement by the commit's author settles nothing.

A commit let through has one line added to its message before Git records it, naming its rounds by kind (no session id is written into a message): Harsh-Review-Rounds: <n> rounds by a reviewer session; findings per round 2, 1, 0; 1 recorded as defects; 1 settled as repaired. record refuses an item whose quote is found neither in the staged patch nor in the message, so no round names a defect it did not read. show prints the register and, given the message, the verdict the rounds give the staged candidate now, exiting one while it would be refused; without a message it lists the rounds and gives no verdict. Under them it lists Oko's harsh-review queue, one line per entry: queue <id> <waiting|assigned|reviewed>: tree <tree> in <checkout> by <author>; reviewer <session>. --json prints {register, tree, entries, admitted, verdict, queue} (the verdict fields null without a message; queue as oko review harsh list prints it). An unreadable register, a line in it that is no round, disposal or settlement, a Git step that fails, or an Oko that cannot list the queue refuses naming its cause.

A reviewer session the author starts

tama reviews harsh run --message <file> (--defect <id> | --task <id>) starts a reviewer session of its own over the candidate staged in --repository (the index GIT_INDEX_FILE names, else the checkout's own) and follows it to its end, so an author's commit does not wait for another session to be free. The run gets a directory of its own, <git common dir>/tama-harsh-review/runs/<tree>/<start in ms>, holding brief.md, the reviewer's events.jsonl and stderr.log, the findings.json and improvements.json it writes, and outcome.txt; a copy of this Tama is put there for the record command and removed when the session ends. The brief names the index, the tree, the message, the item the author's work is for (which the reviewer scopes its session to with tama task scope set), a build hold when one stands on the checkout, and the quotes earlier rounds found that the author recorded as Oko defects; it tells the reviewer to repair what it finds in the staged files, stage the repairs in the same index, and record one round with record. The reviewer is one session of the OMP program TAMA_OMP names, else omp on PATH or in ~/.local/bin, in print mode, in the candidate's checkout. The run ends when the session does; it answers reviewer session over tree <tree> ended; it repaired nothing | it repaired what it found, so read its repairs with `git diff <tree> <tree now>` before committing; its brief, events and errors are in <directory>; it answered: <last answer> and, on the next line, the verdict the rounds now give the staged tree, exiting nonzero when they do not admit it. A session that makes the same call again and is refused the same way, or answers again with no call between, records nothing from then on and is stopped: the reviewer session made the call <call> again and was refused the same way, so it was stopped; the refusal: <refusal>; one that ends without a round over the tree staged now is refused with the reviewer session ended without recording a round over the staged tree <tree> in <register>. Before any run directory exists it refuses a missing --message, an empty message (the message <file> is empty), an item named by neither or both of --defect and --task (name the item the reviewed work is for with exactly one of --defect <id> or --task <id>), a TAMA_OMP set to nothing, and a machine without OMP (no OMP program to run the reviewer in: name it in TAMA_OMP, or put omp on PATH or in ~/.local/bin). run --attestation (session|build):<session id> runs the same reviewer over a session's recorded task or build attestation instead of a staged commit (see Recorded attestations).

One change across two repositories

A product's code and its documentation live in two checkouts, so a change that alters a command and the page that describes it is two commits. Reviewed apart, the code's reviewer finds the page missing and the page's reviewer finds the code missing, and neither half is ever admitted. run and record take the other half with --with <repository>:<index> (its checkout and the index it is staged in) and --with-message <file> (the message it will carry). run briefs the reviewer with both patches as one change, to repair either half and record one round; record accepts a finding quoting either half's patch or message. The round is kept in both repositories' registers over each half's own tree, each naming the other half (paired: {repository, index, tree, message, commitsFirst}, message being the digest of that half's message as the round read it).

The --repository half (the code) commits first: review-commit admits it only while the other half is still staged as the round read it, so the documentation that lands is the one reviewed; a half restaged since is refused with this half was reviewed with its paired half in <name> as tree <tree>, but <index> now stages tree <tree>: the round read another half than the one that would land beside this change; review both halves again with `tama reviews harsh run --with <repository>:<index> --with-message <its message file> --message <file> (--defect <id> | --task <id>)`, and an index Git cannot read a tree from any more with this half was reviewed with its paired half in <name>, staged in <index>, which cannot be read now (<cause>); restage the other half as the round read it (tree <tree>) or review this half again. The other half commits after it: it is admitted once a commit in that repository's HEAD history holds its pair's reviewed tree, so a later commit there does not hold it back, and refused before with … which commits first: no commit in <repository>'s HEAD history holds its reviewed tree <tree>, so commit and push that half first, then commit this one; a history Git cannot list is refused with … which commits first, and <repository>'s HEAD history cannot be read (<status>: <stderr>); commit and push that half first, then commit this one. Git is asked about the other checkout without the repository a commit hook names to it, so it reads that checkout and not the one being committed. Each admitted half's Harsh-Review-Rounds: line ends with read with its paired half in <name> tree <tree>, <name> being the other checkout's directory name, as in the refusals above.

Refusals before any reviewer starts or any round is kept, in record and run alike: --with names the other half of the change as <repository>:<index> for a value with no separator, --with names both the repository and the index of the other half when either part is empty, --with names the index <path>, which is no file, `git -C <repository> write-tree` with the index <index> wrote no tree (<status>: <stderr>) for a file that is no index of that checkout, --with-message is required, --with pairs a candidate staged in --repository with its other half, and --queue reviews one without it; name one of them (--attestation the same), since a queued candidate or an attestation is reviewed alone, and --with-message names the message of the other half --with <repository>:<index> names, and no --with is given; name both or neither for a message with no half. run alone refuses the other half's message <file> is empty, as it refuses an empty --message; record reads the message as it is. A round is kept in the other register only after that half's staged tree passes its product's declared gates, as this half's does, and record marks the Oko harsh-review queue entries that queue either half; a register of the other half that cannot be read is refused as the other half's register in <repository> cannot be read: <cause>.

Recorded attestations

A session's recorded task attestation (tama attestation record --session, read by the stop gates on a machine that declares no model) and its build attestation (spent by the build gate) are certifications in the session's own words. Their form is read without a model, so a session can fill it while the work is not what it says; each therefore has the same rounds before it stands. Until a reviewer other than the session that recorded it has recorded a round that found nothing on the document as it is kept, every gate that reads it refuses with session <id>'s recorded <kind> attestation does not stand: no reviewer other than its author (session <id>) has attacked this certification against the work it certifies, naming the record's file and the command: record --findings <file> --improvements <file> --attestation <kind>:<session id>, kind session or build. A round whose findings or improvements are not empty refuses it with its harsh review refuses it: and each finding, and an earlier finding whose quoted text the document still holds keeps refusing it; the repair is the work and a corrected document recorded again, which is a new candidate needing its own round. record refuses a finding quoting text the attestation does not hold, a round by the session that wrote it (session <id> wrote this attestation, so its own round is no review), an --attestation that is not session:<id> or build:<id>, and an attestation that is not recorded. The rounds are kept in <Tama state>/attestations/reviews/<kind>/<session id>.jsonl, outside the record directories; dispose and settle with --attestation <kind>:<session id> keep their entry in that register instead of the commit's. run --attestation <kind>:<session id> starts the reviewer session the way run does for a commit, with its run directory under review-runs/<kind>/<session id> beside the attestation records and a brief naming the record and the record command; it refuses an attestation that is not recorded with show's own words before any reviewer starts, and answers reviewer session over the attestation <kind>:<session id> ended; the attestation stands, or … does not stand: <why> exiting nonzero, as the gates read it now. tests/task-attestation/no_model.rs drives the stop gate through an unreviewed attestation, a refused unquoted finding, a passing round and a newer round with a finding; tests/build-gate/attested.rs proves a standing build attestation admits no build until a reviewer's round passes it.

Native request and Desktop

tama request reviews/harsh takes {"repository": "<checkout>", "message"?: "<text>"} and returns the same document. Desktop → Reviews → Harsh review rounds reads it for a named checkout and lists each round with its reviewer, staged tree, findings and the improvements the change suggests (or that the round states none, which lets no commit through), each finding recorded as a defect, each finding settled as repaired with who settled it and where it was repaired, and the queue's entries with their state, author, reviewer session and the reviewer's findings; an unreadable register or an entry of an unknown kind is shown as the failure it is. Oko Desktop shows the same queue beside the supervisor review, with a button that runs the supervision step handing waiting entries to reviewers.
