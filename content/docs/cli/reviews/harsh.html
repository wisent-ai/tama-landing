tama reviews harsh

A commit is made only on rounds of harsh review by a reviewer that is not its author. The author's own attack lines in the commit attestation are one pass he writes himself; they can say an attack failed while he knows the defect, and nothing repeats them. So tama hook review-commit, which Git's commit-msg hook runs for every commit of every session, reads the rounds recorded for the commit being made and refuses it until a round by someone other than the author, over the exact staged tree and message, found nothing.

Invocation

tama reviews harsh record --findings <file> --message <file> [--repository <path>]
tama reviews harsh dispose --quote <text> --defect <oko defect id> [--repository <path>]
tama reviews harsh show [--message <file>] [--repository <path>] [--json]

Who reviews

  • A reviewer session. A session that is not the author reads git diff --cached and the message the commit will carry, attacks every changed line, and runs record with a JSON list of findings, each {"quote", "problem", "require"}, or [] when it found nothing. The reviewer is the session whose recorded agent process runs the command, found the way owner consent finds it; a command no recorded session runs is the operator's own.
  • A model. On a machine that declared a model (tama model-provider set), every commit attempt first runs one round by the declared judge over the staged patch and message, and keeps it.

A literal, call or construct spelled another way so that a repository gate does not see it is a finding of the gate it dodges, and an attack line saying an attack failed where the patch shows the defect is a finding; the model reviewer is told so, and a reviewer session reviews the same way.

Rounds and the verdict

Every round is kept, in order, in <git common dir>/tama-harsh-review/<parent>.jsonl, where the parent is the commit the new one will follow. A round covers one candidate: the staged tree and the message as Git records it, without comment lines and without the rounds line. Rounds recorded by the commit's author count for nothing. The commit is refused

  • with no round of harsh review by a reviewer other than the author (…) covers staged tree <tree> and this message while there is none;
  • with the newest harsh review round, by …, found: and each finding while the newest such round found anything. Each finding is repaired in the staged change, or recorded as an Oko defect with dispose, which refuses a quote no round found and a defect oko defects show does not hold; then a new round runs on the result, until a round finds nothing;
  • with earlier harsh review findings still stand while any earlier finding's quoted text is still staged and it was not disposed: a later round that passes it does not settle it, and neither does an attack line saying the attack failed.

A commit let through has one line added to its message before Git records it, naming its rounds by kind (no session id is written into a message): Harsh-Review-Rounds: <n> rounds by a reviewer session; findings per round 2, 1, 0; 1 recorded as defects. record refuses a finding whose quote is found neither in the staged patch nor in the message, so no round names a defect it did not read. show prints the register and, given the message, the verdict the rounds give the staged candidate now, exiting one while it would be refused; without a message it lists the rounds and gives no verdict. --json prints {register, tree, entries, admitted, verdict} (the last two null without a message). An unreadable register, a line in it that is no round or disposal, or a Git step that fails refuses naming its cause.

Native request and Desktop

tama request reviews/harsh takes {"repository": "<checkout>", "message"?: "<text>"} and returns the same document. Desktop → Reviews → Harsh review rounds reads it for a named checkout and lists each round with its reviewer, staged tree and findings, and each finding recorded as a defect; an unreadable register or an entry of an unknown kind is shown as the failure it is.

Journeys

tests/harsh-review/rounds.rs (cargo test -p tama-cli --test harsh_review_rounds) commits through the built hook in a clone: a round that found something refuses, a later passing round does not settle a finding still staged, the author's own round admits nothing, and a reviewer's passing round over the repaired change admits the commit; a finding quoting text that is not there is not recorded. tests/commit-review/attested.rs proves an attested commit no other reviewer reviewed is refused and that the made commit carries its rounds line.
