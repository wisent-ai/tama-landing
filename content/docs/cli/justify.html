tama justify

Records the justification the authorization gates require before a new file or a new test is written, and reads or removes one that is already recorded.

Invocation

tama justify <record|show|remove|list> [--file <path>] [--justification <text>] [--kind file|test] [--quote <text>] [--expires-at <iso>] [--home <path>] [--json]

--kind file (the default) addresses ~/.shared-hooks/file_justifications.json, which require-new-file-justification reads; --kind test addresses ~/.shared-hooks/test_justifications.json, which the write gate reads for a new test. --home points both at another home directory, which is how a test drives this command without touching an operator's registry. Entries are keyed by absolute path, because that is the key the gates look up.

Why a command and not an edit

A justification registry is data an agent is required to write, and the directory holding it is hook configuration an agent must never write. Three gates enforce that directory: block-hook-config-edits-without-consent reads it as protected configuration, block-oversized-files reads a registry of a few thousand entries as an oversized source module, and the write gate protects the path outright. Editing the file by hand is refused by design, so the data inside it gets a product surface instead of an exemption.

The document is edited in place rather than re-serialised: one entry is spliced in, the result is parsed back, and it is compared against the registry plus exactly that entry before anything is written. An operator registry keeps its order and its other entries byte for byte, and a splice can never publish a broken registry.

Actions

  • record writes one entry and replaces an entry already stored under that path.
  • show prints the stored entry, or refuses when nothing is recorded for that path.
  • remove deletes one entry.
  • list prints every path the registry carries, one per line, or as JSON with --json.

What a recorded justification must satisfy

The command enforces exactly what the gates enforce, so a recorded entry is never one a gate then rejects:

  • fifty words or more, counted the way the gates count them;
  • for --kind test, a --quote copied verbatim from the request that asked for the test, contained verbatim inside the justification, and confirmed against the stored transcripts by the same checker the test gate runs.

Refusals

Each of these exits 1 and writes nothing:

  • the justification is <n> words and the registry requires 50
  • the registry is keyed by absolute paths, and <path> is relative
  • a test justification needs --quote, copied verbatim from the request that asked for <path>
  • the justification must contain the quote verbatim, because the gate checks that
  • the quote is not a verbatim message from any stored user turn
  • the quote verifier is missing at <path>, and the test gate refuses a quote it cannot verify
  • no justification is recorded for <path>
  • the edit would have changed entries other than the one asked for, so <registry> is unchanged, and its sibling for invalid JSON — the read-back check refusing to publish a document it did not intend

An unknown action or a missing subcommand prints the usage text and exits 2.

The same capability in Tama Desktop

The Justifications screen records an entry as well as reading one: its Record justification action opens a sheet for the target, the registry, the justification and the user quote, and runs this command from the release sealed into the application. The rules are not restated in the interface, and a refusal appears there in the command's own words.
