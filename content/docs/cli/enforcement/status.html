tama enforcement status

Reads the durable machine-wide hook selection and the emergency switch that can temporarily bypass it.

Invocation

tama enforcement status [--json]

The command takes no positional input. --json selects the structured status document.

Output and state

Text output reports mode: all or mode: only, selected hooks: <selected>/<installed> installed, either selected ids: all installed hooks or the selected id list, and emergency disabled: true or false. While the emergency switch holds, it adds emergency switch: Tama's emergency switch is set by <who> since <when> because <why>; it lifts itself at <end>: every Tama hook is off on this machine, …, naming whatever the switch's record lacks. JSON reports mode, enabled, selectedHookCount, installedHookCount, emergencyDisabled, emergencySwitch (holds, set, setBy, reason, changedAt, expiresAt, expired, gaps), emergencyNotice while the switch holds, and an optional readError. A switch past its expiresAt reads emergencyDisabled: false and expired: true: the hooks run again (emergency disable). The command is read-only.

The installed count, and every id only, add and remove accept, come from the registry the hook engine runs: the file AGENT_HOOK_REGISTRY names, else ~/.shared-hooks/registry.json, which tama hooks release installs. The checkout a release was recorded from is not read, so a selected hook the installed release carries is counted even when that checkout stands behind it. A run with TAMA_ROOT set counts that checkout's registry instead, which is how a journey names its fixture.

A new release never changes a selection in mode only: tama hooks release prints new in this release: <id>; a machine in mode `only` enforces it once its operator runs `tama enforcement add <id>` for each hook it brings, and mode all enforces them at once.

Refusals and failures

A missing hook-enforcement.json is normal all-hooks state. Malformed or unreadable state still prints the fallback-all status, writes the following exact sentence to stderr, and exits 1:

Tama could not read the machine enforcement selection: <core error>. Falling back to all hooks.

The JSON result includes the same failure in readError. The dispatcher also falls back to all, never none.
