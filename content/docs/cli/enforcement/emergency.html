tama enforcement emergency

The operator's break-glass switch: turns every Tama hook off on this machine for a stated number of minutes, records who threw it and why, shows it in every session record and hook answer, and lifts itself when the time has passed. Tama Desktop's Disable all policies and Re-enable all policies run these same commands through the bundled release's own tama.

Invocation

tama enforcement emergency status [--json] --home DIR
tama enforcement emergency on --reason TEXT --minutes N --release DIR --home DIR
tama enforcement emergency off [--release DIR] --home DIR
tama enforcement emergency expire [--release DIR] --home DIR

--home is the account home the switch lives under (~/Library/Application Support/Tama/hook-emergency-state.json below it). --release is the sealed hook release whose installer sets the hooks aside and restores them; the desktop passes its bundled hooks-release.

What each command does

  • status prints the switch as every reader judges it: Tama's emergency switch is set by <who> since <when> because <why>; it lifts itself at <end>: …, naming what a hand-written record lacks; The emergency switch expired at <end>: every Tama hook runs again. …; or The emergency switch is not set: every Tama hook runs. --json prints holds, set, setBy, reason, changedAt, expiresAt, expired and gaps.
  • on installs the session controllers from --release (so session visibility survives), empties the Claude and Codex hook maps unless every hook there is Tama's dispatcher (copies kept in emergency-backup/), moves the OMP hooks folder, every Git hook source the installed registry declares and the editor watcher's LaunchAgent aside to <name>.tama-disabled, stops the editor watcher, writes emergency-backup/manifest.json and the switch with setBy (the account running it), reason, changedAt and expiresAt, and loads a LaunchAgent (ai.wisent.tama.emergency-expiry.<home digest>) that runs expire every minute. It prints Disabled hooks for <N> minutes. Running agent sessions read the emergency state at once and keep running; the hooks run again when it expires.
  • off restores everything on set aside through the full install of --release with the manifest, loads the editor watcher again, removes the switch, the manifest and the backups, takes the expiry agent away, and prints Enabled approved hook release <first 12 of its id>. … A switch with no manifest — written by hand, so nothing was set aside — is removed alone, without --release: Lifted an emergency switch that set nothing aside (no emergency-backup/manifest.json): every hook runs again. …
  • expire is what the agent runs: nothing before expiresAt; after it, The emergency switch expired at <end>; restoring every hook. and then off. With no switch, or one that names no end, it takes the agent away. Each run's output lands in emergency-expiry.log beside the switch.

Every reader — the hook engine, session records, tama enforcement status, the OMP adapter, Tama Desktop — already treats a switch past its expiresAt as lifted, so the hooks run again at the expiry even before the agent restores the entrypoints (emergency disable).

Refusals and failures

  • on without --reason, --minutes or --release: `tama enforcement emergency on` needs <flag>: …; nothing was changed, exit 1.
  • --minutes that is not a whole number above zero: --minutes is <value>; it must be a whole number of minutes above zero, and nothing was changed; an empty --reason: --reason is empty; ….
  • on from inside an agent session: `tama enforcement emergency on` turns gates off, and it runs inside <agent> session <id>, which those gates hold: narrowing the selection is the operator's own act from his terminal, and nothing was changed. … A process tree whose session cannot be read is refused the same way. off and expire turn gates on and are open to anyone.
  • on when a manifest already exists: Tama hooks are already disabled. and the status, exit 0.
  • The session controllers cannot be installed: enforcement: the session controllers could not be installed from <release>, so nothing was set aside: <install error>.
  • An entrypoint present both active and set aside: Both active and disabled hook entrypoints exist: <path>; remove the one that is not wanted, then run this again.
  • The account has no name in the user database: enforcement: the user database has no name for this process's user, so the switch cannot record who threw it: ….
  • The expiry agent cannot be loaded: Tama could not schedule the switch's own lifting (launchctl bootstrap <plist> exited <status>: …); every reader still treats it as lifted at its expiry, and `tama enforcement emergency off` restores what it set aside. on stderr; the switch is set.
  • off with neither a switch nor a manifest: Tama has no emergency switch set and no emergency backup manifest to restore., exit 1.
  • off whose restore fails: enforcement: the hooks could not be restored from <release>; the switch and what it set aside are kept: <install error>; nothing is removed, so the next off can finish it.
  • A missing --home or an unknown command prints the usage, exit 2.

The real journey is tests/enforcement/emergency_command.rs: each refusal above, the hand-written switch, expire before and after its end, and — with TAMA_TEST_HOOK_RELEASE naming a sealed release — the full on then off in a home of its own.
