tama enforcement preflight

Asks one installed hook whether it can work on this machine, and prints the whole exchange.

Invocation

tama enforcement preflight <hook-id>

Takes exactly one hook id. The command reads the installed registry and runs that one hook; it never writes the machine selection, the adaptive state or the session state.

Output and state

Seven lines, in order: hook: the id as asked; catalogue: whether the installed registry declares it; command: the command string the catalogue records, including a literal $HOME when that is what is stored; program: the path actually executed after the home directory is expanded; exit: the hook's exit code, or spawn: and the operating system error when it could not be started at all; answer: the first line the hook printed; and verdict: one of usable, unusable: the hook cannot reach the service it needs, or not installed on this machine.

The hook is asked with the same activation payload the session path sends, so a hook that already understands the session preflight answers this command the same way.

Exit is 0 for a usable hook, and 1 when the hook answered with an infrastructure failure or the catalogue records no command for it. An absent binary exits 0: a hook that is not installed yet is not a broken hook.

Refusals and failures

There are no policy refusals: nothing is changed. A registry that cannot be read prints enforcement: <error> and exits 1. An id the installed registry does not declare is still probed if the catalogue records a command for it, and the catalogue: line says it is unknown.

This is the diagnostic behind the refusal in tama enforcement only. Read it when a hook was accepted or refused and the reason has to be visible rather than guessed.
