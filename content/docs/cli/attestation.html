tama attestation

An agent's own attestation, read without any model. A commit carries its attestation in its own message: every claim of the commit standard, word for word. review-push reads every commit a push adds and refuses the push at the first commit whose message lacks a claim, naming the commit and each missing claim. An answer that ends a turn carries the claims each turn-end stop hook declares (check-stop-asking, block-false-blockers, block-stop-on-own-work), and those hooks refuse an answer that lacks one in the same way. Nothing else is asked: no model, no key, no Brama and no other product, so a push and a turn end are judged the same on a machine with nothing but Git and Tama. A session's attestation that its task is finished is different: it is recorded, and on a machine that declared no model (tama model-provider set --none) the stop gates that would otherwise ask a model read it instead.

Invocation

tama attestation standard (--commit | --turn | --session ID) [--json]
tama attestation check (--commit REV [--repository PATH] | --turn HOOK --file PATH) [--json]
tama attestation record --file PATH --session ID [--json]
tama attestation show --session ID [--json]
tama attestation remove --session ID [--json]
tama attestation list [--json]
  • standard --commit prints the commit standard's claims, one per line and nothing else, so the output is pasted into a commit message as it is. With --json: {"kind": "commit", "claims": [...]}.
  • standard --turn prints every turn-end claim as <hook>: <claim>. With --json: {"kind": "turn", "hooks": {"<hook>": [...]}}.
  • check --commit REV reads the message of the commit REV names in --repository (the current directory when it is not given) and names every claim it lacks, the same claims review-push would name. check --turn HOOK --file PATH reads the answer in PATH against the claims HOOK declares, the same verdict the hook gives. Exit 0 when every claim stands, 1 when one is missing.
  • standard --session ID prints the task standard a session's recorded attestation confirms, each claim as attestation: claim <key>: <claim> and each list that must stay empty as attestation: empty <key>: <why>.
  • record judges the JSON document in --file against the task standard and keeps it only when it stands, under the Tama state root in attestations/session/<id>.json; recording again replaces the kept record, and a refused attestation leaves the kept one as it was. show prints the kept record and how it stands against today's standard, list every kept record, remove deletes one.

Quickstart

A commit that carries its attestation, checked before it is pushed:

$ git commit -m "Parse a balance from its text"
$ tama attestation check --commit HEAD
attestation: commit <sha> does not carry its attestation
    missing: "<claim>"
    …
$ git commit --amend -m "Parse a balance from its text

$(tama attestation standard --commit)"
$ tama attestation check --commit HEAD
attestation: commit <sha> carries every claim
$ git push            # review-push reads the same message and lets it through

An answer checked before the turn ends with it:

$ tama attestation standard --turn
$ tama attestation check --turn check-stop-asking --file answer.md

A session on a machine with no model:

$ tama model-provider set --none
$ tama attestation standard --session "$SESSION"
$ tama attestation record --file done.json --session "$SESSION"
attestation: session <session> stands
attestation: recorded at ~/Library/Application Support/Tama/attestations/session/<session>.json

How a carried attestation is read

Every claim the declaration lists must stand in the text word for word. Runs of spaces and line breaks count as one space, so a claim wrapped over lines reads as written; nothing else is forgiven: a reworded, shortened or translated claim is missing. The claims come from standards/commit.json (its required[].claim) and standards/turn.json (each hook's list) beside the attestation module, the same files the gates read. A claim is carried only when it is true; a false one is the agent's defect, on record in the commit or the transcript.

Every commit carries its own: the tip of a push speaks for no commit under it. For a ref the remote does not hold yet, the commits read are those no ref Git keeps for that remote already holds.

What a session's recorded attestation holds

{
  "attestations": {
    "<claim key>": {"confirmed": true, "how": "…"},
    "…": {"confirmed": true, "how": "…"}
  },
  "next_steps": [],
  "harsh_senior_review_findings": []
}

Every claim of standards/task.json must be present with "confirmed": true and a how that explains, in the agent's own words, how the claim holds, in at least the number of words the operator stated (attestation_min_words in the stated-numbers declaration). next_steps and harsh_senior_review_findings must be present and empty: a step that continues the task is the task's work, and every finding means the task is not finished.

Output and refusals

  • review-push: BLOCKED: <local ref> -> <remote ref>: commit <sha> carries no commit attestation in its message: followed by one missing: "<claim>" line per missing claim, then the instruction to carry the block tama attestation standard --commit prints and amend or rebase the unpublished commits; the push exits 1 and nothing reaches the remote. A pushed commit Git cannot list or read is refused with review-push: the pushed commits cannot be read: <cause>.
  • BLOCKED: <hook>: the answer this turn ends with does not carry its turn-end attestation: followed by the missing claims in the same form; a transcript that cannot be read is refused as TAMA_HOOK_INFRASTRUCTURE: <hook>: <cause>.
  • check prints attestation: <kind> <id> carries every claim or attestation: <kind> <id> does not carry its attestation and the missing claims; with --json, {"kind", "id", "stands", "missing"}. <rev> names no commit in the repository at <place>: <git's words> and standards/turn.json declares no turn-end attestation for the hook <hook> exit 1.
  • record prints attestation: session <id> stands and attestation: recorded at <path>, or does not stand with every reason, exit 1, nothing kept: attestations.<key> is missing, .confirmed is not true, .how is missing, .how explains in N words …; the operator asks for at least M, <list> names N item(s). show or remove with nothing kept: no attestation is recorded for session <id>, exit 1.
  • Flags that do not fit the verb are refused with the usage text before anything is read, exit 2: standard prints one standard: --commit, --turn or --session ID, check reads one text: --commit REV [--repository PATH], or --turn HOOK --file PATH, <verb> needs --session ID, record needs --file PATH, <verb> takes no --file, <verb> takes no --commit, --repository or --turn, list prints every kept record, so it takes only --json, <verb> is not a verb of tama attestation, <flag> is not an option of this command, <flag> needs a value, <flag> is given twice.

Tama Desktop

The Install screen's Carried attestations section shows every claim a commit message carries, with a Copy block button that puts them on the clipboard one per line, and each stop hook's turn-end claims. Its form checks a commit in a chosen repository, or an answer typed for a chosen hook, and shows the verdict with each missing claim as the gate would name it. It sends tama request attestation/required and attestation/check with {"commit": "<rev>", "repository": "<path>"} or {"turn": "<hook>", "answer": "<text>"}; a commit without its repository, or a body naming neither, is refused with attestation/check needs "commit" with "repository", or "turn" with "answer". The Recorded attestations section records a chosen file for a session, shows, removes and lists records, and shows the task standard, through attestation/record, show, remove, standard and list with {"session": "<id>"}.

Tests

tests/review/attested.rs pushes a real commit through Git to a bare remote with Brama's address removed and no resolver state: the push without the attestation is refused naming the commit and its missing claims, tama attestation check --commit and the Desktop's attestation/check say the same, and once the message carries the block standard --commit prints, both pass and the commit reaches the remote. tests/task-attestation/turn.rs runs each turn-end hook the declaration names against an answer without and with its claims, wrapped over lines, and checks standard --turn and check --turn. desktop.rs runs the Desktop's requests, record.rs the recorded session attestation and every malformed command, and no_model.rs a model-asking stop gate reading a recorded session attestation.
