tama doctor

Diagnoses access to the configured model service from this machine without changing its provider, credentials or fleet declaration.

Invocation

tama doctor [--json]

Use this when a model-dependent operation cannot discover Brama or authenticate to its catalogue. The command uses the same diagnostic as tama model-provider check, including declared alternative providers.

Output and state

The report identifies the provider, endpoint, transport policy, catalogue request, returned status, credential source and verdict. JSON output preserves the report fields. A failure before a report exists produces {"error":"<actual cause>"} and the same cause on stderr.

Success requires an allowed endpoint and catalogue acceptance. It proves neither chat inference nor a judged-hook verdict. No provider selection or fleet configuration is changed.

Refusals

An absent route, denied consumer, unreadable credential, malformed declaration, refused transport or failed catalogue request exits unsuccessfully and retains the actual cause. A declared none provider reports no model is declared on this machine, so there is no service to check.

When Stado returns a structured undeclared or invalid_declaration route refusal, Tama submits its machine, service, consumer operation, cause and state to oko reflection observe --input - --json. Oko retains the observation without calling a model; repeated identical failures keep one source. The diagnostic includes that source or the exact intake failure, never a claim that a defect was admitted. Authentication refusal and unavailable transport are not relabelled as missing declarations. No judge request is sent on a declaration refusal.

An unknown argument is refused with doctor: unexpected argument "<argument>"; use tama doctor [--json]. --help describes the diagnostic without contacting the model service.

Desktop

Install → Model service exposes the same configured provider and catalogue diagnostic. Its check.error retains failures that occur before a catalogue report exists.
