tama history rebase

Writes the unpublished commits of a checkout's branch again on the current tip of its upstream. When other people push to the same remote, the branch's unpublished commits stand on an older tip and the push is refused until they carry the new commits; this rewrites them onto the tip without touching the checkout's index or working tree, so it runs in a checkout where people are still working.

Invocation

tama history rebase [--repository <PATH>] [--prefer upstream] [--json]

Without --repository it rebases the checkout the command runs in. Fetch the upstream first (git fetch origin): the rebase writes onto the tip the upstream's remote-tracking ref names now.

What it does

It reads the branch the checkout has checked out, its head, and the commits between the branch's upstream and that head, oldest first, as tama format fold does, refusing a detached head, a branch without an upstream, and a merge that brings more than published history. When the upstream's tip is already in the branch's history nothing is written and it says so.

Each commit's own change, its tree against its first parent, is merged by Git (git merge-tree --write-tree, renames not followed) onto the commit written before it, the first onto the upstream's tip, in a private index under the repository's Git directory. The new commit keeps the old one's message, author, committer and dates; its attestation note under refs/notes/attestation is copied to it; and the rewrite record under refs/notes/rewritten on the new commit names the commit it replaced, the same record the fold writes, so a register that names the old commit follows it. A commit whose change is no longer anything over the upstream is dropped, and the record names it on the commit before it.

The branch moves from the head that was read to the new head, refused when it moved meanwhile. Every path the rebase changed that nobody changed in the index or the working tree follows the new head; a working change someone made stays as it is.

Where Git cannot merge

A commit and the upstream may change the same lines, or one may delete a file the other changes. Without --prefer the rebase is refused at the first such commit, naming the commit and the paths, and nothing is written or moved.

With --prefer upstream the upstream's side is kept at each such place: its lines where both changed the same lines (Git's ours strategy option, the upstream being the side the commit is laid on), its file where the commit deleted it, and its deletion where the commit changed a file it deleted. The commit's other changes are merged as usual, and each path where the commit's side was given up is listed beside the commit, so that change can be made again in a new commit over the upstream's work.

Output

One line per commit: <old> -> <new>, followed by ; kept the upstream's side in <paths> when there were any, or <old> dropped: nothing of its change is left over the upstream's; then <n> commit(s) rebased onto <upstream>. With --json: {"repository", "upstream", "rebased": [{"old", "new", "upstreamKept"}]}, new null for a dropped commit.

Refusals

  • commit <sha> and the upstream change <paths> in ways Git cannot merge, so nothing was rewritten; name --prefer upstream to keep the upstream's side there.
  • --prefer takes upstream, the side kept where Git cannot merge; got <word>, and --prefer needs upstream.
  • git merge-tree of <commit> onto <parent> wrote no tree (<status>): <Git's words> when Git could not run the merge at all.
  • The fold's refusals of the branch: no branch checked out, no upstream, a merge carrying a change of its own, and a branch that moved while the rebase ran.

Journey

tests/rebase/upstream.rs (cargo test --test history_rebase) runs the built tama against a real bare remote, our checkout and a second clone that pushes meanwhile: the merge onto the new tip with message, author, note and rewrite record kept and a working change left alone; a line both changed refused naming the commit and path, then kept as the upstream wrote it under --prefer upstream with the commit's other change merged; a file the upstream deleted staying deleted; and an unknown preference refused.
