tama worktrees list

Reports every linked git worktree under the roots you name, with its branch, head, dirty, locked and prunable state, and mutates nothing.

Invocation

tama worktrees list [--root <PATH>]... [--json]

Inputs and options

OptionContract
--root <PATH>Repeatable, and required at least once. Each value is a directory under which Tama looks for the repositories that own worktrees. There is deliberately no default root
--jsonPrints the exact document below instead of the text report. Both modes read the same state

No other input is accepted, and no argument selects a single worktree: the command reports every linked worktree it finds under the given roots.

Discovery

tama_violations::repo_discovery's discover_repos(root) finds the owning repositories under each root; git itself is then the authority on worktrees, through git -C <repo> worktree list --porcelain. The repository's own main worktree is never reported. A worktree is dirty when git -C <worktree> status --porcelain prints anything; locked and prunable are git's own porcelain flags.

Only linked worktrees appear — a checkout whose .git is a file holding a gitdir: pointer into <owner>/.git/worktrees/<name>. A second full clone with its own .git directory is a repository copy that no repository owns, so git never lists it and neither does this command (the worktrees group).

Output document

Under --json, exactly:

{"schemaVersion":1,"roots":[String],"repositories":[{"repository":String,"worktrees":[{"path":String,"branch":String|null,"head":String,"dirty":Boolean,"locked":Boolean,"prunable":Boolean}]}],"worktreeCount":Number}

roots echoes the roots you passed, in order. repositories carries one entry per owning repository that has at least one linked worktree, and branch is null for a detached head. worktreeCount is the total across every repository, so an empty machine answers "worktreeCount":0 with an empty repositories array. The same document is served by POST /v1/worktrees/list with body {"roots":[String]} on the loopback desktop backend (tama serve).

State effect

None. The command runs git worktree list and git status, both read-only; it never removes, prunes, locks, unlocks or checks out anything. It is the safe first command when a hook has just refused a repository copy.

Refusal boundary

Passing no --root is a usage error, exit 2:

tama worktrees needs at least one --root; a machine-wide default would walk directories Tama does not own.

A root that does not exist or cannot be read is an operational failure, exit 1. A repository whose git worktree list fails is reported as the failure it is rather than silently omitted. Otherwise the command exits 0, including when it finds nothing — an empty inventory is an answer, not an error. This leaf has no other refusal: it never asks about dirty or locked state, which is tama worktrees remove's boundary.
